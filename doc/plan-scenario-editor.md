# Phase 21C. 시나리오 에디터·지도 독립화 계획

상태: **21C-1~7 구현, 21C-8 사용성 검수 중** (2026-10-29). 상위 작업표는 [v2 로드맵](plan-v2-implementation-roadmap.md#phase-21c-시나리오-에디터지도-독립화)을 따른다. 기존 [지도 에디터 계획](plan-scenario-map-editor.md)과 [역사 시나리오 초안](plan-historical-scenarios.md)을 입력으로 사용한다.

## 1. 목표와 현행 구조

시작 화면의 순서는 **게임 시작(시나리오 선택) → 게임 불러오기 → 장수 편집 → 신규 장수 추가 → 시나리오 에디터 → 지도 에디터**다. 이 여섯 항목은 각각 독립 화면으로 진입한다. 게임 시작에서는 시나리오를 먼저 선택하고, 해당 시나리오가 참조하는 지도를 미리보기로 확인한 뒤 세력과 난이도를 고른다. 지도는 게임 시작 화면에서 임의로 바꾸지 않는다.

현재 `ScenarioStartMenu`는 기본 지도/편집 지도 중 하나만 선택한다. `ScenarioLoader`는 공통 `data/*.json`을 읽고, `ScenarioMapPresetApplier`는 편집 지도에 기존 도시의 이름·ID를 맞추거나 첫 도시를 대체 자료로 쓰며 장수 주둔지를 다른 성으로 옮긴다. `run-newmap.bat`은 테스트용 세력을 무작위 배치하고 일부 성 이름에 의존한다. 이는 역사 시나리오의 초기 상태나 사용자 편집 시나리오를 나타내지 않는다. **지도에 성이 없어졌는데 주둔·병력·소유권을 다른 성에 조용히 옮기는 동작은 시나리오 에디터에서 허용하지 않는다.** `run-newmap.bat`은 독립 검수 도구로 남기고 정식 게임 시작 경로에서 사용하지 않는다.

## 2. 데이터 소유권과 파일

### 21C-1 현행 자료 감사 (2026-10-29)

| 자료 | 현재 위치·동작 | 21C 이행 기준 |
| --- | --- | --- |
| 기본 지도 | `res://assets/maps/east-asia-user-preset.json`과 `east-asia-map.json` | 배포 자료는 읽기 전용으로 두고 고정 지도 ID를 부여한다. |
| 사용자 편집 지도 | `user://map-presets/east-asia.json` 단일 파일, `run-editmap.bat`이 직접 저장 | 원본을 보존하고 사용자 지도 ID/불변 버전 파일로 가져온다. |
| 게임 시작 | `ScenarioStartMenu`가 기본/편집 지도 경로를 선택하고 `ScenarioMapPresetApplier`가 기존 성·장수 위치를 추측해 옮긴다 | 시나리오 ID와 정확한 지도 버전을 먼저 선택하고 유효성 검사 후 시작한다. |
| 기본 시나리오 | `res://data/*.json`에서 `ScenarioLoader`가 세력·성·장수 등을 읽는다 | 기본 시나리오 자료를 별도 읽기 전용 목록으로 제공한다. |
| 저장 게임 | `user://saves/sanguo-save-01..20.json`, `SaveSlotStore`/`SaveService`가 `GameState.MapPresetSnapshot`을 포함해 저장 | 기존 슬롯의 스냅샷을 유지하고 외부 지도 변경을 재적용하지 않는다. |

지도 파일은 `user://maps/<map-id>/<revision>.json`, 시나리오 파일은 `user://scenarios/<scenario-id>.json`으로 확정한다. `map-id`와 `scenario-id`는 파일 이름으로 안전한 고유 식별자이며, `revision`은 정규화한 지도 내용의 SHA-256이다. 같은 버전 파일은 덮어쓰지 않는다. 기본 지도 ID는 `default-east-asia`, 기존 편집 지도 가져오기 ID는 `legacy-east-asia`다. 기존 `user://map-presets/east-asia.json`과 세이브는 이행 과정에서도 삭제·변경하지 않는다.

| 자료 | 저장 단위 | 편집/시작 계약 |
| --- | --- | --- |
| 기본 지도 | 배포 파일, 읽기 전용 | 모든 기본 시나리오가 최초에 참조하는 지도. 사용자 편집으로 덮어쓰지 않는다. |
| 사용자 지도 | 지도별 고유 ID와 개별 파일 | 지도 에디터에서 **새 지도 저장/복제**한다. 이름 변경은 ID를 유지하고, 배포 지도 변경은 새 ID로 복제한다. |
| 시나리오 | 시나리오별 고유 ID와 개별 파일 | 제목·시작 날짜·지도 ID/지도 버전·초기 세력/거점/장수/자원/병력/선박/유적 상태를 보유한다. |
| 새 게임 | 선택 시나리오 + 지도 불변 스냅샷 | 시작 시 시나리오와 지도 유효성을 검사하고 상태를 만든다. 이후 원본 편집은 진행 중 게임에 영향이 없다. |
| 저장 슬롯 | 현재 게임 상태와 사용된 시나리오·지도 스냅샷/식별자 | 불러올 때 최신 지도/시나리오 파일을 재적용하지 않는다. 식별자는 표시·진단용이다. |

파일 후보: `res://assets/maps/default-east-asia.json`과 `res://assets/scenarios/*.json`은 배포 기본 자료, `user://maps/<map-id>.json`과 `user://scenarios/<scenario-id>.json`은 사용자 자료다. 실제 이름과 마이그레이션은 21C-1에서 확정한다. 현행 `user://map-presets/east-asia.json`은 기존 편집 지도로 **가져오기/복제**하고 삭제하지 않는다. 저장은 임시 파일에 쓴 뒤 원자적으로 교체하고, 다시 읽어 내용과 버전을 검증한다.

지도 참조는 표시 이름이나 파일 경로만으로 묶지 않는다. 시나리오에 `mapId`, `mapRevision` 또는 콘텐츠 해시를 저장한다. 사용자 지도가 수정되면 기존 시나리오는 마지막으로 검증된 지도 버전을 계속 사용한다. 새 버전으로 바꾸려면 시나리오 에디터에서 **지도 교체/최신 버전 적용**을 선택하고 재검증한다. 이전 버전을 보존하거나 시나리오에 지도 스냅샷을 포함해 참조가 끊어지지 않도록 한다. 삭제는 참조 중인 시나리오를 표시하고 거부하거나 복제본으로 이관한 뒤 수행한다.

지도 에디터에서 **시나리오가 참조하는 지도 버전의 성은 삭제할 수 없다.** 성 제거를 누르는 즉시 해당 지도 ID·버전을 참조하는 기본/사용자 시나리오를 확인하고, 참조가 있으면 경고창에 성 이름과 시나리오 이름을 보여준 뒤 삭제를 취소한다. 주둔 병력·장수의 유무와 관계없이 적용하며 지도 메모리·파일·실행 취소 기록을 변경하지 않는다. 편집하려면 먼저 지도를 복제하고 새 지도에서 성을 제거한 다음, 시나리오 에디터에서 새 지도를 선택해 누락 거점 검증을 완료해야 한다. 저장 시에도 참조 중인 지도 버전에서 성 ID가 빠졌는지 다시 검사하여 우회 저장을 차단한다.

## 3. 시나리오 편집 화면

왼쪽에는 기본/사용자 시나리오 목록과 검색·복제·신규 작성, 오른쪽에는 탭을 둔다. 기본 시나리오는 직접 덮어쓰지 않고 **복제하여 편집**한다.

| 탭 | 편집 내용 | 지도와의 관계 |
| --- | --- | --- |
| 기본 정보 | 제목, 설명, 시작 연·월·일, 시작 가능 세력, 표시 순서 | 지도 ID·버전과 미리보기를 항상 표시 |
| 지도 | 기본/사용자 지도 목록, 지역·성/항구 수, 지도 미리보기, 교체 | 교체 전후 영향을 받는 거점과 배치 오류를 비교 |
| 세력·거점 | 군주, 세력색, 외교, 거점 소유, 성벽·치안·금·군량 | 현재 지도에 존재하는 성/항구만 선택 가능 |
| 장수 | 출현·재야·소속·주둔·군주/태수/군사 | 삭제된 거점에 장수가 남지 않도록 검증 |
| 병력·함선 | 거점별 병종·병력·부상병·선박 | 항구에만 선박을 배치, 병종 해금과 자원 검증. 후속 [관문](plan-gate.md)에는 별도 주둔 상한과 관문장을 적용 |
| 검증·저장 | 오류·경고 목록, 대상 선택 시 해당 탭/거점으로 이동 | 오류가 있으면 저장 및 시작 불가 |

지도 교체 시 자동 재배치는 하지 않는다. **같은 지도 계보의 새 버전에서 같은 거점 ID가 남아 있을 때만 유지**하고, 없는 거점의 소유·장수·명령·병력·선박은 `미배치` 목록으로 옮겨 사용자가 새 거점을 지정하거나 명시적으로 제거한다. 관계없는 지도의 동일 숫자 ID는 같은 거점으로 취급하지 않는다. 이름이 같아도 ID가 다르면 임의 병합하지 않는다. 위치·크기·종류가 바뀐 같은 계보의 거점은 영향을 목록으로 보여주고 해당 규칙을 다시 검사한다. 미배치 자료가 있으면 시작을 막는다. 거점이 없는 지역은 중립 지형으로 남을 수 있지만, 시작 가능 세력은 군주와 최소 한 거점을 가져야 한다.

장수 에디터/신규 장수 생성 결과는 시나리오 편집 화면에서 **새 게임용 장수 후보**로 읽는다. 시나리오별 출현 여부·소속·주둔은 시나리오가 결정한다. 장수 정의의 변경도 기존 저장 게임에 소급하지 않는다. 184·190·194·208·211·가상 시나리오는 [역사 시나리오 초안](plan-historical-scenarios.md)의 세력/시점 검토 후 기본 시나리오 자료로 구축한다. 아직 배치가 확정되지 않은 연도의 거점 소유를 임의로 완료로 표시하지 않는다.

## 4. 검증 규칙과 실패 처리

1. 지도 파일의 크기·타일 코드·배치물 ID·발자국·해안 방향·생산시설 부모·유적 육해상 조건을 검사한다. 지도 ID와 버전/해시가 실제 참조 대상과 일치해야 한다.
2. 시나리오의 세력 ID와 군주, 도시 ID, 장수 ID는 유일하고 실제 자료를 가리켜야 한다. 각 장수의 초기 위치와 소속은 정확히 하나이며, 군주/태수/군사·병력·선박 배치도 존재하는 거점에 연결되어야 한다.
3. 시작 가능 세력마다 시작 거점·군주·적어도 하나의 유효한 장수 주둔이 있어야 한다. 중립 거점은 허용하되 해당 거점에 특정 세력의 병력/담당자가 남아서는 안 된다.
4. 지도 교체나 거점 삭제 후 끊어진 참조를 **오류 목록으로 보여주고 저장/새 게임을 차단**한다. 다른 성에 자동 이동시키거나 첫 성으로 대체하지 않는다. 저장 전 오류가 발생하면 기존 정상 파일을 보존한다.
5. 기존 세이브는 자기 스냅샷으로 계속 열고, 구 형식의 시작 지도/장수 프리셋은 한 번만 새 구조로 가져온다. 마이그레이션 실패 시 원본을 보존하고 원인을 표시한다.

각 단계는 QA 결과와 함께 별도 커밋·푸시한다. Core의 데이터·검증은 xUnit, Game 연결은 빌드와 Godot headless 시작/저장 QA를 수행한다. 실제 화면 배치·입력은 자동 QA와 구분해 `run-scenario-editor.bat` 및 시작 화면에서 확인한다. 21C-1을 시작할 때 현재 데이터의 실제 범위와 세이브 스키마를 재조사하고, 위 파일 경로 후보를 확정한다.

## 6. 2026-10-29 구현 및 저장 호환성

- `run-scenario-editor.bat`는 독립 시나리오 편집 화면을 연다. 기본 정보, 지도 버전, 세력, 거점, 장수, 병력과 선박을 편집하고 검증한 뒤 `user://scenarios/<id>.json`에 원자 저장한다. 편집한 기존 지도는 `user://map-presets/east-asia.json`에서 새 지도 버전으로 가져온다.
- 지도 교체에서 **같은 지도 계보와 같은 거점 ID**만 초기 소유권과 장수 배치를 보존한다. 다른 지도나 삭제된 거점은 중립/미배치로 표시하고, 군주가 미배치되면 저장을 차단한다. 같은 이름의 다른 거점을 자동으로 합치지 않는다.
- 시작 화면은 시나리오와 세력을 고른 뒤 선택한 지도/거점/장수/병력/선박을 캠페인에 적용한다. 저장 슬롯 불러오기는 슬롯이 보유한 지도 스냅샷을 사용하여 화면을 다시 구성한다.
- 21C 이후의 신규 저장에는 지도 스냅샷이 포함된다. 이전 저장 파일 중 스냅샷이 없는 것은 현재 지도와 거점 ID·좌표가 모두 일치할 때만 불러온다. 일치하지 않으면 기존 저장 파일을 그대로 두고 원래 지도에서 다시 불러오라는 오류를 표시한다. 저장 당시의 지형을 기록하지 않은 구 세이브에서 지형을 임의로 추정하지 않는다.
- 현재 기본 시나리오는 기존 `data/*.json`에서 생성한다. 역사 시나리오 여섯 종의 세력·도시 수치 배치는 [역사 시나리오 초안](plan-historical-scenarios.md)의 별도 데이터 작업으로 남아 있다.
