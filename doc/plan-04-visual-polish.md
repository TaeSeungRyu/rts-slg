# 개발 계획 04 — 시각 개선 (표현 폴리시)

> 사용자 우선순위: **시각적 만족이 이후 작업 지속의 판단 기준**. 과거 "구성은 좋았지만 UI로 포기"한 경험을 넘기 위해,
> 맵+유닛 슬라이스(plan-02) 위에 **코드 드로잉 기반 시각 완성도**를 올린다. 아트 에셋(스프라이트) 없이 색·라벨·하이라이트·애니메이션으로 다듬는다.

## 확정된 설계 결정

- **아트 방향**: 무료 CC0 아트 에셋 도입으로 변경(당초 코드 드로잉에서 상향). **지형 타일만** 사용(Kenney Hexagon Pack, CC0), **도시·유닛은 마커 유지**(유럽풍 건물은 삼국지와 안 맞아 제외)
- **헥사 방향**: 아트가 **pointy-top**이라 Game의 픽셀 변환을 pointy-top으로 맞춤. Core는 좌표계 무관이라 변경 없음
- **도시 라벨**: 한글 이름 표시. **Pretendard**(SIL OFL) 번들
- **분리 원칙 유지**: 스프라이트·라벨·하이라이트·픽셀 변환은 Game(Godot). Core(맵·좌표·경로)는 그대로, 게임 규칙 변경 없음

## 검증 방식

각 단계마다 에이전트가 `--shot`으로 헤드리스 렌더를 캡처해 스크린샷으로 확인하고, 사용자도 실행/스크린샷으로 함께 다듬는다. "동작"이 아니라 **"보기 좋다"**가 완료 기준.

---

## 단계 세분화

각 단계는 독립 커밋, 빌드 green + 스크린샷 확인 후 푸시. 범례: 🔍 = 스크린샷으로 확인하는 지점(전 단계 해당).

### Step 1 — 한글 폰트 번들 + 도시 라벨 🔍
- **내용**: 한글 지원 폰트를 `SanguoSLG.Game/assets/fonts/`에 번들(라이선스 포함), `HexMapView`가 도시 마커 아래 이름(허창·업·성도·형주)을 `DrawString`으로 표시
- **확인**: 한글이 깨지지 않고(두부현상 없이) 렌더되는지 스크린샷

### Step 2 — 세력 색 구분 🔍
- **내용**: 도시·유닛을 소유 세력 색으로 구분(예: 위=청색, 촉=녹색). 세력색 팔레트는 Game 측 설정(FactionId 기준). 마커/토큰/라벨에 반영
- **확인**: 세력별 색이 한눈에 구분되는지

### Step 3 — 호버 하이라이트 + 경로 미리보기 🔍
- **내용**: 마우스 아래 헥사를 하이라이트. 유닛에서 호버 헥사까지 A* 경로를 실시간 선/점으로 미리보기(클릭 전에 어디로 갈지 보임)
- **확인**: 호버·경로 프리뷰가 부드럽고 정확한지

### Step 4 — 선택 표시 + 이동 이징 🔍
- **내용**: 유닛 선택 링, 이동 트윈에 이징(가속/감속) 적용, 이동 중 경로 잔상(선택). 손맛·가독성 강화
- **확인**: 선택·이동 애니메이션의 느낌

### Step 5 — 팔레트·타일·배경 폴리시 🔍
- **내용**: 타일 색/외곽선/미묘한 음영, 배경, 전반 팔레트 통일. 도시/유닛/그리드의 대비·톤 정리
- **확인**: 전체 화면의 완성도

### Step 6 — 마무리 + 회고
- **내용**: 헤드리스 빌드 최종 점검, 스크린샷 회고, 만족도 확인 후 다음 방향(지형/다중 유닛/내정) 결정
- **확인**: 사용자 최종 만족 여부
