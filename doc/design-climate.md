# 기후 설계 — 지역별 일반·비·눈

상태: **1차 구현·자동 QA 완료, 실기기 시각 검수 및 이동 경계 정밀 QA 대기** (2026-10-19). [v2 로드맵 Phase 21A](plan-v2-implementation-roadmap.md#phase-21a-지역-기후)의 진행 현황을 따른다. 현행 연속 이동의 판정 순서는 [Phase 18D 계획](plan-renewal-movement.md)을 우선한다.

## 1. 지도·시간 규칙

- 기후는 `일반`, `비`, `눈` 중 **타일마다 정확히 하나**다. 지형 종류와 별개인 상태이므로 눈 때문에 평지가 설산으로 바뀌거나 통행 가능 여부가 변하지 않는다.
- 비·눈은 지도 전체가 아닌 국지적 **6×6 헥사 영역**에서 발생한다. 6×6은 축좌표 `(q,r)`에서 각각 연속 6칸인 최대 36타일의 평행사변형 패치다. 맵 밖 타일은 잘라낸다. 실험 후 자연스러운 경계가 필요하면 패치 가장자리의 표시만 다듬고, 실제 효과 범위 36칸은 유지한다.
- 매일 `진행`의 **이동턴 시작 전**, 게임 달력을 기준으로 기후 상태를 한 번 갱신한다. 7일 진행 중에도 날짜별로 재판정하며, 진행 중 화면·정보 표시를 당일 상태에 맞춘다. 플레이어가 대기 중일 때는 날짜가 흐르지 않으므로 기후도 바뀌지 않는다.
- 눈의 신규 발생과 존속은 **12·1·2월에만** 허용한다. 2월 마지막 날 뒤 남은 눈은 3월 첫날 일반으로 정리한다. 비는 연중 가능하되 눈과 같은 타일에 동시 적용하지 않는다. 12~2월의 비/눈 비율·발생 빈도·지속일은 `data/balance.json`에 두는 조정 값이며 구현 전 밸런스 테스트로 확정한다. 시드 기반 난수로 동일 저장 상태와 날짜에서 동일한 결과를 만든다.
- 패치가 겹치면 한 타일의 기후가 중첩되지 않게 **기존 패치 우선**, 빈 타일에만 새 패치를 배치한다. 패치에는 ID·종류·타일 집합·시작/종료일을 저장한다. 지도 크기에 비례해 동시 패치 수를 제한하고, 전 지도 기후화는 허용하지 않는다.
- 1차 밸런스: 매일 새 패치 생성 시도 12%, 동시 최대 2곳, 3~6일 지속, 2일마다 원점 최대 1칸 이동. 수치는 `data/balance.json`에서 조정하며 눈의 겨울 신규 발생 확률은 현재 60%다. 저장한 패치/시드에 의해 같은 시뮬레이션은 재현된다.

## 2. 게임 효과

| 기후 | 이동 | 공격 | 시각 효과 |
|---|---|---|---|
| 일반 | 기존 속도 | 기존 공격력 | 없음 |
| 비 | 해당 구간 모든 부대 속도 ×0.70 | 해당 타일에서 **궁병 분류**가 공격할 때 공격력 ×0.80 | 해당 패치에 국지적 비 |
| 눈 | 해당 구간 모든 부대 속도 ×0.70 | 해당 타일에서 **기병 분류**가 공격할 때 공격력 ×0.80 | 해당 패치에 눈·적설 |

- 육상·해상·보급·수송·집단군·소환 부대 모두 이동 감속 대상이다. 병종 공격 페널티는 **공격자의 공격턴 시작 위치 타일**로 판정하고 반격에도 같은 기준을 쓴다. 집단군은 독립 `army_group` 분류로 취급하여 궁병/기병 페널티를 받지 않는다. 복합·특수 병종은 실제 데이터의 전투 분류를 사용하며 구현 시 분류표를 QA로 고정한다.
- 공격력 저하는 기본 `atk`와 연구·지형·스킬 등이 계산된 뒤 **기후 배수 한 번**을 적용한다. 피해량이나 방어력을 다시 20% 깎는 이중 적용은 금지한다. 기후가 다른 두 부대는 각자의 공격 위치를 따로 판정한다.
- 연속 이동에서 부대 판정 원/이동 선분이 기후 타일에 **닿는 구간부터** 감속한다. 하루 안에 맑은 곳과 기후 구역을 오가면 전체 하루를 일괄 감속하지 않고 접촉 구간에만 적용한다. 기존 지형 감속과는 서로 다른 요인으로 곱하되, 비와 눈끼리는 중복되지 않는다. 이동 소수 잔량 누산 및 30/60/144FPS 동일 결과를 유지한다. 기존 이동턴→공격턴 순서는 변경하지 않는다.
- 기후로 인한 이동 속도 변동은 현재 경로를 삭제하거나 재명령하지 않는다. 경로 예상 소요일은 현재 기후 기준의 추정치이며, 이후 날씨가 바뀌면 갱신한다. 화계 같은 스킬의 추가 상호작용, 낙뢰 확률 변화, 시야 감소는 **이번 범위에 넣지 않는다**.

## 3. 화면·에셋

- 비: 6×6 패치 내부에만 입자와 약한 지면 습윤 표현을 적용한다. 눈: 떨어지는 눈 입자와 타일 바닥·지형 윗면의 밝은 적설 오버레이/셰이더를 결합한다. 기존 GLB/충돌체/타일 원본 재질은 교체하지 않는다. 성·건축물의 적설 표현은 공용 윗면 마스크부터 시작하고 복잡한 모델별 지붕 가공은 후속 시각 개선으로 분리한다.
- 패치의 경계에서 비/눈 입자가 갑자기 끊겨 보이지 않도록 가장자리 **시각 효과만** 페이드한다. 게임 효과 판정은 정확한 타일 경계를 따른다. 물·다리에서 지면 적설을 칠하지 않고 눈 입자만 보여준다. 눈 오버레이가 선택 원, 이동 경로, 부대와 UI를 가리지 않도록 렌더 계층과 깊이를 검증한다.
- 저사양/화면 밖 패치는 GPU 입자 수를 제한하고 화면 밖 입자는 정지/생략한다. **논리 기후와 시각 효과는 분리**한다. 이펙트를 끄더라도 이동·공격 규칙은 동일하다.
- 1차 구현은 6×6 타일별 옅은 적설/습윤 육각 오버레이와 패치당 최대 24개의 작은 눈/비 입자를 사용한다. 높은 지형·성 지붕 자체에 눈이 쌓이는 정교한 마스크, 카메라 밖 입자 정지, 발생/소멸 페이드는 후속 시각 개선으로 남긴다. 따라서 이 문서의 최종 연출 목표와 1차 구현 품질을 혼동하지 않는다.
- 타일 정보에는 현재 기후와 `이동 −30%`, 해당 병종 `공격 −20%`를 표시한다. 선택 부대의 경로 미리보기와 교전 상세에도 영향받는 구간/공격 보정을 설명한다. 안개 속 기후 정보는 기존 시야 정책을 따라 숨기고, 확인된 타일에만 표현한다.

## 4. 구현 경계·저장·QA

1. Core에 Godot 의존 없는 `ClimateKind`, 타일별 기후 조회, 패치/달력 갱신, 시드 난수, 저장 상태를 추가한다. 설정 수치와 병종 분류는 데이터로 관리한다.
2. 이동 서비스의 지형 접촉 판정에 기후 구간 배수를 연결하고 기존 통행/충돌/지형 감속을 회귀 검증한다.
3. 공격·반격 공통 산출 지점에 기후 배수를 연결한다. AI도 동일한 Core 상태를 읽으며 별도의 AI 날씨 규칙은 만들지 않는다.
4. Game에서 국지적 비/눈과 적설, 정보 표시, `run-maptest.bat` 검수 장면을 연결한다. 기존 저장을 불러오면 기후 상태를 일반에서 시작하고, 신규 저장은 패치/남은 기간/난수 상태를 복원한다.

`run-maptest.bat`에는 좌측 상단 아래 테스트용 `☂ 비`/`❄ 눈` 버튼이 있다. 클릭 시 현재 화면에 보이는 타일을 우선하여 빈 6×6 영역을 골라 패치를 즉시 배치한다. 두 종류가 겹치지 않는 한 함께 볼 수 있고, 동시 2곳을 넘기면 오래된 테스트 패치부터 교체한다. 테스트 버튼은 일반 캠페인에 표시하지 않는다. 눈 버튼은 겨울 외에도 즉시 연출을 볼 수 있지만 다음 `진행`의 일별 갱신에서는 겨울 제한을 따른다.

필수 QA: 11월/12월/2월/3월 경계, 6×6과 맵 가장자리, 패치 중첩·전역 기후 방지, 하루 중 경계 통과, 지형 50%와 비/눈 70%의 결합, 전 병종 이동, 궁병/기병 공격·반격 각 20%, 집단군 예외, 저장/불러오기 재현성, 7일 진행 중 기후 변화, 30/60/144FPS 동일 결과, 안개·저사양 표시. 시각적 적설 품질은 사용자가 실기기에서 별도로 확인한다.
