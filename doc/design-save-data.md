# 저장·불러오기와 장수 데이터 계층

> 2026-09-29 기준. 저장 슬롯 UI를 실제 저장 기능에 연결하고, 장수 원본 데이터와 캠페인별 상태를 분리하기 위한 기준 문서다.

## 1. 20개 수동 저장 슬롯

- `게임 저장하기`와 `게임 불러오기`는 같은 1~20번 슬롯을 사용한다.
- 슬롯 메타데이터에는 저장 시각, 시나리오, 게임 년/월/일, 플레이 세력, 군주, 보유 도시 수를 기록한다.
- 빈 슬롯은 저장만 가능하고, 사용 중 슬롯을 저장 대상으로 고르면 덮어쓰기 확인창을 표시한다.
- 사용 중 슬롯을 불러오기 대상으로 고르면 불러오기 확인창을 표시한다. 빈 슬롯은 불러올 수 없다.
- 저장은 임시 파일에 전체 상태를 쓴 뒤 성공한 경우에만 대상 슬롯 파일을 교체하는 원자적 방식으로 처리한다.
- 불러오기 실패 시 현재 플레이 상태를 변경하지 않고 오류 원인을 사용자에게 알린다.
- UI만 갱신하고 실제 파일 기록이 누락되는 상태를 완료로 인정하지 않는다.

저장 대상에는 도시·항구·유적·시설, 세력 자원과 영입 포인트, 장수 런타임 상태, 부대·명령·연구,
정찰 만료일, 병종 해금, 난수/진행 기준 상태가 포함된다. 파생 UI 캐시와 Godot 노드 참조는 저장하지 않는다.

## 2. 장수 원본과 캠페인 상태 분리

### 원본 정의

- 저장소의 `data/generals.json`과 관련 초상/스킬 정의는 **오리진 데이터**다.
- 오리진 데이터는 새 캠페인의 초기값이며 실행 중 전투·성장·영입·배속 결과로 직접 수정하지 않는다.
- 장수 ID는 원본, 에디터 프리셋, 캠페인 세이브 사이에서 절대 변경하지 않는다.

### 새 게임 시작

1. 오리진 장수 정의를 읽는다.
2. 선택한 시나리오의 초기 배속·등장년도·후보 목록을 적용한다.
3. 게임 시작 전 장수 에디터 프리셋이 있으면 ID 기준 오버레이한다.
4. 결과를 캠페인 전용 장수 상태로 깊은 복사한다.

### 캠페인 진행과 저장

- 레벨·경험치·패시브 경험치·병종 숙련·소속 세력·주둔 도시·업무·해금/영입 상태는 캠페인 상태만 변경한다.
- 저장 파일은 해당 캠페인의 장수 상태를 보존한다. 불러올 때 오리진 파일의 현재 값으로 덮어쓰지 않는다.
- 향후 저장 데이터별 장수 에디터는 선택한 슬롯의 캠페인 상태만 수정한다. 오리진과 다른 슬롯에는 영향이 없다.
- 향후 게임 시작 전 에디터는 별도 프리셋을 만들며, 사용자가 명시적으로 원본 갱신을 선택하지 않는 한 `data/generals.json`을 수정하지 않는다.

권장 계층:

| 계층 | 역할 | 변경 주체 |
|---|---|---|
| `GeneralDefinition` | ID, 이름, 기본 능력·적성·스킬, 초상 키 | 오리진 데이터/개발자 |
| `GeneralPresetOverride` | 새 게임 시작 전 선택적 수정값 | 시작 전 장수 에디터 |
| `GeneralCampaignState` | 성장, 소속, 위치, 업무, 해금·영입 상태 | 게임 진행/세이브별 에디터 |

## 3. 버전과 호환

- 저장 파일에 스키마 버전을 기록한다.
- 새 필드는 기본값으로 보완하고, 제거된 내정 패시브·포로 상태 같은 구필드는 명시적 마이그레이션으로 제거한다.
- 오리진 데이터에 장수가 추가되어도 기존 세이브에 자동 편입하지 않는다. 시나리오/마이그레이션 규칙이 있는 경우에만 추가한다.
- 오리진에서 장수를 제거해도 기존 세이브의 ID 참조를 조용히 다른 장수로 바꾸지 않는다. 로드 오류 또는 지정된 대체 규칙을 사용한다.

## 4. 필수 QA

- 1~20번 각 슬롯의 신규 저장, 덮어쓰기, 불러오기, 빈 슬롯 거부.
- 저장 직후와 프로세스 재실행 후 상태 왕복 일치.
- 저장 실패·손상 파일 로드 실패 시 현재 게임 상태 보존.
- 서로 다른 두 슬롯의 장수 능력·소속·성장 상태가 섞이지 않음.
- 장수 에디터 프리셋이 새 게임에만 반영되고 오리진 파일과 기존 세이브를 변경하지 않음.
- 제거된 구필드가 있는 이전 저장의 마이그레이션과 최신 저장 재로드.
