# 전투 중심 리팩토링 계획

작성일: 2026-08-31  
목표: 삼국지 11/13식 내정·인사·연구 복잡도를 줄이고, 플레이 판단의 중심을 “어디서, 누구로, 어떻게 싸울 것인가”에 다시 둔다.

## 1. 현재 문제 인식

현재 프로젝트는 전투 축 자체는 꽤 강하게 만들어져 있다.

- 헥사 이동, 탐지, 추격, 사거리 정지
- 병종별 공격·방어·사거리
- 장수 선봉·부관 편성
- 공성, 성벽, 성 반격, 함락
- 군량, 보급, 입성, 야전 부대 유지
- 계략·특기·연구·시설·태수·시장·등용·충성·포로

문제는 뒤쪽 시스템들이 계속 붙으면서 플레이의 질문이 흐려졌다는 점이다.

처음에는 “전투를 받치는 최소 내정”이었지만, 지금은 내정과 인사 시스템이 독립 게임처럼 커졌다. 그 결과 사용자는 싸움보다 명령 팔레트, 조건, 시설, 장수 잠금, 연구, 수입 계산을 더 많이 신경 써야 한다.

따라서 리팩토링의 방향은 기능을 무작정 삭제하는 것이 아니라, 모든 시스템을 다음 질문에 종속시키는 것이다.

> 이 기능이 다음 전투 판단을 더 재미있게 만드는가?

그렇지 않다면 제거, 자동화, 후순위 보관 대상으로 돌린다.

## 2. 새 지향점

### 핵심 장르

전략 SLG 전체가 아니라, “헥사 기반 전술 캠페인”에 가깝게 재정의한다.

- 도시는 생산 거점이 아니라 전선 거점
- 장수는 인사 관리 대상이 아니라 부대 전투 스타일을 정하는 카드
- 내정은 성장 시뮬레이션이 아니라 전투 준비 버튼
- 연구는 장기 테크트리가 아니라 병종 선택을 강화하는 간단한 전투 보정
- 계략은 별도 외교/도시 공작이 아니라 전장 스킬

### 플레이 루프

리팩토링 후의 이상적인 한 사이클은 다음 정도가 좋다.

1. 전선 확인
2. 도시에서 부대 편성
3. 이동·공격·후퇴·보급 명령
4. 7일 진행
5. 전투 결과 확인
6. 손실 보충 또는 다음 공세 결정

내정 버튼을 여러 개 눌러 “도시를 키우는 게임”이 아니라, 전투 후 다음 결정을 압축해서 내리는 구조가 되어야 한다.

## 3. 유지할 핵심 시스템

### 반드시 살릴 것

아래는 게임의 정체성을 만든다. 제거하지 않는다.

| 영역 | 유지 이유 |
|---|---|
| 헥사 이동·사거리·탐지 | 전투 판단의 뼈대 |
| 병종별 차이 | 편성의 핵심 재미 |
| 장수 선봉·부관 | 역사 SLG 맛을 주되 전투에 직접 연결됨 |
| 공성·성벽·함락 | 캠페인 목표를 만든다 |
| 군량·보급 | 전선 길이와 진군 타이밍을 만든다 |
| 부대 입성·재편성 | 전투 후 회복 루프 |
| 최소 AI | 적이 싸움을 걸어와야 한다 |

### 간소화해서 살릴 것

| 영역 | 현재 | 리팩토링 방향 |
|---|---|---|
| 금·군량 | 도시별 월 수입, 시설, 세율, 태수 영향 | 도시별 기본 보급력으로 축소 |
| 시설 | 논·밭·마을·공방 건설, 체력, 업그레이드 | 대부분 제거 또는 시나리오 고정 거점화 |
| 연구 | 병종별 10단계, 성벽 연구, 공방 필요 | 3단계 이하의 간단한 병종 숙련/군제 보정 |
| 장수 잠금 | 모든 내정 명령에 장수 필요 | 전투 편성에만 장수 사용, 내정 장수 잠금 제거 |
| 계략 | 도시 계략 + 야전 계략 | 야전 계략 중심으로 통합 |
| 시장 | 자원 구매, 가격 변동 | 보급 부족 시 즉시 보급 구매 정도로 축소 |

### 제거 또는 보류할 것

아래는 현재 기준으로 전투 집중도를 흐릴 가능성이 높다.

| 기능 | 처리 |
|---|---|
| 세율 조정 | 제거 후보. 월 수입 최적화는 전투 집중과 거리가 멀다 |
| 치안 | 제거 또는 함락 후 회복 페널티 정도로만 유지 |
| 논·밭·마을 건설 | 제거 후보. 도시 개발 게임으로 흐른다 |
| 시설 업그레이드 | 제거 후보. 체력·수입·비용 UI가 과하다 |
| 태수 수입 보정 | 제거 후보. 장수 배치를 전투 밖으로 분산시킨다 |
| 충성도 급여·배신 | 보류. 삼국지 맛은 있지만 현재 목표와는 멀다 |
| 포로교환·외교 | 보류 |
| 탐색·보물 | 보류 |
| 시장 시세·계절성 | 제거 후보 |
| 도시 계략 | 야전 계략으로 흡수하거나 보류 |

## 4. 리팩토링 원칙

### 원칙 1. 도시 명령 수를 줄인다

최종적으로 성 클릭 시 명령은 4개 안팎이 좋다.

추천 명령:

- 출전
- 보충
- 재편성
- 수리 또는 방어 준비

선택 후보:

- 징집: 병력 부족 시 즉시 또는 짧은 지연으로 병력 확보
- 보급 구매: 군량 부족 시 금으로 보급 확보

삭제 후보:

- 세율
- 논·밭·마을 건설
- 시설 업그레이드
- 병종 연구
- 성벽 연구
- 등용
- 도시 계략
- 시장 상세 구매

### 원칙 2. 내정은 “월말 성장”보다 “전투 준비 상태”로 표현한다

현재는 월 금, 월 군량, 시설 수입, 세율, 태수 정치가 얽혀 있다. 전투 중심 구조에서는 다음처럼 단순화한다.

도시는 아래 3개 정도만 가지면 충분하다.

- 병력 풀
- 보급량
- 방어 상태

금은 꼭 필요하다면 전역 공용 자원으로 두는 것이 낫다. 도시별 금고는 수송·시장·태수까지 부르게 되어 복잡도를 다시 키운다.

### 원칙 3. 장수는 전투 카드로만 쓴다

장수를 내정 명령에 계속 쓰면 사용자는 좋은 장수를 전장에 낼지, 도시 명령에 묶을지 고민하게 된다. 이 고민 자체는 삼국지11스럽지만, 지금 목표에서는 전투 집중을 흐린다.

리팩토링 후 장수의 역할은 다음에 집중한다.

- 어떤 병종을 잘 쓰는가
- 어떤 패시브/액티브를 주는가
- 어떤 부관 조합이 좋은가
- 어느 전선에 투입할 것인가

정치·지력은 완전히 버리기보다 야전 효과로 전환한다.

- 정치: 보급 효율, 부대 유지, 회복률
- 지력: 계략, 정찰, 함정 해제
- 무력: 직접 전투

### 원칙 4. 연구는 병종 선택을 보조하는 정도로만 둔다

현재 병종 연구 10단계는 장기 운영 게임을 만든다. 전투 중심으로는 너무 길다.

대안:

- 세력 공통 연구 제거
- 도시 또는 세력별 “병종 숙련 0~3단계”만 유지
- 전투 경험 또는 특정 도시 점령으로 해금

예시:

| 단계 | 효과 |
|---|---|
| 0 | 기본 |
| 1 | 해당 병종 공격/방어 +1 |
| 2 | 해당 병종 이동/보급/사거리 중 하나 개선 |
| 3 | 특수 전술 또는 액티브 강화 |

핵심은 “10단계 숫자 올리기”가 아니라 “내 주력 병종의 전술성이 조금 열린다”가 되어야 한다.

### 원칙 5. 시설은 짓는 것이 아니라 점령하는 대상으로 바꾼다

논·밭·마을을 직접 건설하고 업그레이드하면 도시 개발 게임이 된다. 전투 중심으로는 맵 위 고정 거점이 더 좋다.

대안:

- 마을: 점령하면 병력 보충 보너스
- 논/밭: 점령하면 보급 회복 보너스
- 공방: 점령하면 공성 병기 편성 가능
- 항구: 점령하면 수군 편성 가능
- 광산/목장/상원: 특수 병종 편성 가능

즉, 시설은 “내정 버튼으로 키우는 대상”이 아니라 “싸워서 차지하는 전술 목표”가 된다.

## 5. 단계별 실행 계획

코드 수정은 한 번에 하면 위험하다. 기존 기능이 많기 때문에 작은 단계로 끊어야 한다.

### Phase 0. 방향 확정 문서화

목표:

- 이 문서를 기준으로 “전투 중심 모드”의 범위를 확정한다.
- 기존 삼국지식 확장 로드맵은 폐기하지 않고 “보류”로 이동한다.

작업:

- `doc/plan-roadmap.md`에 전투 중심 리팩토링 방향 추가
- 제거/보류/유지 목록 확정
- 코드 수정 없음

완료 기준:

- 사용자가 유지할 기능과 제거할 기능을 확정한다.

### Phase 1. UI 명령 팔레트 축소

목표:

- 플레이어가 보는 조작면부터 단순하게 만든다.
- 내부 로직은 당장 제거하지 않아도 된다.

작업:

- 성 명령 팔레트에서 전투 관련 명령만 남기는 실험 모드 추가
- 숨김 후보:
  - 세율
  - 건설
  - 시장 상세
  - 등용
  - 도시 계략
  - 연구
- 유지 후보:
  - 출전
  - 보충/재편성
  - 수리
  - 정보

완료 기준:

- 사용자가 성을 클릭했을 때 다음 전투 준비에 필요한 버튼만 보인다.
- Core 로직은 아직 삭제하지 않는다.

권장 커밋 단위:

- `refactor: 전투 중심 명령 팔레트를 분리`

### Phase 2. 경제 표시 축소

목표:

- 우측 성 요약에서 전투 판단에 직접 필요한 수치만 남긴다.

작업:

- 우측 요약 카드 핵심 수치 재정의:
  - 병력
  - 군량/보급
  - 성벽
  - 주둔 장수
  - 진행 중 전투 준비
- 숨김 후보:
  - 월 금
  - 월 군량
  - 세율
  - 시설 수입 상세
  - 치안
  - 광물/말/코끼리 상세

완료 기준:

- 성 요약을 봤을 때 “이 성에서 지금 싸울 수 있는가”가 먼저 보인다.

권장 커밋 단위:

- `refactor: 성 요약 정보를 전투 중심으로 정리`

### Phase 3. 시설 건설·업그레이드 비활성화

목표:

- 도시 개발 루프를 멈추고 전투 거점 루프로 전환한다.

작업:

- 건설 명령을 기본 UI에서 제거
- 시설 업그레이드 명령 비활성화
- 기존 세이브 호환을 위해 데이터 구조는 유지
- 이미 존재하는 시설은 고정 보너스 또는 전술 거점으로만 사용

완료 기준:

- 플레이어가 논·밭·마을을 직접 키우지 않는다.
- 공방은 “공성 병기 가능 거점” 정도로만 남는다.

권장 커밋 단위:

- `refactor: 시설 개발 명령을 전투 거점 규칙으로 축소`

### Phase 4. 자원 체계 단순화

목표:

- 금·광석·말·코끼리·군량의 복잡한 구매/생산 관계를 줄인다.

대안 A: 전역 자원화

- 금은 세력 공용
- 군량은 도시별 또는 전선별
- 광석/말/코끼리는 제거하거나 병종 해금 조건으로만 사용

대안 B: 보급 중심화

- 금 제거 또는 최소화
- 모든 전투 준비 비용은 “보급 점수”로 통합
- 도시마다 매주 보급 점수를 회복

추천은 B다. 싸움 중심 게임에서는 돈보다 “이 전선이 얼마나 버틸 수 있나”가 더 직관적이다.

완료 기준:

- 플레이어가 시장 시세나 월 수입보다 전선 보급을 본다.

권장 커밋 단위:

- `refactor: 경제 자원을 보급 중심으로 단순화`

### Phase 5. 장수 역할 전투화

목표:

- 정치·지력·무력 모두 전장 판단에 연결한다.

작업:

- 내정 명령 장수 잠금 제거
- 정치 효과를 부대 보급/회복/재편성 효율로 이동
- 지력 효과를 야전 계략/정찰/교란으로 이동
- 태수 수입 보정 제거 또는 자동 방어관으로 축소

완료 기준:

- 좋은 장수를 도시 클릭 노동에 묶지 않고 전투 편성에서 고민한다.

권장 커밋 단위:

- `refactor: 장수 능력치를 전투 역할 중심으로 재배치`

### Phase 6. 연구 축소 또는 폐기

목표:

- 장기 테크트리 관리를 줄인다.

작업:

- 병종 10단계 연구 UI 제거
- 성벽 연구 제거 또는 시나리오 진행 단계로 자동화
- 대체안으로 병종 숙련 0~3단계 도입 여부 결정

추천:

- 일단 연구 UI는 제거
- 기존 연구 데이터는 세이브 호환용으로 유지
- 이후 전투 경험 기반 숙련으로 다시 설계

완료 기준:

- 전투 준비 중 연구 버튼을 누르지 않아도 된다.

권장 커밋 단위:

- `refactor: 연구 시스템을 전투 숙련 후보로 축소`

### Phase 7. 계략을 야전 중심으로 통합

목표:

- 도시 계략과 야전 계략을 분리하지 않는다.

작업:

- 도시 계략 UI 제거 또는 보류
- 야전 부대 계략만 우선 완성
- 계략은 2일 예약 후 발동 구조를 유지하되, 전투 지도에서 대상 지정

완료 기준:

- 계략은 “전투 중 전선을 흔드는 기술”로 느껴진다.

권장 커밋 단위:

- `feat: 야전 계략 중심으로 계략 사용 흐름을 정리`

### Phase 8. 전투 중심 QA 시나리오 재작성

목표:

- 테스트 기준도 내정 성장보다 전투 흐름으로 바꾼다.

작업:

- 작은 전투 시나리오 3개 작성
  - 소성 공략
  - 보급선 압박
  - 공방 점령 후 공성 병기 투입
- 각 시나리오에서 필요한 UI 버튼 수와 판단 수를 측정

완료 기준:

- “한 턴에 해야 할 내정 클릭”이 줄고, “전투 판단”이 늘어난다.

권장 커밋 단위:

- `test: 전투 중심 시나리오 검증 케이스를 추가`

## 7. 위험과 대응

### 위험 1. 이미 구현한 코드가 아깝다

맞다. 하지만 삭제보다 “숨김/보류”부터 하면 된다. Core 기능을 바로 지우지 말고 UI에서 먼저 걷어내면, 되돌리기도 쉽고 비교도 가능하다.

### 위험 2. 삼국지 맛이 사라질 수 있다

삼국지 맛은 내정 버튼 수가 아니라 장수와 전선에서 나온다.

- 유비를 어디에 배치할지
- 관우를 선봉으로 쓸지 아낄지
- 공성 병기를 어느 전선에 보낼지
- 보급이 끊긴 부대를 구할지 버릴지

이쪽을 살리면 삼국지 감성은 남는다.

### 위험 3. 너무 단순해질 수 있다

단순함은 목표가 아니라 초점이다. 내정에서 줄인 복잡도는 전투에서 다시 쓸 수 있다.

예를 들어 시설 업그레이드를 없애는 대신, 공방을 점령해야 투석기를 뽑을 수 있게 하면 전투 목표가 생긴다.

## 8. 바로 다음에 할 만한 작은 작업

코드 수정 없이 다음 회의에서 먼저 결정할 질문은 3개면 충분하다.

1. 성 명령 팔레트에서 최종적으로 남길 버튼은 무엇인가?
2. 시설 건설/업그레이드를 완전히 숨길 것인가, “전투 중심 모드”에서만 숨길 것인가?
3. 금을 유지할 것인가, 보급 중심 자원으로 합칠 것인가?

결정 후 첫 구현은 Phase 1이 좋다. 내부 로직을 지우지 않고 UI만 전투 중심으로 줄이면, 가장 안전하게 체감 변화를 확인할 수 있다.
