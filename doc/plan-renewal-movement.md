# 연속 이동·이동턴/공격턴 개편 계획

작성일: 2026-10-04. 소속: [v2 로드맵 Phase 18D](./plan-v2-implementation-roadmap.md).
상태: **Phase 18D 10/12단계 완료. Core 연속 이동 전 규칙과 운영 AI·전용 저장 복원·공간 인덱스·50/100/300부대 부하 검증 구현, 캠페인 미연결.**

새 작업자는 [에이전트 시작 안내](../AGENTS.md)를 읽고, 이 문서 §14의 결정 목록과 §15의 단계별 실행 인계를 확인한다. §3의 확정 계약과 제안 API는 구현 완료를 의미하지 않는다. 5.6 sol을 포함한 다른 모델에 인계할 때도 같은 기준을 사용한다.

최신 합의(2026-10-04): **연속 이동 + 아군 중첩 + 이동턴/공격턴 유지**로 개편한다. 진행 한 번은 7일이며, 매일 이동턴과 공격턴을 순서대로 처리한다. 이동 중에는 고정 틱으로 이동·탐지·충돌을 확인하고, 일반 공격·반격은 공격턴에서 묶어 계산한다. 이전의 독립적인 초 단위 공격 쿨다운 계획은 대체한다. 아군 도착 시 근거리 분산, 모든 건물·건축물 통과 금지는 유지한다.

**행군 후속 확정:** 행군은 적 사거리 진입만으로 멈추지 않는다. 이동 후처리가 끝난 **공격턴 시작 위치**에서만 일반 교전의 사거리·대상을 판단한다. 이미 사거리를 벗어났으면 통과에 대한 피해는 없으며, 과거 위치의 공격 예약·소급 피해는 사용하지 않는다. 적 부대·건물 자체의 관통 금지는 유지한다.

## 1. 목적과 적용 순서

타일을 선점해야 이동하는 구조를 연속 위치 기반 이동으로 바꾸되, 이동턴/공격턴은 유지한다. 이동턴 내부에서 이동·탐지·충돌·추격을 일정 시간 간격으로 판단하고 공격턴에서 유효 교전을 계산한다. 타일은 지형·시야·효과 범위를 정의하는 지도 단위로 계속 사용한다. 기존 피해·부상·반격 공식과 일/주 정산을 보존하면서 출격·이동·단계 후처리를 개선한다.

기존 출격에서 관찰한 문제는 방향과 실제 출구 불일치, 아군 점유로 인한 우회·장기 대기, 중형성 내부 출현, 목표 지정 두 번 필요, 순간이동·깜빡임, 도착 후 무행동이다. 겹침 허용은 아군 길막을 줄이지만 목표 상태와 화면 재생 오류까지 자동으로 해결하지 않는다. 좌표·명령·시계·사건 전달도 함께 정리한다.

현행 [이동 설계](./design-movement.md), [전투 설계](./design-combat.md), [스킬 설계](./design-skill.md), [야전 건축 계획](./plan-v2-implementation-roadmap.md), [저장 설계](./design-save-data.md)를 비교 기준으로 삼는다. 이 문서는 신규 모드의 구현 목표이며 기존 모드가 이미 전환되었다는 의미가 아니다. 사용자 확정 15개 규칙이 충돌하는 현행 규칙보다 신규 모드에서 우선한다.

## 2. 사용자 확정 요구사항

| 번호 | 확정 규칙 | 구현 계약 |
|---:|---|---|
| 1 | 목적지를 클릭하여 이동 | 클릭 지점을 연속 목표로 보존. 경유지는 순서대로 소비 |
| 2 | 목적지 방향을 바라보고 출성 | 거점 외곽의 목적지 방향 경계에서 출격. 반대편 임의 출현 금지 |
| 3 | 칸에 걸쳐도 이동 제약 적용 | 부대 판정 원과 지형 타일의 교차로 효과 판정. 이동 구간도 검사 |
| 4 | 아군 중첩 허용, 적군 중첩 불가 | 같은 세력은 서로 통행 장애물이 아님. 도착 시 근거리 분산, 공간 부족 시 중첩 허용 |
| 5 | 모든 건물·건축물 통과 금지, 입장만 허용 | 아군·적군·중립 모두 장애물. 건물 외곽 충돌과 허용된 명시적 입성 전환 분리 |
| 6 | 액티브는 기존 칸 기준 주변 적 모두 적용 | 기존 효과별 타일 집합과 교차하는 적을 ID별 1회 적용 |
| 7 | 이동턴·공격턴 분리 유지(최신 합의로 변경) | 이동턴은 고정 틱 연속 이동·탐지, 공격턴은 하루 한 번 교전 정산. 공격 가능한 거리 진입은 이동 중 확인 |
| 8 | 겹친 아군은 목록부터 선택 | 아군 목록 팔레트 → 부대 선택 → 기존 명령 팔레트 |
| 9 | 소형 3·중형 5·대형 7부대 공성 | 성 전체 공유 공격 참여권. 나머지는 주변 대기 |
| 10 | 행군은 사거리를 무시하고 이동 | 사거리 진입만으로 정지하지 않음. 공격턴 시작에 사거리 안이면 기존 행군 피해·무반격. 적 부대·건물 관통 금지 |
| 11 | 전진은 발견한 적을 추격·공격 | 부대·건축물·성·항구 대상으로 탐지, 시야를 잃으면 원래 목적지 재개 |
| 12 | 공격은 지정 대상만 공격 | 타 대상에게 받는 피해는 행군 판정. 주변 대상으로 임의 전환 금지 |
| 13 | 보급·효과 범위는 기존 타일 기준 | 같은 범위 제공자로 판정과 UI 미리보기 연결 |
| 14 | 병종별 이동속도 | 집단군 최저, 기병 최고. 세부 값은 데이터에서 조정 |
| 15 | 주 피해 대상 1개·반격 N개 유지 | 공격턴마다 능동 공격 1회와 해당 교전의 반격 N개를 중복 없이 기존 공식으로 계산 |

같은 세력 중첩 자체에 추가 피해 패널티는 도입하지 않는다. 일반 공격은 선택한 대상에게만, 광역 스킬은 범위 내 적 모두에게 적용한다. 과거에 논의했던 '겹치면 일반 공격 피해 복제'는 이번 확정 목록에 없으므로 적용하지 않는다.

## 3. 시간·좌표·모드 계약 — Phase 18D 1단계 확정

진행 7일, 하루 이동턴→공격턴, 공격턴당 기본 능동 공격 1회는 이번 합의의 기준이다. 아래 값은 1단계에서 구현 계약으로 확정한 초기값이다. 밸런스 조정은 데이터 변경으로만 하며, 재생속도를 바꿔도 하루 이동거리·공격 횟수·스킬 충전량은 바뀌지 않는다.

| 항목 | 확정값 | 구현·검증 계약 |
|---|---|---|
| 논리 좌표 정밀도 | 인접 헥사 중심 거리 `1칸 = 1,000` 고정소수점 단위 | Core 정수 좌표가 원본. Godot 좌표·화면 픽셀·프레임 보간값은 원본 상태로 역수입하지 않음 |
| 이동 판정 간격 | 이동턴 내부 시뮬레이션 `0.1초 = 1틱` | 화면 FPS와 독립인 고정 스텝. 하루 50틱 |
| 이동 시간 예산 | 이동턴당 시뮬레이션 5초 | 공격턴은 별도 단계. 이동 연출이 끝나도 하루 후처리까지 날짜를 증가시키지 않음 |
| 게임 진행 | **확정:** 이동턴→공격턴을 하루로 하여 7일 반복 후 정지 | 적이 없어도 공격턴과 후처리는 수행. 검수장에 한 틱/한 단계/하루 실행 제공 |
| 기본 공격 주기 | **확정:** 공격턴당 최대 1회 능동 공격 | 액티브 연타는 한 행동의 하위 타격. 반격 N개는 별도 대응이며 재반격 금지 |
| 액티브 | 공격턴의 실제 교전 참여 시 일당 최대 1칸, 충전 후 당일 발동 판정, 선봉/부관 교대 | 공격 또는 유효 피격·반격 참여를 합쳐 부대당 1칸. 이동·사거리 통과만으로 충전하지 않음 |
| 기존 '1진행' 지속 시간 | 게임 7일, 일 단위 효과는 게임 1일 | 아래 환산표를 기준으로 하며 재생 버튼 횟수나 FPS에 종속되지 않음 |
| 동맹 중첩 | 동일 세력만 중첩, 동맹은 비공격 장애물 | 적대 여부와 충돌 여부를 분리 |
| 항구 공격 상한 | 소형 3·중형 5, 육상·해상 합산 | 항구 전체가 공유하는 공격 참여권. 먼저 유효 사거리에 든 명령 순서→부대 ID 순 |
| 보루·진법·유적 공격 상한 | 별도 상한 없음 | 성·항구의 참여권을 자동 확장하지 않음. 사거리·모드·생존 조건을 만족한 전 부대가 공격 가능 |
| 병종 이동거리 | 기존 `movement_per_day`를 하루 연속 거리로 그대로 사용 | 속도 1/2/3은 하루 1/2/3칸. 50틱에 균등 분배하고 나머지는 정수 누산하여 유실 금지. 집단군은 기존 속도 1 유지 |
| 부대 판정 반경 | 180 단위(0.18칸) | 모델 장식 크기와 독립. 부대끼리 적대 충돌에 사용 |
| 도착 허용 오차 | 50 단위(0.05칸) | 남은 거리가 이 값 이하면 정확한 목표 위치로 확정하고 도착 사건 1회 발생 |
| 아군 분산 상한 | 원 목적지에서 500 단위(0.5칸) | 유효 후보가 없으면 중첩. 분산 보정으로 사거리·보급 범위를 바꾸지 않음 |
| 사거리 경계 | 중심 간 거리 `<= 사거리×1,000`이면 포함 | 최소 좌표 단위 1을 ε로 사용하여 `R-1`, `R`, `R+1` 회귀 검사. 다중 타일 건물은 논리 발자국의 가장 가까운 점 기준 |

평면 좌표는 렌더링과 무관한 Core 고정소수점 `(X, Y)`다. `HexCoord` 중심을 평면 좌표로 바꾸는 변환은 하나의 `HexSpace` 계열 서비스로만 제공하고, 현재 맵의 헥사 방향을 그대로 사용한다. 거리·범위·충돌은 정수 제곱 거리 또는 결정론적 정수 연산으로 비교한다. 부동소수점은 Game의 화면 보간에만 허용한다.

이동량은 `movement_per_day × 1,000`을 하루 50틱에 분배한다. 속도 1/2/3의 무감속 이동은 각각 틱당 20/40/60 단위이므로 정확히 하루 1/2/3칸을 이동한다. 지형·상태 보정에서 나눗셈 나머지가 생기면 부대별 누산기에 보존하며 FPS나 부대 처리 순서 때문에 버리지 않는다. 공격턴에는 이동 예산을 소비하지 않는다.

지형 접촉은 이전 위치에서 다음 위치까지 부대 판정 원을 쓸어 검사한다. 여러 감속 지형이 겹치면 가장 강한 감속 하나만 적용하며 가산하지 않는다. 통행 불가 지형·적 부대·건물은 이동 구간 전체를 검사하여 빠른 기병도 관통하지 못한다.

### 기존 시간 표현 환산표

| 기존 표현/데이터 | 신규 모드 의미 | 중복 방지 키 |
|---|---|---|
| 진행 1회 | 게임 7일, 매일 이동→공격→정산 | `(진행 ID, 날짜)` |
| `movement_per_day = N` | 하루 이동턴에 최대 N칸 연속 거리 | `(날짜, 부대 ID, 이동 틱)` |
| 실제 교전 1회 | 같은 날짜 공격턴의 연결된 교전 묶음 1회 | `(날짜, 교전 사건 ID, 부대 ID)` |
| 액티브 게이지 +1 | 해당 공격턴에 공격하거나 유효 피해/반격 대상이 된 부대당 1칸 | `(날짜, 부대 ID, combat-charge)` |
| 병종 숙련 +1 | 해당 공격턴 실제 교전 참여 부대의 장수당 1, 협공 수와 무관 | `(날짜, 장수 ID, 병종)` |
| 전투/패시브 경험치 | 현행 하루 교전 성장값을 실제 참여 장수에게 1회 | `(날짜, 장수 ID, combat-growth)` |
| 지속 상태 남은 1 | 게임 하루 종료 시 1 감소; 새로 부여된 날에는 즉시 추가 틱하지 않음 | `(날짜, 부대 ID, 상태 종류)` |
| 출전 지연 N일 | N번의 하루 종료 전까지 거점 예약, 다음 날 이동턴 시작에 출격 시도 | `(예약 ID, 출격 가능 날짜)` |
| 진법 판정 | 이동 후처리에 범위 내 적 부대당 하루 1회 | `(날짜, 진법 ID, 부대 ID)` |
| 연구·건축·생산 N일 | 하루 종료에서만 1일 경과 | `(날짜, 작업 ID)` |

군량·부상 회복·경험치·진법 확률·화계 피해는 판정 틱 수만큼 반복 적용하면 안 된다. 일/진행/이동턴/공격턴 단위로 적용 완료 ID를 저장한다. 진법은 **이동턴 종료 후 공격턴 전에** 범위 내 대상에게 기존 확률로 1회 판정한다. 병종 숙련도는 공격턴 실제 교전 참여 부대의 장수마다 1이며, 같은 날 협공 수로 증가하지 않는다.

### 하루의 처리 순서 — 확정

1. **이동턴:** 출격 가능 예약 처리 → 모든 부대의 연속 이동·탐지·충돌·추격 → 도착/입성 사건 처리. 전진·공격은 유효 대상 사거리에 도달하면 멈추고 공격턴을 기다린다. 행군은 사거리만으로 멈추지 않고 적 부대·건물을 관통하지 않는 범위에서 계속 이동한다.
2. **이동 후처리:** 도착·입성·생산 진입을 반영하고 진법 등 이동턴 효과를 계산한다. 이 효과로 괴멸한 부대는 즉시 제거하여 공격턴에 참여하지 않는다. 입성한 부대는 주둔 상태로 반영하고 이전 야전 위치로 소급 피격시키지 않는다.
3. **공격턴:** 후처리 완료 상태의 현재 위치에서 생존·적대·시야·사거리·모드 검사 → 공성 참여권/주대상 확정 → 방어 스킬 우선 → 기존 능동 공격·반격·액티브 계산 → 피해 반영.
4. **공격 후처리:** 괴멸·건축물 파괴·주둔 해제·성/항구 점령·입성·노획을 즉시 반영한다. 다음 이동턴이나 7일 진행 종료까지 미루지 않는다. 이미 공격을 수행한 부대의 행동권을 재생성하지 않는다.
5. **하루 종료:** 기존 날짜 경계의 자원·연구·생산·지속 상태를 한 번 정산하고 다음 날로 넘어간다. 7일째는 정산 후 명령 대기로 돌아간다.

게임 날짜는 논리적 하루 종료로 흐르며 이동/공격 연출의 실제 재생시간과 분리한다. 공격 이펙트 길이에 따라 추가 공격이나 추가 날짜가 발생하지 않는다.

## 4. 연속 위치와 지형

- Core에 엔진과 무관한 평면 좌표·거리·판정 원을 추가한다. 고정소수점 정수 좌표/정수 틱을 권장한다. 화면 픽셀이나 Godot `Vector3`를 Core에 넣지 않는다.
- 평면 좌표가 실제 위치의 원본이며 `HexCoord`는 지형·범위 조회용 파생 정보다. Game이 표시 좌표를 Core로 역전송해 이동 결과를 덮어쓰지 않는다.
- 헥사 A*는 큰 경로 후보를 만드는 데 재사용할 수 있다. 실제 이동은 칸 중심으로 순간 이동하지 않고 충돌 여유를 둔 연속 경로를 따른다. 모서리 단축 경로는 통과 가능성을 재검사한다.
- 통행 불가 지형·적 부대·건물은 시작점→끝점 전체를 쓸어 검사한다. 큰 프레임 지연, 빠른 기병, 서로 마주 오는 적도 관통하지 않아야 한다.
- 이동 제한 지형과 판정 원이 조금이라도 겹치면 적용한다. 여러 지형 감속이 겹치면 가장 강한 감속 하나만 적용한다. 같은 지형 효과가 경계에서 중복 가산되지 않는다.
- 일반 육상 부대는 해상 진입 불가, 선박은 육상 진입 불가. 항구의 입출항 경계만 전환점이다. 안개는 통행 금지가 아니며 보이지 않는 적의 위치를 길찾기 미리보기로 노출하지 않는다.
- 아군은 경로 장애물에서 제외한다. 적을 만났을 때 모드에 따라 교전·우회·대기하며 실패 이유를 남긴다. 위치 강제 보정으로 반대 방향에 재생성하지 않는다.
- 성·항구・목책·정찰대·감시탑·보루·진법·유적·논·밭·마을 등 모든 건물/건축물은 소유 세력과 무관하게 통과 금지다. 건물의 게임 판정 외곽을 장애물로 쓰며, 장식용 구름·연기·처마는 충돌 면적을 늘리지 않는다.
- 정찰대도 존재하는 동안에는 통과 금지다. 적 경로 계획은 보이지 않는 정찰대를 장애물로 미리 노출하지 않는다. 실제 이동 구간의 판정 원이 정찰대 논리 외곽에 처음 접촉하면 공격 없이 즉시 철수·소멸시키고, 그 틱의 남은 이동량으로 계속 이동한다. 소멸 사건은 정찰대별 1회만 발생한다.

### 도착 시 아군 분산 배치 — 확정

- 같은 목적지로 이동하는 아군은 이동 중 중첩할 수 있다. 도착할 때 가까운 유효 위치로 조금씩 분산한다. 빈자리 확보를 출격/이동의 필수 조건으로 만들지 않는다.
- 원래 목적지는 유지하고 분산 위치만 별도로 저장한다. 결정론적인 후보 순서로 한 번 선택하며, 매 틱 서로 밀어내거나 자리 교환을 반복하지 않는다.
- 분산 위치까지 실제로 이동한다. 순간이동·모델만 옮기는 표현 보정으로 처리하지 않는다. 경로와 판정 위치가 일치해야 한다.
- 분산은 적·건물·통행 불가 지형을 침범하지 않는다. 근처에 적절한 공간이 없으면 원래 목적지에서 아군 중첩을 허용한다.
- 입성·생산 진입·공격 사거리 도달·공성 대기는 각각의 목표 조건을 우선한다. 분산 때문에 사거리/보급권 밖으로 나가거나 원치 않는 다른 시설에 들어가지 않는다.
- 최대 분산 거리는 1단계 검수용 수치로 정한다. 추천 상한은 원래 목적지에서 0.5칸거리이며 불가능하면 중첩한다.

## 5. 출성·입성

1. 편성은 거점 내부 예약 상태를 가진다. 출전 지연 0~6일은 게임 시계의 출격 가능 시각으로 환산한다.
2. 목적지(경유지가 있으면 첫 경유지) 방향과 성 전체 외곽의 교점을 출발 경계로 선택한다. 모델 중심이나 중형성 중심 타일에 야전 부대를 먼저 생성하지 않는다.
3. 항구는 선택 병종의 육지/해상으로 연결되는 유효 외곽만 쓴다. 그 방향에 유효 출구가 없으면 미리보기에서 알리고 예약 대기한다. 무단 반대편 출구 변경은 금지한다.
4. 같은 세력 부대는 출구를 막지 않는다. 같은 방향 동시 출격을 허용한다. 적·통행 불가 지형·건물이 막으면 예약에 남기고 이유를 표시한다.
5. Game은 Core가 보낸 출격 시각과 경계 위치부터 보간한다. 야전 위치, 표시 시작점, 최종 목표를 서로 바꾸지 않는다.
6. 복귀 대상은 도시/항구 ID로 보존한다. 해당 외곽 입구에 닿은 틱에 입성·자원 합산·장수 배치·필드 제거를 원자적으로 처리한다. 가는 길의 다른 아군 성에 잘못 들어가지 않는다.
7. 보루/진법 입장도 ID·아군 여부·수용 1부대 조건으로 별도 처리한다. 파괴되면 주둔 부대를 유효 외곽 위치로 한 번만 복원하고 같은 전투 흐름에 연결한다.
8. 성/항구 점령 조건 충족 시 즉시 소유권·주둔·노획·장수·입성 처리를 완료한다. 집단군 입성 시 원래 병종으로 분해하며 임시 army_group 병종을 주둔 병력에 남기지 않는다.
9. 논·밭·마을 생산 작전은 해당 시설 외곽에 도착한 뒤 명시적 생산 진입으로 전환한다. 일반 이동은 시설을 관통하지 않는다. 입장 가능한 건물도 목적지로 지정하지 않았다면 통과용 지름길로 사용하지 않는다.

## 6. 모드와 목표 상태

명령에는 명령 ID, 부대 ID, 모드, 원래 목적지/경유지, 지정 대상 ID, 현재 추격 대상 ID를 구분해 저장한다. 이동하는 적은 좌표가 아닌 ID로 추적한다. 명령 확인 1회로 원자 적용하며 UI가 두 번째 부대 명령을 첫 번째 예약에 덮어쓰지 않게 한다.

| 모드 | 이동·탐지 | 교전 | 목표 상실 |
|---|---|---|---|
| 행군 | 사거리 진입은 무시하고 목적지로 이동, 적 부대 충돌 시 우회 또는 대기 | 공격턴 시작 시 사거리 안에서 유효 공격을 받으면 현행 행군 피해·무반격. 사거리 밖이면 통과 피해 없음 | 도착 즉시 **대기** 전환. 자동 추격·능동 공격은 없고, 이후 공격받으면 정상 반격 가능 |
| 전진 | 발견한 적 부대·건물·성·항구를 추격 | 사거리 도달 시 정지, 공격턴에 유효 사거리 재검사 후 공격·기존 반격 | 추격 대상이 시야를 잃거나 제거되면 같은 이동턴의 남은 예산으로 원래 목적지/남은 경유지 재개 |
| 공격 | 지정 대상 ID만 추적, 다른 적은 통행 장애물로만 취급 | 지정 대상과 정상 교전, 비지정 대상에게는 행군 피해·반격 금지 | 시야 상실 시 마지막 확인 위치까지 이동 후 대기. 대상 제거·우호화 시 즉시 대기 |

`대기`는 목적지·추격 대상이 없는 명시적 상태다. 기존 코드 이행 중 `Advance + Target=null`로 표현할 수는 있으나, 능동 공격/자동 추격을 허용하는 의미로 사용해서는 안 된다. 신규 상태 모델에는 `Standby` 또는 동등한 상태를 분리한다.

캠페인에서 7일 진행이 시작되면 중간 재명령은 허용하지 않는다. 일시정지·배속은 재생 제어일 뿐 Core 명령 접수 시점을 열지 않는다. 독립 검수장만 디버깅을 위해 한 틱·한 단계·하루 실행과 초기화를 제공한다.

전진은 한 번 선택한 추격 대상을 시야 안에서 유지하여 매 틱 다른 적으로 흔들리지 않는다. 대상이 사거리 밖으로 벗어나도 시야 안이면 같은 이동턴의 남은 예산으로 추격을 재개한다. 시야를 잃거나 제거되면 즉시 원래 목적지로 복귀하며, 그날 남은 이동 예산만 사용한다.

현재 `FieldUnitCommandService`의 적 점유 좌표 자동 Attack 전환은 신규 UI에서 명시적 공격 명령에만 사용한다. 사용자가 고른 행군 모드를 Core가 몰래 바꾸지 않도록 명령의 의도를 보존한다. 이번 모드 의미는 오래된 이동 문서의 '공격이 주변 적 추격' 규칙보다 우선한다.

대상 선택 동률은 거리 → 명령 순번 → 부대 ID로 고정한다. 정찰대는 적 건물 자동 탐지/공격 대상에서 제외한다. 목표가 함락되어 아군이 된 경우 입성 가능 여부를 재검사하며 적대 공격을 지속하지 않는다.

## 7. 교전과 공성 참여권

이동 중에는 거리·탐지·추격·충돌을 검사하고, 일반 교전은 공격턴 시작의 현재 위치로 판단한다. 과거 사거리 통과 이력을 피해 근거로 사용하지 않는다. 부대별 독립 초 단위 공격 쿨다운은 사용하지 않는다. 같은 공격을 AnimationPlayer 콜백이나 매 프레임에서 다시 계산하지 않는다.

### 공격·반격 합의 — 확정

능동 공격은 공격턴에 먼저 공격하는 행동이고, 반격은 해당 교전에서 공격받은 대상에 대한 대응이다. 각 부대의 기본 능동 공격 기회는 공격턴당 1회다. 능동 공격을 수행했다는 이유만으로 반격 N개를 막지 않되, 같은 교환의 같은 대상에게 능동 공격과 반격을 두 번 더하지 않는다. 반격은 추가 공격턴을 생성하지 않는다.

| 상황 | 처리 계약 |
|---|---|
| A만 능동 공격, B는 반격 가능한 대기 | A 공격 + 조건을 만족하는 B 반격. B의 다음 공격턴 행동을 차감하지 않음 |
| A와 B가 같은 공격턴에 서로 공격 | 하나의 교환으로 A→B와 B→A 계산. 각 방향에 능동 공격과 반격을 추가로 두 번 더하지 않음 |
| B·C·D가 같은 공격턴에 A를 공격 | 같은 교전 묶음에서 A의 주대상/추가 반격 대상 N개를 기존 공식으로 계산. 독립 1:1 세 개로 반격 정타를 반복하지 않음 |
| A가 행군 중 | 반격 없음. 기존 행군 피해 판정 |
| A가 B를 지정 공격 중인데 C가 공격 | B와 정상 교전, C에게는 행군 피해 판정·반격 금지 |
| 반격 피해가 발생 | 반격을 원인으로 다시 반격하는 사건을 생성하지 않음 |

권장 구현 절차:

1. 이동 후처리 완료 상태에서 실제 공격 가능한 부대의 능동 공격 의도를 수집한다. 현재 위치의 사거리·시야·적대·생존·모드·공성 참여권·상태이상을 검사한다.
2. 같은 공격턴의 실제 공격 관계로 연결된 교전 묶음을 만든다. 서로 관계없는 전투를 하나로 합치지 않는다. 연결되어 있다는 이유로 현재 유효 사거리 밖 대상에게 피해를 주지 않는다. 유적 등 기존에 명시된 반격 사거리 예외는 유지한다.
3. 방어 스킬을 우선 반영하고 각 부대의 주대상과 유효 반격 대상을 기존 순서/수식으로 결정한다. 모드·반격 사거리·공격 불가 부대 등 기존 예외는 유지한다.
4. `(교전 사건 ID, 피해를 주는 부대 ID, 받는 대상 ID)`별 기본 교환을 한 번만 산출한다. 액티브의 명시적인 연타·광역·지속 피해 사건은 별도 하위 사건으로 보존한다.
5. 같은 교환의 피해를 동일 기준 스냅샷으로 계산한 뒤 적용한다. 해당 공격턴의 행동 완료를 기록하고, 피해 반영 후 괴멸·점령·전리품을 처리한다.

이동 중 사거리에 도착한 시각이 1틱 달라도 같은 공격턴에 참여하면 같은 교전 단위로 계산한다. 따라서 이전 계획의 독립 공격 시차에 따른 반격 횟수 차이는 별도 쿨다운을 추가하지 않고 공격턴 공통 정산으로 해결한다.

### 행군의 사거리 통과 — 확정

- 이동 중 적 사거리를 지나쳐 공격턴 시작 전에 벗어났다면 해당 통과로 인한 피해는 없다. 사거리 안에 들어갔다 나오는 횟수도 피해·충전·경험치 근거가 되지 않는다.
- 공격턴 시작에 사거리 안에 남아 있고 적의 유효 공격 대상으로 선정되었다면 기존 행군 피해 판정을 적용하고 반격하지 않는다. 단순히 사거리 안에 있다는 이유만으로 모든 적이 추가 공격하지 않는다.
- 이동 중 목적지 성·항구 외곽에 도착하면 기존 입성 조건을 검사하고 즉시 입성한다. 지나온 사거리 때문에 입성을 지연하거나 야전 피해를 나중에 주둔 병력에 소급하지 않는다. 입성한 성/항구가 공격받는 경우에는 정상 수성 규칙을 적용한다.
- 적 부대·건물이 물리적으로 길을 막으면 우회 또는 대기한다. 사거리 무시는 충돌 무시가 아니다. 전진 모드 적은 이동 중 행군 부대를 탐지·추격할 수 있고, 최종 위치가 사거리 안이면 공격턴에 교전한다.
- 과거의 통과 공격 예약·피격 후보·접촉 위치 소급 연출·미정산 통과 기록 저장 계획은 폐기한다. 화면 공격도 공격턴의 현재 위치를 기준으로 표현한다.
- 이 규칙은 일반 공격에 관한 것이다. 진법·지형 효과·이미 적용된 지속 피해의 기존 발생/만료 조건은 별도로 유지하며, 사거리를 벗어났다고 그 효과까지 면역이 되지 않는다.

### 공성 참여권과 후처리

- 기존 공방·훈련·병종 상성·장수·패시브·성벽 붕괴·건물 방어·부상/사망·전리품 공식을 재사용한다.
- 주대상 1개와 반격 N개는 기존 교전 묶음으로 계산한다. 같은 공격턴의 다대일을 독립 1:1 루프로 풀어 반격을 중복 가산하지 않는다. 기존 주대상 100%/추가 대상 60%와 성의 예외는 기존 공식 기준이다.
- 공격 모드의 비지정 대상 및 행군의 반격 금지가 우선한다. 반격이 새 반격을 끝없이 생성하지 않는다.
- 공성 참여권은 성 ID별 소형 3·중형 5·대형 7개, 공격 측 모든 세력·근접·원거리 합산이다. 성의 타일별로 따로 상한을 두지 않는다. 집단군도 1부대로 센다.
- 유효 사거리에 도착하고 공격 가능한 부대부터 참여한다. 동률은 도착 틱 → 명령 순번 → 부대 ID. 원거리 부대도 성의 실제 외곽에서 거리를 계산한다.
- 빈자리를 기다리는 부대는 주변 유효 지점에 정지하고 `공성 대기 3/3` 등 이유를 표시한다. 대기열에 있다고 성의 사거리나 적 광역 피해로부터 면역이 되지는 않는다.
- 참여 부대의 사망·후퇴·명령 변경·사거리 이탈·성 점령 시 즉시 참여권을 해제한다. 공격턴 시작 시 참여 명단을 고정하고, 그 공격턴 도중 빈자리를 승계한 부대는 다음 공격턴부터 공격한다. 같은 공격턴에 부대 교체로 3/5/7 상한을 초과하지 않는다.
- 원거리 피해·액티브로 성을 공격하는 경우에도 공성 상한을 우회할 수 없다. 성 피해는 참여권 보유자만 줄 수 있고, 주변 야전 부대를 대상으로 한 광역 피해는 정상 처리한다.

§3의 하루 처리 순서를 공통으로 사용한다. 이동 틱에서 일반 공격을 실행하지 않으며 공격턴 후처리가 끝나기 전에 다음 이동턴을 시작하지 않는다. 후속 대상은 생존 여부를 재검사한다. 동일 공격턴 피해의 동시 적용 범위는 기존 공식과 대조해 테스트로 고정한다.

## 8. 스킬·범위·표현

범위는 기존 스킬/보급/건축별 타일 집합을 재사용한다. 헥사 반경과 기존 3×3/2×2 정의를 임의의 원으로 일괄 치환하지 않는다. 타일 폴리곤과 부대 판정 원이 교차하면 범위 안으로 판단하고, 여러 타일과 교차해도 같은 시전자·사건에서 부대 ID당 1회만 적용한다. 영역 중심은 발동 틱의 소속 타일에 고정한다.

사거리는 연속 거리로 검사한다. '1칸 사거리'는 인접 헥사 중심 간 거리 1,000을 기본 척도로 환산하고 부대/성 외곽 반경을 포함하는 공통 함수로 만든다. 전투 유효 거리와 화면 원이 일치해야 하며 정확한 경계는 포함한다.

선봉/부관 액티브 교대, 집단군 등 기존 예외, 방어 우선 처리, 스킬원 초기화, 시전자 초상은 유지한다. 실제 교전 참여 부대는 공격·피격·반격만 한 경우를 합쳐 공격턴당 게이지 1칸과 성장 판정 1회를 받는다. 먼저 게이지를 충전한 뒤 그 공격턴의 방어 우선→예약된 선봉/부관 액티브 순으로 발동하므로 다섯 번째 참여일에 발동할 수 있다. 협공 대상이 되어 여러 공격을 받아도 충전·경험치는 한 번이다. 행군 중 피격도 참여로 기록하지만 공격·반격형 액티브는 발동하지 않는다. 지속 상태는 공격턴 시작에 기존 상태를 1회 적용·감소시키고, 같은 날 새로 받은 상태는 다음 날부터 적용한다.

교란 강제 후퇴는 일반 이동과 다른 공격턴의 특수 변위다. 대상 반대 방향으로 4칸부터 3·2·1칸 순서로 유효 종점을 찾는다. 이동 구간의 아군·적군 부대는 무시하고 통과하지만 통행 불가 지형과 모든 건물은 관통하지 않는다. 종점은 적 부대·건물과 겹칠 수 없고 아군 중첩은 허용한다. 유효 종점이 없으면 밀려나지 않는다. 혼란 중 이동·공격 금지, 화계 등 지속 효과 만료도 게임 시계로 처리한다.

화면은 현재/이전 Core 스냅샷을 보간한다. 걷기 애니메이션은 실제 이동 거리로, 공격 모션은 고유 공격 사건 ID로 실행한다. 마지막 일격·부관 효과·해골 효과도 1회씩 처리한다. 대상 제거 후에도 독립 이펙트는 수명을 끝까지 재생한다. 이펙트 종료를 기다리느라 시뮬레이션 공격을 멈추지 않는다.

## 9. 겹친 부대 선택 UI

한 부대만 클릭 범위에 있으면 기존 팔레트를 연다. 아군이 둘 이상이면 작은 목록 팔레트에 선봉 얼굴·이름·병종·병력·현재 명령을 표시하고, 한 행을 선택하면 해당 부대의 명령 팔레트로 이동한다. 부대 ID 기반으로 선택을 유지하며 전체 재정렬 때문에 행이 바뀌지 않게 한다.

많은 부대는 목록 내부 스크롤/페이지로 처리하고 전체 화면을 밀지 않는다. 마우스 오버/선택 부대에는 윤곽과 경로를 강조한다. 지도 줌과 목록 스크롤을 분리하고 닫기·ESC·우클릭은 기존 UI 규칙을 따른다. 사망/입성 부대는 목록에서 즉시 제거하고 선택 대상을 재검사한다. 적이 밀집한 곳의 공격 대상 선택도 별도 후보 목록으로 명확히 한다.

처음에는 신규 시뮬레이션 진입점을 별도로 두고 기존 자원·피해·장수 규칙을 공유한다. 기존 타일 이동 결과를 화면에서만 자유이동처럼 꾸미지 않는다. Core가 연속 좌표로 이동을 계산하고 이동턴/공격턴별 사건과 후처리 상태를 제공한다. Game은 해당 단계 상태를 재생하며 7일 최종 상태로 중간 이동·사망·점령을 덮어쓰지 않는다.

세이브에 모드/버전·연속 좌표·날짜/현재 단계/이동 틱·목표 ID·경유지·행동 완료 ID·스킬 충전·예약·주둔·난수 상태를 저장한다. 기존 저장을 조용히 덮어쓰지 않는다. 구버전 타일 중심 변환과 아군/적 중첩 해소가 검증되기 전에는 신규 모드 전용 저장을 사용한다. 적 겹침 변환 실패는 명시적 호환 불가로 보고한다.

공간 인덱스로 주변 후보만 조회하고 경로 재계산은 명령 변경·장애물 변화·추격 대상 이동에 제한한다. 결정론 순서를 유지한다. 50/100/300부대 및 아군 30부대 중첩 장면에서 틱 처리 시간·최대 지연·경로 재계산 횟수·메모리를 측정한다. 목표 PC의 1틱 예산 초과 시 전환하지 않는다.

## 11. 구현 단계와 검증 절차

12단계 체크표는 로드맵에서 관리한다. 각 단계의 커밋에 구현과 해당 QA 결과를 함께 남기고 개별 푸시한다. 전체 코드를 한 번에 교체하지 않는다.

1. **계약(완료):** 시간·사거리·충돌·공격 모드·특수 시설 예외·현행 효과 시간 단위를 목록화하고 D01~D07을 확정한다.
2. **검수장:** `run-renewal-movement.bat`와 독립 씬 생성. 같은 맵 데이터/부대 에셋 사용. 시드·속도·일시정지·초기화·한 이동 틱/한 단계/하루 실행·현재 이동턴/공격턴·로그 표시. 육상 1부대 이동부터 화면 확인 가능하게 한다.
3. **이동:** 연속 경로, 지형 교차, 같은 세력 중첩, 적/건물 쓸기 충돌. 각자 교차 이동과 고속 관통 검사.
4. **거점:** 성 3규모와 항구 출입, 예약/지연, 수송·보급·생산·집단군·출항 공통 적용.
5. **모드:** 원래 목적지/추격/고정 공격 대상 상태, 시야 상실·목표 사망·명령 변경 검사.
6. **전투:** 공격턴 시작 위치로 교전 묶음 구성, 사거리 통과 후 무피해/사거리 잔류 시 행군 피격 검증, 기존 피해 비교, 반격 중복 방지, 3/5/7 공성 참여권, 단계 직후 점령/괴멸 처리.
7. **스킬:** 시간 환산·광역·상태·경험치, 선봉/부관 교대, 효과가 시계를 막지 않는지 검사.
8. **연동:** 내정·연구·보급·함선·건축·생산·정찰의 날짜 경계 적용. 일시정지 중 정산 금지.
9. **UI:** 겹친 부대 선택, 재명령, 경로·범위·대기 이유, 작은 화면과 다수 목록 검증.
10. **운영:** AI 동일 규칙, 저장 복원 결정론, 대규모 부하 검증.
11. **통합:** 아래 회귀 표를 신규 BAT에서 재현. 자동 QA 결과와 사용자 육안 검수를 나누어 기록.
12. **전환:** 사용자 검수 및 전환 승인 후 캠페인 연결. design-movement/combat/skill/unit-state/UI와 CLAUDE의 '좌표 변환 Game 전용' 설명을 엔진 독립 시뮬레이션 좌표와 화면 변환의 구분에 맞게 갱신. 구버전 재현 수단을 남긴다.

## 13. 규모와 주요 위험

단순 이동 수정이 아니라 Core 위치 모델·단계별 교전·Game 표시·저장을 가로지르는 큰 변경이다. 이동턴/공격턴 유지와 공격턴 시작 위치 판정으로 독립 실시간 공격 시계·소급 피해 정산·경제 시간 환산의 범위를 줄인다. 난도가 높은 부분은 적끼리의 연속 충돌, 단계별 입성/괴멸의 정합성, 다대일 반격, 여러 타일 성 입출입이다. 일정은 1~3단계에서 실제 코드 영향과 성능을 측정한 후 산정한다. 문서 작성 시점에 짧은 고정 완료 시간을 약속하지 않는다.

아군 중첩을 허용해도 적 봉쇄와 지형 병목은 남는다. 이때는 정상적인 대기 이유를 알려야 하며 위치 순간 보정으로 해결하지 않는다. 원거리 중첩 집중 화력·공성 대기열 고착·클릭 혼잡은 별도 밸런스/UX 검수 대상이다. 신규 검수장에서 위 QA를 통과하고 사용자가 실제 이동감을 확인하기 전까지 캠페인 전환 완료로 표시하지 않는다.

## 15. 단계별 구현 인계 지침

### 검토 결과와 문서 우선순위

2026-10-04 인계 점검: 요구사항과 회귀 사례는 충분하지만, 종전 문서는 선행 결정·단계별 산출물·검증 명령·이어받기 기록이 부족했다. 이 절은 그 실행 기준을 보완한다. 특정 모델의 성공률을 측정한 결과가 아니며, 5.6 sol로 구현을 실제 수행한 QA도 아니다.

읽는 순서: `AGENTS.md` → `doc/ai-working-notes.md`/`CLAUDE.md` → 로드맵 Phase 18D → 이 문서 → 현재 단계 관련 소스와 테스트. 저장소 전체 MD를 매 단계 재독하지 않는다. 기존 `design-movement.md`의 타일 점유/모드 설명은 현행 모드의 이력이며 신규 규칙을 덮어쓰지 않는다.

최신 사용자 지시가 최우선이고, 신규 모드 규칙은 이 문서의 확정 문구, 진행 상태는 로드맵을 원본으로 한다. 의견·추천을 사용자 확정으로 승격하지 않는다. 새로운 설계 선택은 결정 이유와 영향을 기록한다.

### 선행 결정 관리

D01~D07은 §14에서 모두 확정되었다. 후속 단계는 해당 결정을 재질문하지 않고 경계 테스트로 검증한다. 실제 검수 결과가 플레이성·성능 문제를 보이면 관련 결정 ID, 실패 시나리오, 수치 변경 이유를 함께 기록한다. 새로운 미정 사항은 D08부터 추가한다.

### 최소 데이터·상태 계약

제안 설계이며 아직 다음 이름의 타입이 구현되었다고 가정하지 않는다.

- 부대 상태: ID·소유 세력·이동 영역·연속 위치·판정 반경·모드·목적지/경유지·지정 대상·추격 대상·예약/야전/주둔 상태를 구분한다. 한 부대가 예약과 야전에 동시에 있지 않는다.
- 진행 상태: 진행 회차·게임 날짜·단계(`이동`, `이동 후처리`, `공격`, `공격 후처리`, `하루 종료`)·이동 틱·단계 실행 완료 ID를 가진다. 같은 후처리 재호출은 중복 자원·경험치·입성을 만들지 않는다.
- 계산 결과: 새 상태와 순서가 고정된 사건 목록. 사건에 출격/이동/입성/공격/괴멸/점령의 ID·발생 단계·대상·위치를 포함한다. Game 노드가 결과를 다시 계산하지 않는다.
- 위치는 렌더링과 무관한 Core 좌표가 원본이다. 기존 정수 `HexCoord`로 반올림한 위치를 다음 이동의 원본으로 돌려 쓰지 않는다. 화면 좌표 변환만 Game에 둔다.
- 판정 예제: 이동 시간 예산이 같다면 화면 30/60/144FPS에서도 같은 위치·사건이 나와야 한다. 사거리 `R`에 대해 `R-1`, `R`, `R+1` 고정소수점 단위를 검사하며 경계 `R`은 사거리 안이다.

### 실제 검증 명령과 성공 판단

작업 디렉토리는 저장소 루트다. 현재 테스트 프로젝트는 `net9.0`이므로 `dotnet --list-sdks`로 확인한다. Godot 경로는 작업 노트와 실제 BAT가 다를 수 있어 실행 파일의 존재와 mono 지원을 확인한 뒤 사용한다.

```powershell
dotnet --list-sdks
dotnet build
dotnet test SanguoSLG.Core.Tests/SanguoSLG.Core.Tests.csproj
dotnet build SanguoSLG.Game/SanguoSLG.Game.csproj
git diff --check
```

명령별 종료 코드와 통과/실패 건수를 기록한다. Game을 수정하면 Game 별도 빌드가 필요하다. 씬·리소스를 수정하면 확인한 Godot mono 실행 파일로 `--headless --path SanguoSLG.Game --build-solutions --quit`도 실행한다. `--quit` 종료 코드만 보고 씬 동작 QA라고 주장하지 않는다.

관련 테스트 시작점은 `MovementSimulatorTests`, `ControlledDeploymentIntegrationTests`, `FieldUnitCommandServiceTests`, `AdvanceOrchestratorTests`, `CombatPhaseResolverTests`, `CastleEntryPlaybackTests`다. 신규 모드 검증을 추가하고 기존 모드 테스트를 삭제하거나 기대값을 신규 규칙에 맞춰 일괄 변경하지 않는다. 광범위 변경은 전체 테스트를 실행한다.

문서만 수정할 때는 위 빌드 대신 로컬 링크·요구사항·12단계 번호·모순·변경 형식을 검사한다. 실행하지 않은 명령을 통과한 것으로 적지 않는다.

신규 검수장의 자동 실행 옵션과 결과 형식은 2단계에서 실제로 구현하고 여기 기록한다. 현재 존재하지 않는 테스트 옵션을 사용했다고 보고하지 않는다. 자동 검증은 시나리오별 성공/실패와 상태/사건 차이를 출력하고 실패 시 비정상 종료 코드를 반환해야 한다. 수동 검수는 구현 후 `run-renewal-movement.bat` 실행 방법과 조작 순서를 사용자에게 안내한다. 사용자 요청 없이 게임 창을 띄우거나 스크린샷을 생성하지 않는다.

### 그림자 깜빡임 재조사 (2026-10-05)

사용자가 광원/보행 수정 후에도 육상·해상 부대의 그림자 깜빡임을 보고했다. 위 기록의 `shadow_stable=True`와 `march_pose=True`는 설정/조건 검사였으며 화면의 안정성을 증명하지 않는다. 원인을 확정하거나 시각 검수를 완료한 것으로 해석하지 않는다.

- 공통 `MapView3D.TuneImportedMeshes`의 그림자 크기 판정에 부모 변환을 누적한다. 이전에는 편대 축소 배율이 빠져 작은 부품이 그림자를 계속 만들 수 있었다.
- `UnitController3D`의 이동 먼지와 해상 물보라는 그림자를 만들지 않도록 한다.
- 독립 검수장에 `그림자 비교: 켜기/끄기` 선택기를 추가한다. 끈 상태에도 깜빡이면 메시/재질 경로를 추가 조사한다.
- QA: Game 빌드 경고/오류 0, headless 4개 시나리오 통과. 축소·회전 부모 아래의 작은 부품은 그림자 제외, 큰 부품은 유지하는 `scaled_casters=True` 확인. GPU 화면의 깜빡임 해소 여부는 미확인이다.
- 실제 확인: `run-renewal-movement.bat`의 자동 재생 중 그림자 켜기/끄기를 비교하고, 카메라 고정/이동 및 일시정지 상태를 함께 구분한다.

### 궁병 팔 기본 자세 보존 (2026-10-05)

- 그림자를 끈 상태에서도 궁병 팔이 깜빡인다는 사용자 보고에 따라 실제 GLB와 보행 코드를 확인했다. GLB 왼팔은 약 -38도인데 보행/정지 코드가 이를 0도 기준으로 덮어쓰는 오류가 있었다.
- `UnitController3D`에서 왼팔 원본 회전을 저장하고 보행 회전을 가산한다. 정지 및 자세 초기화도 원본 회전으로 복원한다. GLB 자체는 변경하지 않았다.
