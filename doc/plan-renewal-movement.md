# 연속 이동·초 단위 교전 개편 계획

작성일: 2026-10-04. 소속: [v2 로드맵 Phase 18D](./plan-v2-implementation-roadmap.md).
상태: **문서 계획만 작성. 코드·데이터·씬·BAT는 아직 변경하지 않음.**

후속 합의 반영: 공격 간격과 반격을 분리하고 같은 시각 교전을 한 묶음으로 계산한다. 아군 도착 시 근거리 분산을 허용하며, 모든 건물·건축물은 소유 세력과 관계없이 통과할 수 없다. 확정된 구조와 아직 검증해야 할 시간·밸런스 수치는 아래에서 구분한다.

## 1. 목적과 적용 순서

타일을 선점해야 이동하는 구조와 이동/공격 단계 분리를 제거하고, 연속 위치에서 이동·탐지·교전을 일정 시간 간격으로 판단한다. 타일은 지형·시야·효과 범위를 정의하는 지도 단위로 계속 사용한다. 기존 피해·부상·반격 공식을 보존하면서 이동과 교전 시점의 결정 방식을 바꾼다.

기존 출격에서 관찰한 문제는 방향과 실제 출구 불일치, 아군 점유로 인한 우회·장기 대기, 중형성 내부 출현, 목표 지정 두 번 필요, 순간이동·깜빡임, 도착 후 무행동이다. 겹침 허용은 아군 길막을 줄이지만 목표 상태와 화면 재생 오류까지 자동으로 해결하지 않는다. 좌표·명령·시계·사건 전달도 함께 정리한다.

현행 [이동 설계](./design-movement.md), [전투 설계](./design-combat.md), [스킬 설계](./design-skill.md), [야전 건축 계획](./plan-v2-implementation-roadmap.md), [저장 설계](./design-save-data.md)를 비교 기준으로 삼는다. 이 문서는 신규 모드의 구현 목표이며 기존 모드가 이미 전환되었다는 의미가 아니다. 사용자 확정 15개 규칙이 충돌하는 현행 규칙보다 신규 모드에서 우선한다.

## 2. 사용자 확정 요구사항

| 번호 | 확정 규칙 | 구현 계약 |
|---:|---|---|
| 1 | 목적지를 클릭하여 이동 | 클릭 지점을 연속 목표로 보존. 경유지는 순서대로 소비 |
| 2 | 목적지 방향을 바라보고 출성 | 거점 외곽의 목적지 방향 경계에서 출격. 반대편 임의 출현 금지 |
| 3 | 칸에 걸쳐도 이동 제약 적용 | 부대 판정 원과 지형 타일의 교차로 효과 판정. 이동 구간도 검사 |
| 4 | 아군 중첩 허용, 적군 중첩 불가 | 같은 세력은 서로 통행 장애물이 아님. 도착 시 근거리 분산, 공간 부족 시 중첩 허용 |
| 5 | 모든 건물·건축물 통과 금지, 입장만 허용 | 아군·적군·중립 모두 장애물. 건물 외곽 충돌과 허용된 명시적 입성 전환 분리 |
| 6 | 액티브는 기존 칸 기준 주변 적 모두 적용 | 기존 효과별 타일 집합과 교차하는 적을 ID별 1회 적용 |
| 7 | 이동·공격을 초 단위로 판정 | 고정 시뮬레이션 틱에서 이동·공격 가능 여부를 함께 검사 |
| 8 | 겹친 아군은 목록부터 선택 | 아군 목록 팔레트 → 부대 선택 → 기존 명령 팔레트 |
| 9 | 소형 3·중형 5·대형 7부대 공성 | 성 전체 공유 공격 참여권. 나머지는 주변 대기 |
| 10 | 행군은 공격하지 않고 이동 | 자동 공격·추격 금지. 적을 관통할 권한은 없음 |
| 11 | 전진은 발견한 적을 추격·공격 | 부대·건축물·성·항구 대상으로 탐지, 시야를 잃으면 원래 목적지 재개 |
| 12 | 공격은 지정 대상만 공격 | 타 대상에게 받는 피해는 행군 판정. 주변 대상으로 임의 전환 금지 |
| 13 | 보급·효과 범위는 기존 타일 기준 | 같은 범위 제공자로 판정과 UI 미리보기 연결 |
| 14 | 병종별 이동속도 | 집단군 최저, 기병 최고. 세부 값은 데이터에서 조정 |
| 15 | 주 피해 대상 1개·반격 N개 유지 | 능동 공격 주기와 반격 분리, 같은 시각 교전 묶음에서 중복 없이 기존 공식 적용 |

같은 세력 중첩 자체에 추가 피해 패널티는 도입하지 않는다. 일반 공격은 선택한 대상에게만, 광역 스킬은 범위 내 적 모두에게 적용한다. 과거에 논의했던 '겹치면 일반 공격 피해 복제'는 이번 확정 목록에 없으므로 적용하지 않는다.

## 3. 시간·밸런스 추천안과 확정 구조의 구분

|---|---|---|

군량·부상 회복·경험치·진법 확률·화계 피해는 판정 틱 수만큼 반복 적용하면 안 된다. 기존 적용 단위별로 다음 실행 시각을 저장한다. 진법은 이동턴이 없어지므로 우선 게임 일당 1회, 범위 내 대상마다 기존 확률을 적용하는 안으로 검증한다. 병종 숙련도는 유효 교전 묶음당 1, 같은 묶음의 협공 수로 증가하지 않는 계약을 유지한다.

## 4. 연속 위치와 지형

- Core에 엔진과 무관한 평면 좌표·거리·판정 원을 추가한다. 고정소수점 정수 좌표/정수 틱을 권장한다. 화면 픽셀이나 Godot `Vector3`를 Core에 넣지 않는다.
- 평면 좌표가 실제 위치의 원본이며 `HexCoord`는 지형·범위 조회용 파생 정보다. Game이 표시 좌표를 Core로 역전송해 이동 결과를 덮어쓰지 않는다.
- 헥사 A*는 큰 경로 후보를 만드는 데 재사용할 수 있다. 실제 이동은 칸 중심으로 순간 이동하지 않고 충돌 여유를 둔 연속 경로를 따른다. 모서리 단축 경로는 통과 가능성을 재검사한다.
- 통행 불가 지형·적 부대·건물은 시작점→끝점 전체를 쓸어 검사한다. 큰 프레임 지연, 빠른 기병, 서로 마주 오는 적도 관통하지 않아야 한다.
- 이동 제한 지형과 판정 원이 조금이라도 겹치면 적용한다. 여러 지형 감속이 겹치면 가장 강한 감속 하나를 우선하는 추천안으로 시작한다. 같은 지형 효과가 경계에서 중복 가산되지 않는다.
- 일반 육상 부대는 해상 진입 불가, 선박은 육상 진입 불가. 항구의 입출항 경계만 전환점이다. 안개는 통행 금지가 아니며 보이지 않는 적의 위치를 길찾기 미리보기로 노출하지 않는다.
- 아군은 경로 장애물에서 제외한다. 적을 만났을 때 모드에 따라 교전·우회·대기하며 실패 이유를 남긴다. 위치 강제 보정으로 반대 방향에 재생성하지 않는다.
- 성·항구・목책·정찰대·감시탑·보루·진법·유적·논·밭·마을 등 모든 건물/건축물은 소유 세력과 무관하게 통과 금지다. 건물의 게임 판정 외곽을 장애물로 쓰며, 장식용 구름·연기·처마는 충돌 면적을 늘리지 않는다.
- 정찰대도 통과 금지다. 기존 '적이 타일을 지나가면 소멸'은 신규 모드에 그대로 사용할 수 없다. **적 판정 원이 정찰대 외곽에 접촉하면 철수·소멸**하도록 대체하는 안을 §14에 남긴다. 소멸 확정 전에는 부대를 건물 안으로 이동시키지 않는다.

### 도착 시 아군 분산 배치 — 확정

- 같은 목적지로 이동하는 아군은 이동 중 중첩할 수 있다. 도착할 때 가까운 유효 위치로 조금씩 분산한다. 빈자리 확보를 출격/이동의 필수 조건으로 만들지 않는다.
- 원래 목적지는 유지하고 분산 위치만 별도로 저장한다. 결정론적인 후보 순서로 한 번 선택하며, 매 틱 서로 밀어내거나 자리 교환을 반복하지 않는다.
- 분산 위치까지 실제로 이동한다. 순간이동·모델만 옮기는 표현 보정으로 처리하지 않는다. 경로와 판정 위치가 일치해야 한다.
- 분산은 적·건물·통행 불가 지형을 침범하지 않는다. 근처에 적절한 공간이 없으면 원래 목적지에서 아군 중첩을 허용한다.
- 입성·생산 진입·공격 사거리 도달·공성 대기는 각각의 목표 조건을 우선한다. 분산 때문에 사거리/보급권 밖으로 나가거나 원치 않는 다른 시설에 들어가지 않는다.
- 최대 분산 거리는 1단계 검수용 수치로 정한다. 추천 상한은 원래 목적지에서 0.5칸거리이며 불가능하면 중첩한다.

## 5. 출성·입성

1. 편성은 거점 내부 예약 상태를 가진다. 출전 지연 0~6일은 게임 시계의 출격 가능 시각으로 환산한다.
2. 목적지(경유지가 있으면 첫 경유지) 방향과 성 전체 외곽의 교점을 출발 경계로 선택한다. 모델 중심이나 중형성 중심 타일에 야전 부대를 먼저 생성하지 않는다.
3. 항구는 선택 병종의 육지/해상으로 연결되는 유효 외곽만 쓴다. 그 방향에 유효 출구가 없으면 미리보기에서 알리고 예약 대기한다. 무단 반대편 출구 변경은 금지한다.
4. 같은 세력 부대는 출구를 막지 않는다. 같은 방향 동시 출격을 허용한다. 적·통행 불가 지형·건물이 막으면 예약에 남기고 이유를 표시한다.
5. Game은 Core가 보낸 출격 시각과 경계 위치부터 보간한다. 야전 위치, 표시 시작점, 최종 목표를 서로 바꾸지 않는다.
6. 복귀 대상은 도시/항구 ID로 보존한다. 해당 외곽 입구에 닿은 틱에 입성·자원 합산·장수 배치·필드 제거를 원자적으로 처리한다. 가는 길의 다른 아군 성에 잘못 들어가지 않는다.
7. 보루/진법 입장도 ID·아군 여부·수용 1부대 조건으로 별도 처리한다. 파괴되면 주둔 부대를 유효 외곽 위치로 한 번만 복원하고 같은 전투 흐름에 연결한다.
8. 성/항구 점령 조건 충족 시 즉시 소유권·주둔·노획·장수·입성 처리를 완료한다. 집단군 입성 시 원래 병종으로 분해하며 임시 army_group 병종을 주둔 병력에 남기지 않는다.
9. 논·밭·마을 생산 작전은 해당 시설 외곽에 도착한 뒤 명시적 생산 진입으로 전환한다. 일반 이동은 시설을 관통하지 않는다. 입장 가능한 건물도 목적지로 지정하지 않았다면 통과용 지름길로 사용하지 않는다.

## 6. 모드와 목표 상태

명령에는 명령 ID, 부대 ID, 모드, 원래 목적지/경유지, 지정 대상 ID, 현재 추격 대상 ID를 구분해 저장한다. 이동하는 적은 좌표가 아닌 ID로 추적한다. 명령 확인 1회로 원자 적용하며 UI가 두 번째 부대 명령을 첫 번째 예약에 덮어쓰지 않게 한다.

| 모드 | 이동·탐지 | 교전 | 목표 상실 |
|---|---|---|---|
| 행군 | 목적지로 이동, 적 충돌 시 통행 가능한 우회 또는 대기 | 능동 공격·반격 없음, 현행 행군 피해 판정 | 도착 시 정지. 도착 후 자동 모드 변경은 별도 확정 |
| 전진 | 발견한 적 부대·건물·성·항구를 추격 | 사거리 도달 시 공격, 기존 반격 허용 | 추격 대상이 시야를 잃거나 제거되면 원래 목적지/남은 경유지 재개 |
| 공격 | 지정 대상만 추적, 다른 적은 통행 장애물로만 취급 | 지정 대상과 정상 교전, 비지정 대상에게는 행군 피해·반격 금지 | 추천: 시야 상실 시 마지막 확인 위치까지만 이동 후 대기, 제거 시 정지 |

현재 `FieldUnitCommandService`의 적 점유 좌표 자동 Attack 전환은 신규 UI에서 명시적 공격 명령에만 사용한다. 사용자가 고른 행군 모드를 Core가 몰래 바꾸지 않도록 명령의 의도를 보존한다. 이번 모드 의미는 오래된 이동 문서의 '공격이 주변 적 추격' 규칙보다 우선한다.

대상 선택 동률은 거리 → 명령 순번 → 부대 ID로 고정한다. 정찰대는 적 건물 자동 탐지/공격 대상에서 제외한다. 목표가 함락되어 아군이 된 경우 입성 가능 여부를 재검사하며 적대 공격을 지속하지 않는다.

## 7. 교전과 공성 참여권

매 틱 조건을 검사하되 공격 쿨다운이 끝난 경우에만 타격한다. 같은 공격을 AnimationPlayer 콜백이나 매 프레임에서 다시 계산하지 않는다.

### 공격·반격 합의 — 확정

능동 공격은 부대의 공격 간격에 따라 먼저 공격하는 행동이고, 반격은 실제 공격받은 교전에 대한 대응이다. 능동 공격 횟수를 소진했다는 이유만으로 반격을 막지 않는다. 반격은 별도의 정기 자동 공격이 아니며 공격받지 않았을 때 반복 실행하지 않는다.

| 상황 | 처리 계약 |
|---|---|
| A만 공격 준비 완료, B는 아직 대기 | A 공격 + 조건을 만족하는 B 반격. B가 반격했다는 이유만으로 대기 중인 능동 공격을 소진하지 않음 |
| A와 B가 같은 틱에 서로 공격 준비 완료 | 하나의 교환으로 A→B와 B→A 계산. 각 방향에 능동 공격과 반격을 추가로 두 번 더하지 않음. 두 부대의 능동 공격 주기를 소비 |
| B·C·D가 같은 틱에 A를 공격 | 같은 교전 묶음에서 A의 주대상/추가 반격 대상 N개를 기존 공식으로 계산. 독립 1:1 세 개로 반격 정타를 반복하지 않음 |
| A가 행군 중 | 반격 없음. 기존 행군 피해 판정 |
| A가 B를 지정 공격 중인데 C가 공격 | B와 정상 교전, C에게는 행군 피해 판정·반격 금지 |
| 반격 피해가 발생 | 반격을 원인으로 다시 반격하는 사건을 생성하지 않음 |

권장 구현 절차:

1. 같은 틱 시작 상태에서 실제 공격 가능한 부대의 능동 공격 의도를 수집한다. 사거리·생존·모드·공성 참여권·상태이상을 검사한다.
2. 실제 공격 관계로 연결된 교전 묶음을 만든다. 같은 틱이라도 서로 관계없는 전투를 하나로 합치지 않는다. 연결되어 있다는 이유로 사거리 밖 대상에게 피해를 주지 않는다.
3. 방어 스킬을 우선 반영하고 각 부대의 주대상과 유효 반격 대상을 기존 순서/수식으로 결정한다. 모드·반격 사거리·공격 불가 부대 등 기존 예외는 유지한다.
4. `(교전 사건 ID, 피해를 주는 부대 ID, 받는 대상 ID)`별 기본 교환을 한 번만 산출한다. 액티브의 명시적인 연타·광역·지속 피해 사건은 별도 하위 사건으로 보존한다.
5. 같은 교환의 피해를 동일 기준 스냅샷으로 계산한 뒤 적용한다. 실제 능동 공격을 실행한 부대만 다음 능동 공격 시각을 갱신한다. 피해 반영 후 괴멸·점령·전리품을 처리한다.

**남은 경계:** 공격 시점이 0.1초씩 어긋난 두 부대는 서로 다른 교전이므로 반격이 추가 발생할 수 있다. 같은 틱 중복 제거만으로 모든 위상 차이가 해소되지는 않는다. 이 경우를 포함한 공격 주기·반격 타이밍 검증을 1단계 계약 항목으로 남긴다(§14). 반격 상한이나 추가 쿨다운을 임의로 도입하지 않는다.

### 공성 참여권과 후처리

- 기존 공방·훈련·병종 상성·장수·패시브·성벽 붕괴·건물 방어·부상/사망·전리품 공식을 재사용한다.
- 주대상 1개와 반격 N개는 기존 교전 묶음으로 계산한다. 같은 틱의 다대일을 독립 1:1 루프로 풀어 반격을 중복 가산하지 않는다. 기존 주대상 100%/추가 대상 60%와 성의 예외는 기존 공식 기준이다.
- 공격 모드의 비지정 대상 및 행군의 반격 금지가 우선한다. 반격이 새 반격을 끝없이 생성하지 않는다.
- 공성 참여권은 성 ID별 소형 3·중형 5·대형 7개, 공격 측 모든 세력·근접·원거리 합산이다. 성의 타일별로 따로 상한을 두지 않는다. 집단군도 1부대로 센다.
- 유효 사거리에 도착하고 공격 가능한 부대부터 참여한다. 동률은 도착 틱 → 명령 순번 → 부대 ID. 원거리 부대도 성의 실제 외곽에서 거리를 계산한다.
- 빈자리를 기다리는 부대는 주변 유효 지점에 정지하고 `공성 대기 3/3` 등 이유를 표시한다. 대기열에 있다고 성의 사거리나 적 광역 피해로부터 면역이 되지는 않는다.
- 참여 부대의 사망·후퇴·명령 변경·사거리 이탈·성 점령 시 즉시 참여권을 해제하고 다음 유효 후보를 선택한다. 새 참여자의 공격 쿨다운을 초기화해 즉시 반복 공격하는 악용은 막는다.
- 원거리 피해·액티브로 성을 공격하는 경우에도 공성 상한 우회 여부를 검사한다. 추천: 성 피해는 참여권 보유자만 허용, 주변 야전 부대 광역 피해는 정상 처리.

권장 한 틱 순서: 명령/출격 가능 처리 → 이동·연속 충돌 → 입성·영역 진입 효과 → 괴멸 정리 → 시야/타겟/참여권 → 같은 시각 교전 묶음·방어 스킬 우선 → 공격/계략 및 피해 적용 → 괴멸·점령·노획·주둔 해제 → 날짜 경계 정산 → 사건/스냅샷 발행. 후속 대상은 생존 여부를 재검사한다. 동일 시각 피해의 동시 적용 범위는 기존 공식과 대조해 테스트로 고정한다.

## 8. 스킬·범위·표현

범위는 기존 스킬/보급/건축별 타일 집합을 재사용한다. 헥사 반경과 기존 3×3/2×2 정의를 임의의 원으로 일괄 치환하지 않는다. 타일 폴리곤과 부대 판정 원이 교차하면 범위 안으로 판단하고, 여러 타일과 교차해도 같은 시전자·사건에서 부대 ID당 1회만 적용한다. 영역 중심은 발동 틱의 소속 타일에 고정한다.

사거리는 연속 거리로 검사한다. '1칸 사거리'는 인접 헥사 중심 간 거리를 기본 척도로 환산하고 부대/성 외곽 반경을 포함하는 공통 함수로 만든다. 전투 유효 거리와 화면 원이 일치해야 한다. 정확한 경계 포함 기준은 1단계에서 수치 예제로 고정한다.

선봉/부관 액티브 교대, 집단군 등 기존 예외, 방어 우선 처리, 스킬원 초기화, 시전자 초상은 유지한다. 교란 강제 후퇴는 기존 허용 거리와 중간 부대 무시 예외를 명시적으로 이식하되 최종 적/건물 중첩은 금지한다. 혼란 중 이동·공격 금지, 화계 등 지속 효과 만료도 게임 시계로 처리한다.

화면은 현재/이전 Core 스냅샷을 보간한다. 걷기 애니메이션은 실제 이동 거리로, 공격 모션은 고유 공격 사건 ID로 실행한다. 마지막 일격·부관 효과·해골 효과도 1회씩 처리한다. 대상 제거 후에도 독립 이펙트는 수명을 끝까지 재생한다. 이펙트 종료를 기다리느라 시뮬레이션 공격을 멈추지 않는다.

## 9. 겹친 부대 선택 UI

한 부대만 클릭 범위에 있으면 기존 팔레트를 연다. 아군이 둘 이상이면 작은 목록 팔레트에 선봉 얼굴·이름·병종·병력·현재 명령을 표시하고, 한 행을 선택하면 해당 부대의 명령 팔레트로 이동한다. 부대 ID 기반으로 선택을 유지하며 전체 재정렬 때문에 행이 바뀌지 않게 한다.

많은 부대는 목록 내부 스크롤/페이지로 처리하고 전체 화면을 밀지 않는다. 마우스 오버/선택 부대에는 윤곽과 경로를 강조한다. 지도 줌과 목록 스크롤을 분리하고 닫기·ESC·우클릭은 기존 UI 규칙을 따른다. 사망/입성 부대는 목록에서 즉시 제거하고 선택 대상을 재검사한다. 적이 밀집한 곳의 공격 대상 선택도 별도 후보 목록으로 명확히 한다.

## 10. 영향 코드와 전환 방법

| 현행 영역 | 개편 범위 |
|---|---|
| `FieldUnit`, `MovementSimulator`, `MovementTick`, `HexPathfinder` | 연속 위치·경로·이벤트 제공자 추가. 타일 점유/스텝 결과가 위치 원본이 되는 구조 대체 |
| `DeploymentEgressController`, `DeploymentEgressRules` | 예약/지연 유지, 아군 FIFO 점유 제한 제거, 거점 외곽 연속 출격 |
| `FieldUnitCommandService` | 위치 목표와 대상 ID, 원래 목적지/추격 분리, 모드 강제 변경 정리 |
| `AdvanceOrchestrator`, `CombatPhaseResolver`, `UnitCombatState` | 고정 틱 일정 관리, 교전 묶음·피해 공식 어댑터, 충전/효과 중복 방지 |
| `FieldBuildingCombat`, `RuinCombat`, 입성·생산·보급 서비스 | 연속 범위/진입 사건, 파괴 즉시 반영, 주둔·진법·정찰대 처리 |
| `CampaignMapScene`, `MovementPlayback`, 부대 표시 | 새 검수장부터 스냅샷 보간, 실제 공격 사건 모션, 중첩 선택·경로 표시 |
| 저장/AI/테스트 | 위치·명령·쿨다운·참여권·RNG 저장, 동일 Core 호출, 회귀 케이스 이식 |

처음에는 신규 시뮬레이션 진입점을 별도로 두고 기존 자원·피해·장수 규칙을 공유한다. 기존 7일 결과를 미리 전부 계산하고 새 화면만 자유이동처럼 재생하는 방식은 채택하지 않는다. 현재 시각의 상태에서 다음 틱을 계산하여 명령·입성·사망이 그 시점에 반영되어야 한다.

세이브에 모드/버전·연속 좌표·시간·목표 ID·경유지·다음 공격 시각·스킬 충전·예약·주둔·난수 상태를 저장한다. 기존 저장을 조용히 덮어쓰지 않는다. 구버전 타일 중심 변환과 아군/적 중첩 해소가 검증되기 전에는 신규 모드 전용 저장을 사용한다. 적 겹침 변환 실패는 명시적 호환 불가로 보고한다.

공간 인덱스로 주변 후보만 조회하고 경로 재계산은 명령 변경·장애물 변화·추격 대상 이동에 제한한다. 결정론 순서를 유지한다. 50/100/300부대 및 아군 30부대 중첩 장면에서 틱 처리 시간·최대 지연·경로 재계산 횟수·메모리를 측정한다. 목표 PC의 1틱 예산 초과 시 전환하지 않는다.

## 11. 구현 단계와 검증 절차

12단계 체크표는 로드맵에서 관리한다. 각 단계의 커밋에 구현과 해당 QA 결과를 함께 남기고 개별 푸시한다. 전체 코드를 한 번에 교체하지 않는다.

1. **계약:** 시간·사거리·충돌·공격 모드·특수 시설 예외·현행 효과 시간 단위를 목록화하고 추천안을 확정한다.
2. **검수장:** `run-renewal-movement.bat`와 독립 씬 생성. 같은 맵 데이터/부대 에셋 사용. 시드·속도·일시정지·초기화·한 틱 실행·로그 표시. 육상 1부대 이동부터 화면 확인 가능하게 한다.
3. **이동:** 연속 경로, 지형 교차, 같은 세력 중첩, 적/건물 쓸기 충돌. 각자 교차 이동과 고속 관통 검사.
4. **거점:** 성 3규모와 항구 출입, 예약/지연, 수송·보급·생산·집단군·출항 공통 적용.
5. **모드:** 원래 목적지/추격/고정 공격 대상 상태, 시야 상실·목표 사망·명령 변경 검사.
6. **전투:** 기존 피해 비교, 반격 중복 방지, 3/5/7 공성 참여권, 같은 틱 점령/괴멸 처리.
7. **스킬:** 시간 환산·광역·상태·경험치, 선봉/부관 교대, 효과가 시계를 막지 않는지 검사.
8. **연동:** 내정·연구·보급·함선·건축·생산·정찰의 날짜 경계 적용. 일시정지 중 정산 금지.
9. **UI:** 겹친 부대 선택, 재명령, 경로·범위·대기 이유, 작은 화면과 다수 목록 검증.
10. **운영:** AI 동일 규칙, 저장 복원 결정론, 대규모 부하 검증.
11. **통합:** 아래 회귀 표를 신규 BAT에서 재현. 자동 QA 결과와 사용자 육안 검수를 나누어 기록.
12. **전환:** 사용자 검수 및 전환 승인 후 캠페인 연결. design-movement/combat/skill/unit-state/UI와 CLAUDE의 '좌표 변환 Game 전용' 설명을 엔진 독립 시뮬레이션 좌표와 화면 변환의 구분에 맞게 갱신. 구버전 재현 수단을 남긴다.

## 13. 규모와 주요 위험

단순 이동 수정이 아니라 Core 위치 모델·시간 모델·교전 일정·Game 표시·저장을 가로지르는 큰 변경이다. 난도가 높은 부분은 적끼리의 연속 충돌, 날짜와 공격 주기의 정합성, 다대일 반격, 여러 타일 성 입출입이다. 일정은 1~3단계에서 실제 코드 영향과 성능을 측정한 후 산정한다. 문서 작성 시점에 짧은 고정 완료 시간을 약속하지 않는다.

아군 중첩을 허용해도 적 봉쇄와 지형 병목은 남는다. 이때는 정상적인 대기 이유를 알려야 하며 위치 순간 보정으로 해결하지 않는다. 원거리 중첩 집중 화력·공성 대기열 고착·클릭 혼잡은 별도 밸런스/UX 검수 대상이다. 신규 검수장에서 위 QA를 통과하고 사용자가 실제 이동감을 확인하기 전까지 캠페인 전환 완료로 표시하지 않는다.
