# 설계 노트 — 내정 스킬 (2026-08-13 작성 · 2026-08-16 액티브 폐지)

> 장수의 내정 특기. **전부 패시브다**(액티브는 2026-08-16 사용자 요청으로 폐지). 효과별로 태수·업무 담당자·출전 장수 중 실제 수행자가 다르다. 슬롯은 0~4개([spec-general.md](./spec-general.md)).
> 효과가 걸리는 곳은 [design-administration.md](./design-administration.md) "내정 심화 F(담당관)".

## 발동 규칙

2026-09-09 재확인: 코드의 `General.AdminPassives`, `AdminSkill` 및 `data/admin-skills.json`은 이미 패시브 전용이며 삭제할 내정 액티브 데이터는 없다. 장수 상세에는 **내정 패시브**로 표시한다. 전투 액티브와 명령(담당자 지정·연구 등)은 내정 액티브가 아니며 이 정리로 제거하지 않는다.

- 성의 기본 금·군량 수입에 적용하는 상재·둔전은 **정치 60 이상이며 실제 주둔 중인 태수**에게서 읽는다. 조건을 채우지 못하면 기본 수입은 ×0.3이다. 항구의 전용 주간 기본 수입에는 적용하지 않는다.
- 현재 자동 담당자 체계의 치안·모병·훈련은 각각 지정된 수행 장수가 처리한다. 모병관·목마·상사는 자동 모병 담당 장수에게서 읽으며 태수의 동일 패시브를 중복 합산하지 않는다.
- 명령형 축성은 그 도시의 재임 태수에게서 읽되 정치 60 조건을 적용하지 않는다. 병참은 도시 태수가 아닌 출전 부대의 선봉·부관에게서 읽는다.

| `recruiter` | 모병관(募兵官) | recruit_amount | 모든 병력 생산량 +2/4/5% | ✅ 7일 자동 모병 담당자 |

- ✅ = 현행 자동 담당자 체계 또는 현재 명령 경로에 연결. ⚠️ = 데이터는 존재하지만 현행 자동 담당자 경로에는 미연결.
- **적용 주체(현행 코드)**: 모병관·목마·상사는 7일 자동 병력 생산을 맡은 모병 담당 장수의 스킬이다. 선택 병종이 없거나 금 부족으로 생산량이 0이면 보너스도 0이다. 축성은 그 도시 재임 태수의 성벽 수리 명령에 적용하며 정치 60 조건은 없다. 교관은 수동 훈련 명령에는 연결되어 있으나 자동 훈련에는 연결되지 않았다. 진무도 구형 월말 치안 계산에만 연결되어 자동 치안에는 적용되지 않는다. 두 미연결 효과는 별도 구현 결정이 필요하다.
- 병참은 도시 태수가 아니라 **부대를 이끄는 선봉·부관**의 provisions 스킬을 편성 시점에 부대 계수(SupplyUpkeepPercent)로 확정한다(보급부대는 스킬 미발동이라 100%). 계산은 `AdminBonus.Bucket`(Core 공용), 명령 쪽은 `CommandService.GovernorBucket`.
- 목마는 기병 계열 생산분에만, 상사는 상병 계열 생산분에만 적용한다. 모병관은 두 보너스와 가산하되 각 스킬의 티어 효과는 한 번만 계산한다.
- `miner`(채광), `popularity`(인망), `trader`(교역)는 v2에서 제거한다. 기존 세이브나 장수 데이터에 남은 코드는 로드 시 무시하고, 마이그레이션에서 슬롯과 경험치 상태를 제거한다.

## 데이터·부여

- `data/admin-skills.json` — 위 9종(전부 패시브). 장수 보유는 `generals.json`의 `admin_passives`(코드·티어).
- **부여 원칙**: 정치 중심 — 정치가 높을수록 좋은 패시브. 인물 서사 예외(제갈량 둔전,
  마등·공손찬 목마, 맹획 상사 등). 슬롯 0~4. 제거 3종을 보유하던 장수의 빈 슬롯을 자동으로
  임의 스킬로 채우지 않으며, 후속 데이터 조정에서 인물별로 재배정한다.
- 구현 현황(2026-09-29, Phase 18B-2 완료): 현행 데이터는 위 9종만 로드한다. 제거 3종은 데이터·저장 마이그레이션에서 무시하며, 목마·상사·모병관은 실제 7일 자동생산 경로에 연결했다. 대상 병종 제한, 가산 생산량, 금 부족 시 생산 0을 회귀 테스트로 검증했다.
