# Phase 9B — 무관모집·문관모집

상태: 1차 구현·자동 QA 완료, 실제 화면 검수 대기. 이전의 7일 문과·무과시험, 주최 장수 90% 상한, 변동 예산, 연 1회 규칙은 이번 모집 설계로 대체한다. `인재 > 위인영입`은 별도 기능으로 유지한다. [로드맵 Phase 9B](plan-v2-implementation-roadmap.md#보조-인재-수급-무관모집문관모집)의 세부 기준이다.

## 공통 규칙

- `인재` 팔레트에 `무관모집`, `문관모집`을 추가한다. 비용은 해당 도시의 금 1,000이며 영입 포인트는 쓰지 않는다. 둘은 **도시별·게임 달력 기준 월 1회** 시행권을 공유한다. 첫 달에는 즉시 시행할 수 있다.
- 확인 시 금 차감·시행권 사용·능력치와 이름 결정·도시 배속을 하나의 상태 전이로 확정한다. 대화나 임명 팝업을 닫아도 취소되지 않는다. 실패 시 금과 시행권을 그대로 둔다. 점령으로 소유자가 바뀌어도 그달 사용 기록은 유지한다.
- 새 장수는 원본 `data/generals.json`이나 장수 에디터 프리셋에 추가하지 않는다. 게임 상태의 `Generals`·`Postings`와 저장 데이터에만 추가한다. 고유 ID, 모집 종류, 발탁 도시와 날짜, 얼굴 경로를 저장한다. 중복 지급·재추첨 없이 불러오고, 게임 재시작 시에는 새로 시작한다.
- 무력·지력·정치와 모든 병종 적성을 확정 시 난수로 각각 뽑는다. 70 경계는 `70 이상`과 `69 이하`로 나눈다. 문관은 지력 또는 정치 중 **하나라도 70 이상**이면 내정 패시브를 받는다.
- 초상은 `보급 이미지`의 20·30·40·50대 무관/문관 각 4장에서 모집 종류와 생성 나이에 맞게 고른다. 얼굴 중복은 허용하며 초상 경로는 저장한다. Godot에 포함되는 게임 에셋 경로로 복사·등록한다.
- 이름 후보 약 300개를 데이터로 준비한다. 현재 게임의 원본·생성 장수 전체와 비교해 중복을 제거한 뒤 선택한다. 후보 소진 시 번호 접미사로 고유 이름을 결정론적으로 만든다.

| 종류 | 무력 | 지력 | 정치 | 병종별 적성 | 스킬 |
|---|---:|---:|---:|---|---|
| 무관모집 | 50~75 | 20~45 | 20~45 | D~B 무작위 | 무력 70 이상: 낮은 등급 전투 액티브 1개 + 전투 패시브 1개. 69 이하: 전투 패시브 1개 |
| 문관모집 | 20~35 | 50~75 | 50~75 | F~C 무작위 | 지력 또는 정치 70 이상: 낮은 등급 내정 패시브 1개. 둘 다 69 이하: 없음 |

스킬은 현재 데이터에서 실제 구현된 낮은 효과의 허용 목록을 별도로 고정하고, 생성 시 그 목록에서만 무작위 선택한다. 강한 액티브나 미구현 스킬은 제외한다. 기존 데이터의 스킬 수 상한을 지킨다.

## 플레이어 대화·임명

1. 도시의 인재 팔레트에서 모집 종류, 비용, 이번 달 시행 가능 여부를 확인한다. 군주 또는 대리 장수가 금 1,000 사용을 확인한다.
2. 확인 뒤 종류별로 미리 작성된 **3개 대화 중 하나**를 고른다. 각 대화는 `군주 → 무작위 아군 장수 → 군주 → 같은 아군 장수 → 발탁된 장수`의 5개 발언으로 구성하고, 발언마다 30자 이상으로 작성한다. 군주·장수·도시 이름은 확정된 값으로 치환한다.
3. 군주 외 아군 장수가 없다면 다른 아군 도시까지 찾고, 세력 전체에 없다면 군주가 대리 발언하는 별도 문구를 쓴다. 다섯 대화 페이지는 기존 하단 대화 모달을 재사용한다.
4. 마지막 발언 뒤 화면 중앙에 발탁 장수의 초상·이름·모집 종류·무력/지력/정치·대표 적성/스킬을 표시하는 임명 팝업을 연다. 확인을 누르면 연출을 종료한다.
5. 확정된 대화 변형·현재 페이지·임명 팝업 표시/확인 여부를 저장한다. 화면을 닫거나 저장 후 재개해도 보상은 한 번만 지급하고, 남은 연출은 이어서 볼 수 있다. 보고에는 장수 이름과 모집 도시를 남긴다.

## AI 판단

현재 `FactionAI.PlanWeek`는 `RecruitUnlockedHeroes`를 호출해 `AiCanRecruit` 위인을 공통 `CommandService.RecruitHero`로 영입한다. 선행 장수·포인트를 확인하며, 금은 명령 서비스가 검사한다. AI의 `무관모집`·`문관모집`은 미구현이다.

- 기존 위인영입: AI는 후보별 **도시 금까지 미리 확인**하고, 방어·생산·보급용 도시 금 예비를 해치지 않는 도시를 선택한다. 실패해도 같은 후보를 매주 무한 재시도하지 않도록 실패 이유를 남긴다. 위인영입을 할 수 있으면 범용 모집보다 먼저 검토한다.
- 범용 모집: 세력의 자유 장수와 예정된 방어·지원·공세·담당 업무의 부족 인원을 계산한다. 전투 부대의 선봉이 부족하면 무관, 내정/연구 담당이 부족하면 문관을 고른다. 부족이 없으면 모집하지 않는다. 최소 금 예비·도시 월간 시행권을 확인한다.
- 한 도시에서 AI도 무관/문관 합쳐 월 1회, 동일한 1,000금·생성식·이름 풀을 쓴다. 한 주에 여러 도시가 가능해도 부족 인원을 넘겨 연속 모집하지 않는다. AI는 대화 UI를 띄우지 않고 결과만 보고/저장한다. 군단 위임에도 같은 규칙을 적용하되 플레이어의 대화 연출은 띄우지 않는다.
- AI 위인영입과 범용 모집은 `위인영입 → 필요한 무관/문관 모집` 순서로 판단한다. 이미 위인으로 충족된 역할에 범용 장수를 또 생성하지 않는다.

## 단계별 구현·QA

| 단계 | 작업 | 검증 |
|---:|---|---|
| 1 | 모집 명령, 비용, 도시별 월간 공유 시행권 및 저장 | 같은 달 재시도·금 부족·점령·월 변경·저장/로드 xUnit |
| 2 | 스탯·적성·낮은 스킬 풀, 고유 ID·이름 300종, 이미지 연결 | 전체 범위/70 경계, 이름 소진·충돌, 초상 종류, 동일 저장 결과 xUnit |
| 3 | 플레이어 인재 팔레트와 종류별 3종×5발언 대화, 중앙 임명 팝업 | 30자 이상·대화 순서, 닫기/재진입/저장 후 중복 지급 없음, Game 빌드·화면 검수 |
| 4 | AI 기존 위인영입 금 예비 보완 및 부족 역할별 범용 모집 | 위인 우선·무관/문관 선택·도시 월 1회·금 예비·장수 부족 해소, `run-aitest` 수치 QA |

각 단계는 해당 QA 후 개별 커밋·푸시한다. 플레이어의 모집 결과는 확인 시 즉시 확정하며 7일 진행 명령이나 담당 장수 잠금은 두지 않는다.

## 구현·검증 기록 (2026-11-03)

- Core: `GenericRecruitmentService`가 도시별 월 1회, 금 1,000, 고유 이름·능력·스킬·배속·대화 페이지를 게임 상태에 저장한다. AI는 위인영입을 우선하고 부족 인원에 한해 범용 모집을 수행한다.
- Game: `인재` 팔레트의 두 모집 버튼, 종류별 3종×5발언 대화, `new-hero-confirmed`의 `무관임명`/`문관임명` 이미지를 사용한 중앙 팝업을 연결했다. 초상은 `보급 이미지`의 종류·연령별 8장을 사용한다.
- 자동 QA: 모집·저장/로드·AI 관련 136개 xUnit 통과, Game 빌드 통과, Godot 헤드리스 `[genericrecruitqa] passed=True` 확인. 실제 화면의 크기·연출은 사용자 검수가 남았다. 전체 Core 테스트는 기존 작업트리의 데이터·AI 변경이 섞인 상태에서 143건 실패하여 이 기능의 완료 기준으로 사용하지 않는다.
