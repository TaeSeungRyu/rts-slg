# Phase 9B — 문과시험·무과시험 대화형 인재 수급

상태: 계획. [로드맵 Phase 9B](plan-v2-implementation-roadmap.md#phase-9-세력도시형-위인-잠금-해제) 및 [장수 라이프사이클 §6.2](design-general-lifecycle.md#62-문과시험무과시험)의 기존 확률·상한 규칙을 구현할 때 사용한다. **현재 게임에는 시험 명령이 없다.**

## 플레이 흐름

1. `인재 > 문과시험 / 무과시험`에서 도시별 다음 시행 가능일, 현재 금, 주최 장수, 100~1,000금 예산을 확인한다. 주최 장수는 해당 도시 소속이며 다른 불가중복 업무를 수행하지 않아야 한다.
2. 주최 장수 초상 확인창에서 시험 종류·7일 기간·비용·재사용일 산정 기준을 말한다. 확인하면 금을 즉시 예약·차감하고 주최 장수를 7일 잠근다. 같은 도시에서 두 시험은 하나의 연 1회 시행권을 공유한다.
3. 7일간의 진행에는 시험 준비·응시·심사 상태를 기록한다. 플레이를 막는 중간 선택지는 두지 않는다. 도시 상세의 진행 명령에 시험명과 완료일까지 표시한다.
4. 완료일에 시드 기반 난수로 결과를 **한 번만** 확정한다. 생성 장수 1명은 진행한 도시·세력에 즉시 배속한다. 시험 주최 장수와 합격자가 번갈아 말하는 하단 대화 카드 2~3장으로 결과를 발표하고, 마지막 카드에 이름·성별·능력치·병종 적성·출신 도시를 표시한다. 닫으면 장수 상세로 진입할 수 있다.
5. 완료일을 기준으로 360일 뒤 같은 도시의 다음 시험을 허용한다. UI와 저장/불러오기에서 날짜가 동일해야 한다.

## 대화·이벤트 구성

대사는 `data/`의 이벤트 데이터로 분리한다. 말풍선의 주체는 주최 장수 초상과 합격자 초상(기본 생성 장수 이미지가 없다면 전용 실루엣)을 교차한다. 모든 문구는 문과/무과, 결과 품질에 맞게 작성한다.

| 시험 | 결과 대화 3종 | 장면 핵심 |
|---|---|---|
| 문과 | 뛰어난 답안, 안정된 답안, 뜻밖의 관점 | 주최의 질문 → 응시자의 답변 → 임관 선언 |
| 무과 | 뛰어난 무예, 견실한 무예, 뜻밖의 전술 | 시범 과제 → 응시자의 실연·설명 → 임관 선언 |

- 위 6종은 **연출 분류**이며 당락을 새로 뽑지 않는다. 시험은 비용을 낸 정상 완료 시 반드시 1명을 얻는다. 실제 스탯·적성은 기존 확률표의 결과와 일치해야 한다.
- 결과 카드의 첫 줄은 대화, 다음 줄은 실제 생성 수치로 구분한다. 수치가 생성 결과와 다르면 QA 실패다.
- 단순 닫기나 로그 재생으로 보상이 다시 지급되지 않는다. 보고에는 시험 완료·생성 장수 이름만 남기고 대화는 눌러 다시 볼 수 있다.
- 여러 도시 시험이 같은 날 완료되면 도시 ID 순으로 각각 처리·대화 대기열에 넣는다. 다른 장수 대화 중에는 결과 카드를 덮어쓰지 않는다.

## 규칙·예외

- 도시별 시행 기록에는 `마지막 완료일`, `시험 종류`, `생성 장수 ID`를 저장한다. 예정 명령도 저장해 중복 발행을 막는다. 시작일이 아닌 완료일 기준 360일이다.
- 능력치 상한은 주최 장수 각 능력치의 90%; 병종별 적성 상한은 주최의 해당 등급보다 한 단계 아래다. 최저 등급은 F. 두 시험의 가중치와 금별 확률은 [로드맵의 기존 표](plan-v2-implementation-roadmap.md#보조-인재-수급-문과시험무과시험)를 따른다. 어느 보정도 상한을 넘길 수 없다.
- 새 장수 ID는 시나리오 원본 ID와 충돌하지 않게 저장 상태의 최대 ID 다음으로 부여한다. 고유 장수 원본 데이터는 수정하지 않는다. 생성 장수에는 `generated`, 시험 종류, 출신 도시를 남긴다. 이름은 데이터 풀에서 중복을 피해서 선정하고 소진 시 결정적인 번호 접미사를 붙인다.
- 도시가 완료 전 함락되거나 주최 장수가 사라지면 시험을 취소하고 예약한 금을 원래 세력의 존속 도시 금고에 전액 반환한다. 완료 기록과 360일 제한은 남기지 않는다. 원래 세력의 거점이 하나도 없으면 환불 대상이 없어 취소 사실만 기록한다.
- AI도 같은 시작 조건·비용·기간·생성식·도시 쿨다운을 사용한다. UI 전용 무료 생성 경로를 만들지 않는다.

## 단계별 구현·QA

| 단계 | 작업 | 독립 QA·커밋 기준 |
|---:|---|---|
| 1 | 시험 명령·도시별 시행권·주최 잠금·금 예약과 저장 스키마 | 도시별 최초 허용, 문/무 공유 시행권, 중복·금 부족·바쁜 장수 거부, 세이브 왕복 xUnit |
| 2 | 시드 기반 능력치·적성 생성기와 ID·이름 관리 | 100/1,000금 경계, 1% 상한 추정, 주최의 90%/한 단계 아래 절대 초과 금지, 동일 시드 재현 xUnit |
| 3 | 7일 결산·도시 함락 취소·AI 사용 | 하루씩/7일 한 번 동일 결과, 다중 도시 동시 완료, 취소/환불, AI 동일 비용 xUnit |
| 4 | 문·무 시험 가로형 준비 모달과 장수 초상 확인창 | Godot 빌드·헤드리스 UI QA, 금·완료일·재시행일 표시, 테이블/모달 세로 스크롤 회귀 점검 |
| 5 | 데이터형 결과 대화 6종·재생·보고 연결 | 시뮬레이션 결과와 표시 수치 일치, 대기열·닫기 재실행 방지 자동 QA 및 `run-maptest.bat` 실기기 검수 |

각 단계는 개별 QA 뒤 커밋·푸시한다. 별도 성별 확률, 불합격, 시험 중 플레이어 선택에 따른 능력치 보정은 이 계획 범위 밖이다.
