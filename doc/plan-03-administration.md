# 개발 계획 03 — 내정 시스템 (CLAUDE 2단계, 실행 후순위)

> **실행 순서**: 맵+유닛 이동 슬라이스([plan-02-map-units.md](./plan-02-map-units.md)) 이후에 진행한다.
> CLAUDE.md 단계 번호로는 2단계(내정)지만, 표현 슬라이스를 앞당기며 실행 순서가 뒤로 밀렸다.
> 도시를 개발해 자금·군량을 생산하는 내정 루프를 walking-skeleton 방식으로 얹는다.

## 전제 (앞 단계에서 이어받음)

- 파이프라인 `data/*.json → ScenarioLoader → GameState → TurnEngine → Sandbox`가 이미 동작
- 4대 절대 규칙(Core 순수성·테스트·데이터 외부화·결정론)은 계속 지킨다
- 1단계의 더미 세수 틱(`monthly_tax_per_city`)은 이 단계에서 실제 생산으로 **대체**된다

## 확정된 설계 결정

- **컨셉**: 단순 삼국지 기반 (역사 삼국지, 중국 대륙 맵)
- **진행 방식**: 명령형 — 세력이 매월 '개발' 명령을 내려 값을 올린다. 이 단계에서는 **명령 메커니즘만** 구축하고, 누가 어떤 명령을 낼지 결정하는 주체(AI)는 이후다. 지금은 Sandbox/테스트가 명령을 구동한다
- **무장 관여**: 개발 효율에 **무장 정치력**을 반영한다 (도시에 배속된 무장이 개발을 수행)
- **속성 범위**: 우선 **상업·농업**만 (자금·군량 생산). 인구·치안은 이후 단계로 연기 — *이 범위는 조정 가능*

---

## 단계 세분화

각 단계는 독립 커밋이며 `dotnet build` / `dotnet test` green 확인 후 원격 푸시한다.
범례: 🔍 = **사용자가 직접 확인할 수 있는 지점**

### Step 1 — 도시 내정 속성
- **내용**: `City`에 상업(Commerce)·농업(Agriculture)과 각 최대치(CommerceMax·AgricultureMax) 추가. `cities.json`과 로더/DTO 확장
- **테스트**: 로딩 매핑, 참조 무결성 유지
- 🔍 **확인 지점**: `data/cities.json`에서 도시별 상업/농업 초기값·상한을 직접 조정 가능

### Step 2 — 매월 생산
- **내용**: `TurnEngine`이 매월 상업 → 자금(국고), 농업 → 군량(도시 비축)을 생산. 1단계의 `monthly_tax_per_city` 틱을 이 생산으로 교체. 생산 계수는 `balance.json`에서 주입
- **테스트**: 생산량 = 속성 × 계수, 월 누적, 세력별 자금/도시별 군량 반영
- **확인**: 자동 테스트

### Step 3 — 내정 명령 + 개발 적용
- **내용**: `AdministrationCommand`(상업 개발 / 농업 개발) — 대상 도시 + 실행 무장. 턴에 명령을 적용해 속성을 올린다. **개발량 = 기본치 + 무장 정치력 반영분**, 단 최대치를 넘지 않음(cap). 개발 공식 상수는 `balance.json`
- **테스트**: 정치력이 높을수록 개발량 증가, 최대치 초과 없음, 명령 없으면 변화 없음
- **확인**: 자동 테스트

### Step 4 — 무장 배속·명령 유효성
- **내용**: 명령 유효성 경계 검증 — 실행 무장이 해당 세력 소속인지, 대상 도시가 그 세력 소유인지, 한 무장이 한 턴에 하나의 명령만 등. 위반 명령은 무시(또는 명시적 실패)
- **테스트**: 유효/무효 명령 처리, 소속·소유 규칙
- **확인**: 자동 테스트

### Step 5 — Sandbox 내정 구동 🔍🔍
- **내용**: Sandbox에서 몇 개의 개발 명령을 구동하고, 턴 진행에 따라 상업/농업/자금/군량이 어떻게 변하는지 요약 출력. 결정론 유지(같은 시드/명령열 = 동일 출력)
- 🔍 **가장 뚜렷한 확인 지점**: 직접 실행해 개발 → 생산 증가를 수치로 확인
  ```bash
  dotnet run --project SanguoSLG.Sandbox -- --turns 24 --seed 42
  ```

### Step 6 — 불변식·결정론 통합 테스트
- **내용**: 도시 속성은 최대치를 절대 넘지 않는다, 같은 명령열은 같은 최종 상태를 만든다(결정론), 명령 순서 정규화 등 불변식을 테스트로 못박음
- **확인**: 자동 테스트

## 열린 결정 (설계자 확인 필요 — 임의로 정하지 않음)

- **생산 공식**: 자금수입 = 상업 × 계수, 군량수입 = 농업 × 계수 — 정확한 계수·곡선
- **개발 공식**: 개발량에 정치력이 들어가는 방식(예: 기본치 + 정치/N)과 상수
- **속성 초기값·상한**: 도시별 상업/농업 시작값과 최대치
- **명령 제약**: 한 무장 1명령/턴, 도시당 동시 개발 인원 등
- 위 수치는 전부 `balance.json`/`data`의 **임시값**으로 두고, 실제 밸런스는 이후 조정
