# 개발 계획 02 — 맵 + 유닛 이동 수직 슬라이스

> **실행 순서 재조정**: 사용자 결정으로 표현 계층(맵·유닛 이동·UI)을 앞당긴다.
> CLAUDE.md의 단계 번호로는 표현(6단계) + 부대/이동·A\*(3단계)를 가로지르는 **수직 슬라이스**다.
> 내정(CLAUDE 2단계)은 이 슬라이스 뒤로 미룬다 → [plan-03-administration.md](./plan-03-administration.md)

## 왜 지금 하는가 / 순서 위험

- **동기**: 움직이는 맵·유닛을 눈으로 보고 손맛을 확인해야 흥미가 유지된다(1인 개발). 표현 계층 위험을 일찍 걷어낸다
- **위험(짚고 감)**: 전투·AI·밸런스 밑단이 없는 상태의 UI는 밑단 변경 시 재작업 소지가 있다
- **완화**: 게임 로직(헥사 맵·A\* 길찾기·이동 규칙)은 **Core에**, Godot은 **렌더링·입력만**. 화면 픽셀 변환은 Game에서만. → CLAUDE 규칙 #1(Core 순수성) 유지

## 확정된 설계 결정

- **이동 모델**: 자유 클릭 이동 — 헥사를 클릭하면 A\* 최단경로로 걷는다. 이동력·턴 제약 없음(손맛·이동 검증 우선)
- **맵 구성**: 평평한 헥사 필드 — 지형 없음, 전부 통행 가능. 기존 도시는 좌표대로 배치. 지형·이동불가는 이후
- **아키텍처**: A\*·맵·이동은 Core / 렌더링·카메라·입력·애니메이션은 Godot Game

## 실무 제약 (중요)

에이전트는 **Godot 에디터의 렌더링 화면을 볼 수 없다.** 씬·C# 스크립트·Core 로직·테스트를 만들고 헤드리스 빌드로 **컴파일**은 검증하지만, "UI가 좋은지"의 시각 판단·다듬기는 **사용자가 에디터에서 확인하거나 스크린샷을 공유**해야 반복 가능하다. Step 4~5가 그 지점이다.

## 단계 세분화

각 단계는 독립 커밋, `dotnet build`/`dotnet test`(Core) 또는 헤드리스 빌드(Game) green 후 푸시.
범례: 🔍 = **사용자가 직접(에디터/스크린샷) 확인하는 지점**

### Step 1 — Core: 헥사 맵
- **내용**: `HexMap` — 경계 안의 평평한 헥사 필드. 타일 열거, `Contains`/`IsPassable`(지금은 경계 안이면 통행 가능). 맵 크기는 `balance`/데이터의 임시값
- **테스트**: 경계 판정, 타일 수, 통행 가능성
- **확인**: 자동 테스트

### Step 2 — Core: A\* 길찾기
- **내용**: `HexPathfinder` — `HexCoord.Neighbors` 기반 A\*, 스텝 비용 1, 경계/이동불가 회피, 경로(HexCoord 목록) 반환. Godot `AStarGrid2D` 안 씀(Core 규약)
- **테스트**: 평평한 필드에서 경로 길이 = 헥사 거리, 합성 장애물 회피, 도달 불가 시 빈 경로, 시작=목표
- **확인**: 자동 테스트

### Step 3 — Core: 유닛 + 이동
- **내용**: `Unit`(UnitId, 위치 HexCoord, 소유 FactionId), 경로를 따라 위치를 갱신하는 이동 처리(불변 갱신). 시작 위치는 도시 등
- **테스트**: 경로 따라 위치 갱신, 목표 도달, 결정론
- **확인**: 자동 테스트

### Step 4 — Godot: 헥사 맵 렌더링 🔍
- **내용**: axial(q,r) → 픽셀(flat-top) 변환(Game 전용), 헥사 타일 그리기, 카메라(팬/줌), 도시 마커. Core `HexMap`을 읽어 렌더
- **검증**: 헤드리스 빌드 컴파일 + 🔍 **사용자가 에디터에서 맵이 보이는지 확인**(스크린샷 공유 시 함께 다듬기)

### Step 5 — Godot: 유닛 스프라이트 + 클릭 이동 🔍🔍
- **내용**: 유닛 스프라이트 배치, 헥사 클릭 → Core A\*로 경로 계산 → 헥사 중심을 잇는 트윈 애니메이션으로 이동. 경로 하이라이트(선택)
- **검증**: 헤드리스 빌드 + 🔍🔍 **사용자가 클릭해 유닛이 걷는지·손맛을 확인**

### Step 6 — 마무리
- **내용**: 헤드리스 빌드 최종 검증, Core 경계/결정론 테스트 보강, 소소한 다듬기. 슬라이스 회고 후 다음 방향(지형·다중 유닛·이동력 등) 논의
- **확인**: 자동 테스트 + 사용자 회고

## 열린 결정

- **맵 크기·형태**: 평평한 필드의 범위(반경/사각) — 임시값
- **유닛 출처**: 슬라이스에선 도시 등에 유닛 1기 스폰. `units.json`은 이후
- **헥사 픽셀 크기·비주얼**: Game 측, 사용자가 에디터에서 조정
- **입력 UX**: 클릭 이동/선택 방식 세부 — 사용자 피드백으로 다듬음
