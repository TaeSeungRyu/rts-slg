# UI 개선 작업 목록

작성일: 2026-09-27
대상: `run-maptest.bat`의 캠페인 UI를 우선하며, 공통 컴포넌트는 다른 Godot 씬에서도 재사용한다.

> 기능 Phase 0~18A의 규칙을 바꾸지 않고 표현·정보 구조·조작성만 개선한다. UI 작업도 요구사항별 자동 QA를 먼저 만들고 구현과 함께 통과시킨다. 시각적 최종 판단은 프로젝트 규칙에 따라 사용자가 해당 `.bat`을 실행해 확인한다.

## 1. 조사 결과

현재 UI는 기능별로 개별 구현된 화면이 많아 동일 목적의 모달도 폭, 헤더, 닫기 버튼, 스크롤 범위가 다르다.

| 관찰 영역 | 현재 상태 | 개선 필요성 |
|---|---|---|

## 2. 공통 UI 원칙

### 2.1 가로형 우선

- 세로 스크롤이 생기는 모달은 먼저 폭을 넓혀 좌우 두 영역으로 재배치한다.
- 화면 기준 폭 프로필:
  - `Compact`: 화면 폭 44~58%, 단순 알림·시스템 확인.
  - `Standard`: 화면 폭 68~78%, 선택 항목과 상세 설명이 함께 있는 화면.
  - `Wide`: 화면 폭 84~94%, 장수 표·연구·편성·전체 목록.
- 높이는 화면의 70~86% 안에 둔다. 92% 높이의 세로형 모달을 기본값으로 사용하지 않는다.
- 1280×720에서도 패널과 닫기 버튼이 화면 경계를 넘지 않아야 한다.

### 2.2 헤더·본문·푸터 분리

- 헤더: 뒤로가기, 제목, 현재 도시/부대, 닫기 버튼. 스크롤되지 않는다.
- 본문: 필요한 경우에만 단일 세로 스크롤을 사용한다.
- 푸터: 취소·확인·목표 지정 등 최종 행동. 스크롤되지 않는다.
- 중첩 세로 스크롤은 금지한다. 긴 목록은 `Tree` 또는 본문 하나만 스크롤한다.
- 닫기 버튼은 34~40px 정사각형으로 고정하고 콘텐츠 높이에 따라 늘어나지 않는다.

### 2.3 정보 배치

- 선택 화면은 `왼쪽 목록/표 + 오른쪽 설명·예상 결과`를 기본으로 한다.
- 선택 결과, 비용, 기간, 기존 업무 해제, 실패 조건은 오른쪽 요약에 즉시 반영한다.
- 카드 이미지가 레이아웃 최소 크기를 밀어내지 않도록 고정 컨테이너 안에서 비율 유지 축소한다.
- disabled 항목은 색만 흐리게 하지 않고 잠금 사유를 같은 화면에 표시한다.
- 긴 문장은 문단 대신 아이콘·키/값 행·상태 칩으로 분리한다.

## 3. 장수형 확인창 기준

### 3.1 적용 원칙

게임 세계 안에서 장수가 수행하는 명령은 모두 장수형 확인창을 사용한다. 순수 시스템 동작만 인물 없는 확인창을 허용한다.

| 명령 종류 | 확인창 화자 |
|---|---|
| 연구·도시 계략·외교·탐색·생산·시설 작업 | 실제 수행 장수 |
| 전투·보급·수송·집단군·출항 편성 | 선봉/주장 장수 |
| 부대 복귀·재지정 | 해당 부대 선봉 장수 |
| 담당자·태수·군사 임명/해제 | 임명 또는 해제 대상 장수 |
| 위인 영입 | 영입을 주관하는 도시의 태수, 없으면 군주 |
| 진행 | 군사가 있으면 군사, 없으면 군주 |
| 저장·불러오기·종료 | 순수 시스템 확인창 유지 |

화자를 찾지 못한 경우 무관한 임의 장수를 보여주지 않는다. `수행 장수 → 부대 선봉 → 도시 태수 → 세력 군주`의 명시된 순서로만 대체한다.

### 3.2 레이아웃

- `Wide`가 아닌 `Standard` 가로형으로 표시한다.
- 왼쪽 32~38%: 장수 세로 초상, 이름, 현재 업무.
- 오른쪽: 명령 제목, 장수 대사, 명령 요약 표, 경고/해제 업무.
- 하단 고정 푸터: `취소`, 강조된 `확인`.
- 초상은 패널 안쪽에서 잘리고 테두리 밖으로 나오지 않아야 한다.
- 대사는 명령군별 최소 5종을 두며 목적 도시·대상·병종처럼 달라지는 핵심 명칭을 포함한다.
- 성공률이 규칙상 숨겨져야 하는 계략/외교는 기존 군사 예측 정책을 유지하고 확인창이 실제 확률을 누설하지 않는다.

### 3.3 확인창 우선 전환 대상

| 우선순위 | 현재 일반 확인창 | 필요한 화자 |
|---:|---|---|
| P0 | 생산 작전 | 주최 장수 |
| P0 | 전투편성·보급편성·수송편성·집단군편성·출항 | 선봉/주장 장수 |
| P0 | 시설 업그레이드·담당 해제 | 수행/대상 장수 |
| P1 | 위인 영입·주력병종 선택 | 태수 또는 군주 |
| P1 | 명령 취소 | 해당 명령 수행 장수 |
| 유지 | 저장·불러오기 | 인물 없는 시스템 확인창 |

## 6. UI QA 기준

### 자동 QA

- 해상도: 1280×720, 1600×900, 1920×1080.
- 모든 모달의 `GlobalRect`가 뷰포트 안에 있어야 한다.
- 헤더의 제목·뒤로가기·닫기와 푸터의 주요 행동 버튼이 스크롤 없이 보여야 한다.
- 세로 스크롤은 본문에 최대 1개만 허용한다. 표의 가로 스크롤은 Wide 데이터 화면에서만 허용한다.
- 초상·병종 카드·아이콘은 지정 프레임을 넘어 레이아웃 최소 크기를 밀어내지 않아야 한다.
- 빈 목록, 항목 1개, 실제 최대 데이터 목록을 각각 연다.
- 확인창은 명령의 실제 장수 ID와 초상을 사용하며 승인 전 상태가 바뀌지 않아야 한다.
- 확인 후 모달 스택·명령 팔레트·선택 상태가 요구 흐름대로 닫히거나 복귀해야 한다.
- ESC와 우클릭은 최상단 모달 하나만 닫고 아래 화면의 복귀 경로를 보존해야 한다.
- 화면을 반복해서 열고 닫아도 해제된 노드 접근, 중복 시그널, RID/Object 누수가 증가하지 않아야 한다.

### 사용자 실기기 QA

- `run-maptest.bat`으로 글자 크기, 정보 밀도, 초상 크롭, 클릭 손맛을 확인한다.
- 자동 QA가 보장하지 못하는 미적 판단은 단계별로 한 번에 확인할 수 있도록 변경 화면 목록을 완료 보고에 적는다.
- 스크린샷 자동 캡처는 저장소 작업 규칙에 따라 사용하지 않는다.

## 7. 완료 정의

- 기능 규칙과 수치가 UI 개편 전후 동일하다.
- 게임 명령 확인창은 명령 주체가 명확한 장수형 대화로 보인다.
- 긴 모달은 화면 가로 공간을 사용하며 닫기·확인 버튼이 세로 스크롤 아래로 사라지지 않는다.
- 같은 종류의 선택은 같은 표/카드/강조 규칙을 사용한다.
- 해당 화면의 headless UI QA와 Game 빌드가 통과한다.
- 사용자가 실기기에서 확인할 범위를 명확히 안내한 뒤 단계 완료를 판정한다.

## 8. UI-01 확인 방법

1. `run-ui-layout-qa.bat`을 실행한다. 콘솔 마지막에 `[modal-framework-qa] cases=9/9 passed=True`가 나오면 3개 해상도×3개 폭 프로필 자동 QA가 통과한 것이다.
2. `run-maptest.bat`을 실행하고 아군 성을 누른 뒤 `연구 → 전투교리` 또는 `일반연구`를 연다. 이 두 화면은 Wide 프로필이다.
3. 담당자·탐색·외교 등 일반 명령 모달을 열어 Standard 프로필이 적용되는지 본다.
4. 창 크기를 줄여도 모달이 화면 밖으로 나가지 않는지, 제목과 우측 상단 `✕`가 고정되는지, 긴 내용은 본문만 스크롤되는지 확인한다.

UI-01은 공통 틀과 명령 모달 적용까지다. 장수 초상·대사가 나오는 가로형 확인창은 UI-02에서 적용한다.
