# Phase 21B. 시나리오 맵 에디터 상세 계획

상태: **계획 완료·코드 미착수**. 이 문서는 [v2 로드맵 Phase 21B](plan-v2-implementation-roadmap.md#phase-21b-시나리오-맵-에디터)의 구현 기준이다. Phase 21·21A는 1차 완료 후 사용자 재검수를 기다린다.

## 1. 목표와 현재 코드의 출발점

- `run-editmap.bat`의 `EditMap.tscn`/`EditMapScene.cs`는 현재 **2D 지형·성 위치 검수장**이다. `SanguoSLG.Game/assets/maps/east-asia-map.json`은 174×125 행·열 지형, 대표 육상 동선, 성 위치 후보를 담는다. 배치 후보 36개는 캠페인의 실제 `City`가 아니다.
- 실제 게임 지도는 `ScenarioLoader`가 `data/map.json`, 도시 데이터, 시설 정보를 로드하고 `HexMap`·`GameState`를 만든다. 편집기 지도는 행·열, 캠페인 지도는 axial `HexCoord`라서 단순 파일 교체만으로 작동하지 않는다.
- `run-general-editor.bat`은 현재 `data/generals.json` 등을 실제로 수정한다. 새 캠페인은 장수 정의를 별도 상태로 복사하고 저장 슬롯은 그 상태를 보존한다. 맵은 장수처럼 **새 게임에만 반영**하되, 현행 저장/재로딩 경로에 맵 스냅샷이 있는지 먼저 감사하고 부족하면 추가한다. 장수 에디터가 이미 맵 격리까지 제공한다고 가정하지 않는다.
- 최종 목적은 게임 시작 전 화면의 **`맵 변경하기`**와 **`장수 관리`** 진입점이다. 우선 독립 BAT로 기능과 저장 계약을 검증한 뒤 같은 에디터 씬을 시작 화면에서 연다.

## 2. 편집 화면과 선택 흐름

1. 기존 게임의 지형 GLB·재질·조명·성/항구/시설 에셋을 재사용해 지도를 3D로 표시한다. 평면색 육각형은 편집 선택·강조 오버레이로만 남긴다. 21,750타일 규모이므로 반복 지형은 청크/인스턴싱과 가시 범위 렌더를 사용한다. 카메라 확대·이동 중 타일 선택 좌표가 어긋나지 않아야 한다.
2. 타일 또는 성·시설·항구 에셋을 클릭하면 그 타일을 정확히 강조하고 지형 종류, 육상/해상 통행, 배치물의 이름·종류·규모·방향, 인접 성/수면을 설명한다. 같은 선택에 기존 **성·부대 명령 팔레트의 위치·버튼·장수 없는 편집용 스타일**을 공통 컴포넌트로 재사용한다. 편집기는 장수가 명령하는 게임 플레이가 아니므로 장수 확인창은 사용하지 않는다.
3. 팔레트는 `성 추가`, `생산 시설 관리`, `지형 변경`, `항구 관리`와 선택 물체에 맞는 `성 편집`, `시설 편집`, `항구 편집`을 보여준다. 사용 불가 버튼은 숨기지 않고 비활성화하며 사유를 짧게 표시한다. 열린 모달·팔레트는 닫기/취소/빈 지도 클릭으로 정상 종료하고 편집 모달이 켜진 동안 뒤쪽 지형 클릭·줌 입력을 막는다.
4. 선택→편집→확인 시 **메모리의 편집 초안과 3D 화면에는 즉시 반영**한다. `저장` 전에는 디스크·실행 중 캠페인을 바꾸지 않는다. 변경 표시, 저장·취소, 되돌리기/다시 적용, 미저장 종료 확인을 둔다. `지형 변경` 드롭다운은 선택 즉시 타일 에셋을 교체하며, 저장 실패 시 초안과 마지막 정상 저장본을 보존한다.

## 3. 명령 팔레트 활성화 계약

| 명령 | 활성 조건 | 선택 후 동작 |
|---|---|---|
| 성 추가 | 타일에 성·항구·생산 시설이 없고 해당 규모의 성 발자국 전체가 지도 안의 허용 육상 지형이며 다른 객체와 겹치지 않음 | 이름·소/중/대형·6방향을 고른 뒤 성 생성. 저장 전 시각 미리보기 |
| 성 편집 | 클릭한 발자국이 기존 성에 속함 | 이름·종류·방향 변경 또는 제거. 확대/방향 변경 후의 발자국도 재검증 |
| 생산 시설 관리 | 선택 칸이 성 발자국 밖이고 **성 발자국 경계에서 육각 거리 2칸 이내**에 성이 있으며 설치 가능한 육상 타일임 | 연결할 성 선택(복수 후보일 때 필수) 후 논·밭·마을·공방 등 현행 시설의 추가·수정·제거. 기존 시설 클릭 시 `시설 편집`으로 진입 |
| 지형 변경 | 선택 칸에 성 발자국·항구·생산 시설이 없음 | 기존 지형 열거값 드롭다운에서 선택, 즉시 3D 교체. 물/험산 변경으로 길·시설·도시가 고립되면 저장 전 검증 |
| 항구 관리 | 성·항구·생산 시설이 없고 선택한 **육상 해안 칸의 인접 6칸 중 최소 1칸이 통행 가능한 물**임 | 소/중형 항구 추가. 기존 항구 클릭 시 이름·종류·방향·제거가 가능한 `항구 편집`으로 진입 |
| 시설 편집 | 선택 칸에 연결된 생산 시설이 있음 | 방향·종류 변경 또는 제거. 연결 성의 시설 수량과 배치 목록을 동시에 갱신 |
| 항구 편집 | 선택 칸에 기존 항구가 있음 | 이름·소/중형·6방향 변경 또는 제거. 부두가 물을 향하는 유효 방향만 허용 |

성·항구·시설의 점유 칸에서는 다른 물체를 추가할 수 없다. 성 규모를 바꾸거나 지형을 바꿀 때는 **중심 칸만이 아니라 성 전체 발자국**을 기준으로 검사한다. `근처`의 생산 시설 반경 2칸은 우선 확정 구현값이며 UI에 수치로 표시한다. 6방향은 게임의 동·남동·남서·서·북서·북동 순서를 공유한다. 기존 성·항구·시설에 방향 데이터가 없으면 현재 표시 방향을 기본값으로 변환한 뒤 별도 방향 필드를 저장한다.

## 4. 데이터 계층과 새 게임 전용 적용

| 계층 | 역할 | 수정 시점 |
|---|---|---|
| 원본 시나리오 | `data/map.json`·도시/시설 정의 및 동아시아 생성 데이터. 배포 기본값 | 개발자 버전 갱신 시에만 |
| 맵 프리셋 | 에디터가 저장한 지형·성·항구·시설·방향·안정 ID·맵 버전 | 게임 시작 전 `맵 변경하기` 또는 독립 BAT의 명시적 저장 시 |
| 캠페인 맵 스냅샷 | 새 게임 시작 순간 선택 프리셋을 검증·복사한 지도와 배치물 | 게임 진행 및 해당 저장 슬롯에서만 |

- 에디터 저장은 `user://map-presets/`의 **별도 파일**에 원자적으로 기록한다. 원본 `east-asia-map.json`, `data/map.json`, 장수 원본을 덮어쓰지 않는다. 시작 화면은 기본 지도 또는 저장된 프리셋을 선택한다. 현재 세션이 이미 시작되었으면 프리셋 수정/교체를 읽어 재적용하지 않는다.
- 새 게임 시작 시 프리셋의 행·열→axial 좌표/유효 타일 마스크를 결정론적으로 변환하고 `ScenarioLoader` 입력으로 만든다. 지형 코드 `B`(큰강 건넘) 등 기존 로더와 다른 코드는 명시적으로 매핑한다. 성·항구는 안정 ID, 중심·발자국, 규모, 방향을 보존한다. 시설은 연결 성 ID·타일·종류·방향과 도시 시설 개수를 일치시킨다.
- 현행 Core에서 항구는 독립 엔티티가 아니라 `City.Port`로 표현한다. 에디터에서는 성과 항구를 **서로 다른 배치물**로 다루되 내보낼 때 기존 도시/항구 모델과 충돌 없는 형태로 변환한다. 방향/시설 배치 정보가 현행 DTO에 없으면 시나리오 스키마를 확장한다. 성·항구 제거 시 ID 재사용 금지, 연관 시설·배속·시나리오 초기 상태는 저장 전에 정리하거나 명시적 오류로 거부한다.
- 저장 슬롯에는 **맵 지형과 배치물의 스냅샷 또는 불변 시나리오 사본**을 포함한다. 불러오기는 슬롯의 맵을 우선하고 현재 프리셋 파일을 다시 읽어 덮어쓰지 않는다. 현행 세이브가 맵을 보존하지 않는다면 이 단계에서 저장 스키마를 올리고 이전 슬롯의 기본 지도 복원 규칙을 추가한다. 이전 슬롯의 출처가 모호하면 조용히 신규 프리셋을 적용하지 않고 복원 불가 사유를 표시한다.
- `run-general-editor.bat`도 같은 시작 전 메뉴의 `장수 관리`에서 열 수 있게 하되 현재 장수 편집 범위와 저장 파일은 유지한다. 새 게임에 맵·장수 변경을 적용하는 순서와 기존 슬롯에 영향을 주지 않는 규칙을 함께 QA한다.

## 5. 단계별 구현과 QA

| 단계 | 구현 | 필수 검증 |
|---:|---|---|
| 21B-1 | 편집 문서 모델, 좌표 변환, 원본/프리셋/세이브 경계 | 동일 입력의 좌표·ID 재현, 섬/지도 밖 마스크, 기존 세이브가 새 프리셋을 보지 않음 |
| 21B-2 | 게임 에셋 3D 타일·성 후보 미리보기·청크 렌더·카메라 | 줌/이동 후 선택 일치, 해안/강/섬 에셋 매핑, 전체 지도 부하, 에셋 누락 폴백 |
| 21B-3 | 타일 설명·공통 팔레트·조건별 버튼 | 빈 칸/기존 성/시설/항구/물/험산 각각의 활성 사유, 모달 입력 차단·닫기 |
| 21B-4 | 성 추가/편집 | 소·중·대 발자국, 이름 중복·빈 이름, 6방향, 확대 시 충돌/지도 밖 거부, 제거 후 재추가 |
| 21B-5 | 생산 시설 추가/편집 | 2칸 경계, 복수 인접 성 선택, 종류·방향·제거, 연결 도시 개수와 위치 일치 |
| 21B-6 | 지형 변경 | 드롭다운 즉시 3D 반영, 저장/취소/되돌리기, 강·바다·통행·인접 물 변화와 배치 조건 재검증 |
| 21B-7 | 항구 추가/편집 | 물 인접, 부두 방향, 소·중형, 이름·방향·제거, 성/시설 중복 거부 |
| 21B-8 | 프리셋 저장·새 게임/기존 세이브 격리 | A맵 진행 중 B맵 저장 후 A맵 유지, B맵 새 게임 반영, A슬롯 불러오기 유지, 재시작/저장 오류/구버전 |
| 21B-9 | 시작 전 `맵 변경하기`·`장수 관리` 연결 | 메뉴와 독립 BAT 결과 일치, 장수 프리셋과 맵 프리셋 동시 선택, 실제 새 게임 7일 진행/저장·불러오기 |

각 단계별로 데이터/코어 테스트, Game 빌드, Godot 헤드리스 씬 로드를 수행하고 개별 커밋·푸시한다. 실제 화면의 성 에셋 크기와 팔레트 사용감은 자동 QA가 대신할 수 없으므로 `run-editmap.bat`에서 사용자 시각 검수를 별도로 받는다. **본 문서 작성은 구현 완료나 게임 QA를 의미하지 않는다.**
