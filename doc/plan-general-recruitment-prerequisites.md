# 장수 선행 조건 기반 인재 영입 개편 (2026-10-27)

## 목표와 기준

`인재 > 위인영입` 후보를 고정 세력과 년도 대신 **세력 소속 장수**로 결정한다. 삼국지 게임의 인연 관계를 초기 데이터 구성의 참고로 삼되, 특정 작품의 고정 영입 공식이라고 주장하지 않는다. 제갈량→유비, 하후돈·하후연→조조처럼 명확한 인연을 우선 지정하고 근거가 약한 장수는 선행 조건 없이 둔다. 장수 ID를 참조하며 이름은 UI에만 사용한다. 공식 게임도 장수 사이의 관계를 표현한다([코에이 삼국지 8 리메이크 장수 소개](https://www.koeitecmoamerica.com/rtk8-remake/character.html), [관계도 설명](https://www.koeitecmoamerica.com/manual/rtk8-remake/en/3500.html)).

## 확정 규칙

1. 인재 정의에 `required_general`(없으면 `null`)을 둔다. 영입하려는 세력의 **현재 배속 장수 전체**에 해당 ID가 있으면 조건 충족이다. 군주 여부와 거점 위치는 무관하며, 포로·해고·이동 중 장수는 배속 여부에 따라 기존 상태 규칙을 따른다.
2. 조건이 없으면 존속 중이며 도시를 가진 어느 세력이나 영입을 시도할 수 있다. 먼저 포인트를 지불해 성공한 세력이 장수를 얻는다. 동일 장수를 다른 세력이 중복 영입할 수 없다.
3. 선행 장수를 나중에 영입하면 그 장수에 연결된 미영입 후보가 즉시 나타난다. 선행 장수가 세력을 떠나면 아직 영입하지 않은 후보는 즉시 다시 잠긴다. 이미 영입한 장수는 잃지 않는다.
4. 선행 장수가 **시나리오의 장수 명단에 없으면** 후보를 영원히 제외한다. 그 선행 장수 자신이 영입 조건에 묶여 있어도 같은 원칙이다. 단순 미배속·미영입은 영구 제외가 아니다.
5. `unlock_year` 및 `generals.json`의 `unlock_year`는 영입 판단에 사용하지 않는다. 영입 자원은 **세력 공용 포인트만** 사용한다. 금은 검사하거나 차감하지 않는다. 기존 포인트 획득처·수치는 유지한다.
6. AI와 플레이어가 동일한 후보 판정, 중복 방지, 포인트 차감 규칙을 쓴다. 후보 표시와 명령 실행 때 각각 재검증한다. 기존 저장 상태의 `EligibleFaction`이 오래되어도 현재 장수 소속을 기준으로 계산한다.
7. 기존 `faction`·`region`·`wanderer` 분류는 저장/로드 호환을 위해 읽되 새 영입 판단에서는 세력·지역 제한으로 사용하지 않는다. 기존 영입 상태와 배속된 장수는 보존한다.

| ✅ 2 | Core 후보 판정과 영입 명령·AI를 통일. 년도·세력·지역·금 조건 제거 | 관련 Core 테스트 및 금 0 영입 회귀 테스트 · `4889ff7c` 및 후속 수정 |

새 시나리오를 시작하면 편집한 데이터가 적용되고 기존 저장은 포함된 시나리오 정의를 우선한다. 데이터 파일을 수정할 때는 현재 작업 트리의 변경을 덮어쓰지 않고 해당 필드만 병합한다.

전체 Core 테스트는 기존과 같은 134개 실패·2105개 통과였고, `run-maptest.bat qa`의 출전 목표 좌표 검증도 별도로 실패했다. 두 실패는 이 영입 경로의 통과 증거로 사용하지 않았다. 에디터 화면의 시각적 배치와 실제 마우스 조작은 사용자가 `run-general-editor.bat`에서 확인한다.
