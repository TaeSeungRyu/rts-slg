# 고대유물 단서·획득·장착 구현 계획

상태(2026-10-18): **구현 및 관련 자동 QA 완료, 사용자 실기기 UI 확인 대기**. [Phase 18 진행표](plan-v2-implementation-roadmap.md#phase-18-탐색-이벤트와-아이템-ui)의 후속 작업이다. 신수 처치 보물과 별도의 획득 경로를 사용하되, 획득 후에는 같은 `획득 보물` 보관함과 장수당 1개 장착 UI를 사용한다. 아래 이름·효과 수치가 현재 데이터에 반영되어 있다.

## 규칙

1. 탐색의 현행 `ancient_relic_clue` 등장 확률은 유지한다. 당첨 시 시드 기반 난수로 아래 **10종 중 한 종류**를 동일 확률로 정한다. 단서 결과에 종류 코드와 이름을 명시한다. 다른 탐색 결과 및 신수 단서 확률은 건드리지 않는다.
2. 단서는 **세력 단위**로 보유한다. 같은 종류 2개가 모이면 그 종류에 대응하는 유물 1개로 자동 변환한다. 서로 다른 종류는 합치지 않는다. 3개면 유물 1개와 잔여 단서 1개다. 탐색 결과/보고에는 `단서 획득 → 2개 소모 → 유물 획득`을 한 번만 기록한다.
3. 유물은 세력 보관함의 별도 **아이템 인스턴스**로 지급한다. 같은 유물을 여러 번 획득할 수 있으나 장수당 장착 슬롯 1개는 현행 규칙을 유지한다. 소유 세력·장착자·획득일·출처를 저장하고, 장수 소속 변경 시 기존 보물과 같은 회수 규칙을 따른다.
4. 유물 효과는 **장착 중에만** 적용하고 원본 장수 능력치/병종 등급을 영구 수정하지 않는다. 각 수치 효과는 최대 5%다. 같은 계산 항목에 유물 효과가 여러 경로로 들어오면 **최고값 하나만** 적용하며 합계도 5%를 넘지 않는다. 다른 기존 시스템의 신수 보물 효과를 5%로 일괄 하향하지 않는다.
5. `장수 특성`은 문자 등급을 올리는 대신 병종 적성으로 인한 **실효 전투 보정**을 백분율로 추가한다. 화면에는 원래 등급과 유물 보정 `+N%`를 함께 보여준다. 이는 등급의 상시 승급이 아니므로 장착 해제 시 원복된다.
6. 내정 효과는 장착 장수가 해당 도시의 담당자 또는 생산 주최자로 **실제로 일할 때만** 적용한다. 주 단위/완료 시점의 기존 생산 공식에서 적용하고, 같은 산출물의 유물 보정은 최대 5%다. 한 도시에서 여러 장수가 같은 산출물에 기여하면 최고값 하나만 쓴다.

## 단서와 유물 10종 제안

| 단서 코드·이름 | 2개로 얻는 유물 | 장착 효과 제안 | 적용 지점 |
|---|---|---|---|
| `relic_blade_fragment` 검날 파편 | 패왕의 검편 | 부대 공격력 +5% | 장착 장수가 선봉/부관인 부대의 일반 피해 계산 |
| `relic_armor_fragment` 갑주 파편 | 현철 갑편 | 부대 방어력 +5% | 받는 피해의 방어 계산 |
| `relic_spear_inscription` 창술 비문 | 파진 창결 | 창병계 실효 적성 보정 +5% | 해당 병종 편성 시 |
| `relic_bow_inscription` 궁술 비문 | 신궁 비결 | 궁병계 실효 적성 보정 +5% | 해당 병종 편성 시 |
| `relic_horse_gear` 고대 마구 | 비호 마구 | 기병계 실효 적성 보정 +5% | 해당 병종 편성 시 |
| `relic_siege_plan` 공성 도면 | 천공 도면 | 공성계 실효 적성 보정 +5% | 해당 병종 편성 시 |
| `relic_granary_record` 곡창 장부 | 풍년의 장부 | 군량 생산량 +5% | 내정 담당/생산 주최 시 |
| `relic_mint_record` 주조 장부 | 황금의 장부 | 금 생산량 +5% | 내정 담당/생산 주최 시 |
| `relic_drill_manual` 조련 비서 | 정예 조련서 | 병력 생산량 +5% | 병력 담당 시 |
| `relic_guardian_seal` 수호 인장 | 태평 수호인 | 치안 증가량 +5% | 치안 담당 시; 최종 정수 반올림 규칙 검증 필요 |

모든 유물은 독립 코드와 데이터를 갖고, 효과 값·대상 병종은 [`data/ancient-relics.json`](../data/ancient-relics.json)으로 관리한다. 수치 `+5%`는 해당 공식의 **양의 산출/보정량**에 곱한다. 방어 효과는 피해량에서 5%를 직접 빼지 않고 방어 배수 105%로 계산한다. 치안은 정수 절삭분을 도시별로 누적해 평균 +5%를 유지하며 최소 +1을 강제하지 않는다.

## 데이터·처리·화면

- Core에 단서 종류 코드, 세력별 잔여 수량, 소비/지급 이력을 정의한다. 기존 `ExplorationDiscovery.Code == ancient_relic_clue` 판정은 유지하되 **별도 단서 종류 코드**를 실어 결과와 저장 데이터에서 구분한다. 유물 정의는 `data/`의 새 JSON으로 로드하며 Godot에 규칙을 두지 않는다.
- 탐색 결과가 확정되는 단일 Core 처리에서 단서 추가와 2개 소비, 유물 인스턴스 발급을 원자적으로 수행한다. 7일 진행의 화면 재생/로드/보고 재생으로 중복 지급되지 않도록 탐색 결과 고유 ID를 저장하고 처리 여부를 검사한다. 아이템 ID도 그 결과 ID와 획득 순서로 결정론적으로 만든다.
- 구버전 저장의 종류 없는 `ancient_relic_clue`는 없애지 않고 `미분류 단서`로 표시한다. 신규 10종 카운트에는 자동 혼합하지 않는다. 기존 미분류 단서 2개는 보관함의 1회 선택 UI에서 원하는 유물 종류로 전환하고 소모한다. 단서 1개는 그대로 남는다. 마이그레이션은 저장→불러오기 반복에도 한 번만 일어나야 한다.
- `단서·보물 보관함`에 10종 카드(보유 `0/2` 또는 `1/2`, 획득 유물 수, 최근 발견 도시/날짜)를 표시한다. `획득 보물`에는 신수 보물과 유물을 함께 보이되 출처를 구분한다. 장수 정보의 장착 화면에서도 이름·효과·조건·장착 여부가 보여야 한다.
- 유물 이미지가 아직 없을 때는 **유형별 공용 자리표시 아이콘**을 사용하고 레이아웃 크기를 고정한다. 나중에 사용자가 이미지를 주면 유물 코드별 파일명/매핑을 확정해 교체한다. 이미지 부재가 아이템 지급·장착·저장을 막아서는 안 된다.
