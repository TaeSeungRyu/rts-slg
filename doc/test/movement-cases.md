# 이동 시뮬레이션 GUI 검증 케이스 (2026-08-07 작성 — 다음 작업)

> 목적: [design-movement.md](../design-movement.md)의 확정 규칙(일 단위 동시 진행·탐지·
> 추격·모드·자동 교전)을 **2~3개 부대가 적군과 조우하는 상황**으로 실제 GUI에서
> 눈으로 확인한다. 전투 수치는 [design-combat.md](../design-combat.md).

## 선행 구현물 (케이스를 돌리기 위해 필요한 것)

현재 샌드박스는 유닛 1기 자유 클릭 이동뿐이다. 케이스 실행에는 다음이 필요하다:

1. **다중 부대** — 아군 2~3개 + 적군 1~2개를 맵에 배치(세력색으로 구분)
2. **일 단위 진행** — "진행" 버튼: 하루씩(최대 7일) 전 부대가 속도만큼 동시 이동.
   Core에 일 진행기(스텝 판정 포함)가 있어야 한다 — 이것이 이 작업의 본체
3. **명령: 목표 지정 + 모드**(행군/공격) — 목표는 유지되고 경로가 계속 표시된다
4. **탐지·추격·사거리 정지** — Core 판정 + GUI 표시(탐지 범위 원, 추격 대상 강조 등)
5. 적군은 이동 명령을 미리 심어둔 스크립트로 충분(AI 불필요)

## 공통 표기

- `A1, A2, A3` = 아군 부대 / `E1, E2` = 적군 부대. 괄호는 (병종, 속도, 탐지, 모드)
- 속도·탐지 값은 [spec-unit.md](../spec-unit.md) 카탈로그를 그대로 쓴다
- "확인 포인트"가 GUI에서 눈으로 검증할 항목이다

## 케이스 1 — 공격모드 조우: 탐지 → 추격 → 사거리 정지 ✅ 구현됨(2026-08-08)

가장 기본이 되는 조우. 규칙: 탐지에 걸리면 목표를 버리고 추격, 사거리에 닿으면 정지.

- 구현: Core `MovementSimulator`(일 진행기) + xUnit(`MovementSimulatorTests`),
  GUI 하베스트 `MovementTestScene3D`(`--movetest` 플래그, `run-movetest.bat`).
  "진행 ▶" 버튼으로 스텝을 하나씩 재생하고 탐지·추격·정지 사건을 로그로 표시

- 배치: A1(도검병, 2, 2, **공격**) 서쪽 끝. E1(도검병, 2, 2, 정지 명령 없음) 동쪽으로 8칸 거리
- 명령: A1의 목표를 E1 너머 동쪽 끝 타일로 지정 → 진행
- 기대: A1이 동진 → E1이 탐지 범위(2)에 들어오는 날 **추격으로 전환**(경로가 E1을
  향해 다시 그려짐) → 사거리(1)에 닿으면 **이동 종료 + 진행 중단** → 전투 페이즈
- 확인 포인트: ① 경로가 원래 목표에서 E1로 바뀌는 순간 ② 인접 칸에서 멈추는지
  (지나치거나 겹치지 않는지) ③ 진행이 그 날에 멈추는지

## 케이스 2 — 행군모드 통과: 무시 + 감속 + 일방 피해 ✅ 이동 규칙 구현됨(2026-08-08)

- 구현: 이동 규칙(무시·감속·통과)은 `MovementSimulator` + xUnit(케이스2 2건),
  GUI는 `--movetest`의 "케이스 ▶▶"로 전환. **일방 피해(70%)는 전투 페이즈 소관이라
  아직 미구현** — GUI는 사거리 통과 시점만 로그로 표시한다
- 배치: A1(기병, 3, 3, **행군**) 서쪽. E1(궁병, 2, 2, 정지) 경로 중간 옆 1칸
- 명령: A1 목표 = E1 옆을 스쳐 지나는 동쪽 끝 → 진행
- 기대: A1은 E1을 **무시하고 계속** 가되, E1의 탐지 범위 안에 있는 날은 속도
  3 → **2**로 감속. E1 사거리 안을 지나는 동안 전투 페이즈마다 **A1이 70% 피해를
  일방으로 받음**(반격 없음)
- 확인 포인트: ① 감속 구간에서 하루 이동 칸수가 줄어드는지 ② A1이 멈추지 않는지
  ③ 피해가 행군 배수(70%)로 들어가고 반격이 없는지

## 케이스 3 — 정면 자동 교전: 같은 칸 경합과 자리 맞바꾸기 ✅ 구현됨(2026-08-08)

- 구현: `MovementSimulator`(같은 칸 경합·자리 맞바꾸기 고정점 해석) + xUnit(3a·3b),
  GUI는 `--movetest` "케이스 ▶▶"의 3번(3a 같은 칸 경합).
- **설계 확정**: 사거리 진입 정지(EnemyInRange)는 이동 해석보다 **먼저** 판정한다
  — 그래야 케이스1에서 공격 유닛이 정지한 적 칸으로 걸어 들어가 겹치지 않는다.
  그 결과 3a(거리 2에서 가운데 칸 경합)는 사거리(1) 밖이라 깨끗한 자동 교전이 되고,
  3b(사거리≥1 인접 맞바꾸기)는 인접=사거리 안이라 EnemyInRange로 멈춰 전투에 들어간다
  (결과는 같음 — 둘 다 그 자리에서 싸운다). 순수 맞바꾸기 교전 경로는 사거리 0에서만 발동.

- 3a 배치: A1(도검병, 공격)과 E1(도검병, 공격)이 5칸 거리에서 **서로를 향해** 이동
  (홀수 거리라 중간 칸을 동시에 노리는 스텝이 생긴다)
- 3a 기대: 같은 칸을 둘 다 노린 스텝에서 **아무도 못 들어가고 자동 교전**
- 3b 배치: A1과 E1이 **인접**한 상태에서 서로의 칸으로 이동 명령(자리 맞바꾸기)
- 3b 기대: 맞바꾸기 = 정면 충돌 → **자동 교전**
- 확인 포인트: ① 두 부대가 겹치거나 스쳐 지나가지 않는지 ② 교전 발동이 사거리
  진입보다 우선 처리되는지 ③ 행군모드로 같은 상황이면 교전은 벌어지되 행군 쪽이
  공격·반격 없이 맞기만 하는지(3a를 행군으로 재실행)

## 케이스 4 — 연쇄 이동은 성립: a→b, b→c

- 배치: A1(도검병, **공격**)이 E1(도검병, **행군**)의 칸으로, E1은 다른 칸으로 이동
- 기대: 둘 다 이동 **성립**(충돌 아님). 이동 후 A1 사거리 안에 E1이 있으면 진행이
  멈추고 **A1만 공격, E1은 반격 못 하고 70% 피해**
- 확인 포인트: ① E1이 비운 칸에 A1이 정상 진입 ② 전투가 "이동 후 위치" 기준으로
  판정되는지

## 케이스 5 — 다대일 조우: 2개 부대가 하나를 협격

전투 규칙([design-combat.md](../design-combat.md) 야전 다대일)의 GUI 검증.

- 배치: A1(도검병, 공격, **명령 순번 1**), A2(궁병, 공격, **명령 순번 2**)가
  양쪽에서 E1(도검병, 정지)을 향해 이동
- 기대: 둘 다 사거리에 닿으면 정지 → 전투 페이즈에서 E1의 공격이 **A1(주대상,
  명령 순번 빠름) 100% + A2 60%**로 들어가고, A1·A2는 각자 100%를 E1에게 준다
- 확인 포인트: ① 주대상이 명령 순번을 따르는지 ② 피해 수치가 100%/60% 비율인지
  ③ (연장) A1이 전멸하면 다음 라운드 주대상이 A2로 승계되는지

## 케이스 6 — 추격 중단: 시야를 잃으면 원래 목표로 복귀

- 배치: A1(도검병, 2, 2, 공격) 목표 = 동쪽 끝. E1(기병, 3, 3, 행군)이 잠깐
  A1의 탐지에 걸렸다가 빠르게 이탈하는 경로로 스침
- 기대: A1이 추격으로 전환 → E1이 탐지 범위를 벗어나면 **추격을 버리고 원래
  목표로 복귀**(경로가 되돌아감)
- 확인 포인트: ① 추격 중 매일 경로 재계산 ② 복귀 시 원래 목표가 보존되어 있는지

## 케이스 7 — 탐지 동률: 가장 가깝고, 같으면 명령 순번

- 배치: A1(도검병, 공격) 기준 같은 거리(2칸)에 E1·E2를 배치. E1을 먼저,
  E2를 나중에 이동 명령
- 기대: A1은 **E1**(명령 순번이 빠른 쪽)을 추격
- 확인 포인트: 추격 대상 표시가 E1인지. E1을 1칸 멀리 옮기면 E2로 바뀌는지

## 케이스 8 — 아군 경합·막힘: 교전 없음 + 3일 정지 알림

- 배치: A1·A2(아군끼리)가 같은 칸을 노리도록, 그리고 A3의 외길을 A1이 막고
  서 있도록 배치
- 기대: 아군 경합은 교전 없이 다음 스텝 재시도. A3가 **3일 연속 한 칸도 못 가면
  진행이 멈추고 알림**(목표는 유지)
- 확인 포인트: ① 아군끼리 교전이 절대 발동하지 않는지 ② 3일 정지 알림 시점

## 구현 순서 제안

1. Core: 일 진행기(스텝 동시 판정·경합·교전 발동) + xUnit — 케이스 1·3·4가 그대로 테스트가 된다
2. Game: 다중 부대 배치 + 진행 버튼 + 모드 토글 + 탐지/추격 표시
3. 케이스 1부터 순서대로 GUI 확인 — 케이스마다 배치를 코드로 심은 시나리오 전환
   (키 입력으로 케이스 선택)이 편하다
