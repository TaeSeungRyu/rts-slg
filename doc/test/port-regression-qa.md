# 항구 입항·모델 회귀 검증 (2026-09-16)

## 원인과 수정

- 실제 로그: 좌중성 수송부대가 `(-5,0)`에서 목표 위중항 `(-6,-2)`로 이동하지 못했다.
- 경로 탐색은 목표 중심만 통행 예외로 두었다. 중형 항구는 육지 쪽 점유 타일에 막혀 중심까지 경로를 만들 수 없었다. 목표 도시의 점유 타일을 경로 탐색에 포함하고, 첫 아군 점유 타일 진입 시 기존 입성 처리를 실행한다. 적 도시 점유 타일에는 진입하지 않는다.
- 지도 지형의 `PortSmall` 모델과 도시 항구 모델이 중복 생성됐다. 캠페인의 도시 항구 위치에서는 지형 바닥만 만들고, 물 방향으로 회전한 도시 모델 하나만 표시한다.

## 실행한 QA

- 해안 지형의 소형·중형 항구에 수송 2개 연속 입항: 수정 전 중형 실패를 재현, 수정 후 둘 다 통과.
- Core Simulation 및 PassabilityMap 테스트: 679개 통과.
- Game 빌드: 오류·경고 0개.
- `PortRegressionQa.tscn`: 실제 테스트 지도 아군 성 5곳 → 소형·중형 항구의 10개 수송 경로 통과. 실제 GLB 잔교 메시 방향과 인접 물 방향 일치 확인, 지형 잔교 중복 0개 확인.
- `scenes/CastleEntryQa.tscn`: 입성·애니메이션 81개, 출격 216개 통과.
- 전체 Core 테스트: 785개 통과, 이번 변경이 건드리지 않은 데이터 검증 3개 실패. 항구 타일을 평야로 요구하는 검사, 시나리오 중형 항구 지물과 도시의 중첩 검사, 을지문덕 수성 적성 S 상한 검사다. 사용자 편집 데이터는 보존했다.

## 재실행

Game 프로젝트 빌드 후 Godot Mono로 실행:

```text
--headless --path SanguoSLG.Game --scene res://PortRegressionQa.tscn
--headless --path SanguoSLG.Game --scene res://scenes/CastleEntryQa.tscn
```

화면의 최종 모습은 `run-maptest.bat`에서 확인한다. 위 방향 검사는 수치 검증이며 스크린샷 육안 검증은 수행하지 않았다.
