# 설계 노트 — 이동 체계 (2026-08-06)

> 동시 명령 → 동시 실행 방식의 턴 진행 설계.
> 병종별 이동력·사거리·통행 지형은 [design-unit.md](./design-unit.md) 참조.
> 파일명은 기존 문서 규약(`design-*.md`)에 맞췄다.

## 확정 규칙

### 턴 진행

| 단계 | 내용 |
|---|---|
| **1. 명령** | 유닛마다 목적지를 지정한다. 적을 클릭하면 "그 적을 치러 간다"는 뜻이 되고, 목적지는 그 적에 인접한 칸이 된다 |
| **2. 이동** | "진행"을 누르면 전원이 동시에, 스텝 단위로 움직인다. **이동 중에는 전투가 일어나지 않는다** |
| **3. 전투** | 이동이 모두 끝난 뒤, 사거리 안에 적이 있는 유닛이 **동시에** 공격한다. 피해는 일괄 적용 |
| **4. 정리** | 전멸한 부대를 제거하고 다음 턴으로 |

### 이동 규칙

1. 유닛은 병종 이동력만큼의 스텝을 갖는다([design-unit.md](./design-unit.md) 참조, 현재 2~5).
2. 스텝마다 전 유닛의 다음 칸을 **동시에** 확정한다.
3. **같은 칸을 둘 이상이 노리면 아무도 들어가지 못한다.** 막힌 유닛은 그 스텝을 제자리에서
   보내고 **다음 스텝에 같은 칸을 다시 노린다.** 남은 이동력을 버리지 않는다.
4. 경로는 명령 시점에 한 번만 계산한다. 막혔다고 다시 계산하지 않는다.
5. **정면 교차(자리 맞바꾸기)는 충돌이 아니다.** 그대로 지나간다.
6. 명령이 없는 유닛은 제자리에 있는다.

### 전투 규칙

1. 이동이 전부 끝난 뒤에 판정한다.
2. 사거리 안에 적이 있으면 공격한다. 사거리는 대상에 따라 다르다
   (`range_unit` / `range_building` / `range_castle`).
3. 전 유닛이 동시에 공격하고, 피해는 일괄 적용한다. 먼저 친 쪽이 이득을 보지 않는다.

## 이 구조로 정한 이유 (기록)

처음에는 "부딪히면 공격 / 부딪히면 이동 불가 / 기병은 -1만큼 통과"를 스텝 단위 충돌 판정으로
옮기려 했다. 규칙을 하나 확정할 때마다 경계 사례가 **줄지 않고 늘었다**.

- 한 턴에 두 번 부딪힌 기병의 이동력은 5 → 3인가 4인가
- 통과하면서 공격도 하는가
- 이동 중 죽은 유닛이 비운 칸에 뒤 유닛이 들어갈 수 있는가
- 통과한 칸에 또 적이 있으면

그리고 더 근본적인 모순이 있었다. **사거리를 이미 정의해 뒀는데(궁병 2, 투석기 3, 대궁병 3)
"부딪히면 공격"은 그것과 어긋난다.** 궁병이 적과 몸을 부딪혀야 화살을 쏜다는 규칙이 된다.

원인은 규칙이 부족해서가 아니라 **이동과 전투를 같은 페이즈에 섞었기 때문**이었다.
페이즈를 나누자 위 경계 사례가 전부 사라졌다 — 이동 중 아무도 죽지 않으므로 물어볼 것이 없다.

### 얻은 것

- **사거리 체계가 그대로 산다.** 궁병은 부딪힐 필요 없이 2칸 밖에서 쏜다
- **결과가 읽힌다.** 이동이 끝난 화면을 보고 누가 누구 사거리 안에 있는지 눈으로 셀 수 있다
- **연출이 좋아진다.** 느린 유닛을 기다리는 시간차가 **전투 직전의 뜸**이 된다.
  다 모인 뒤 전 부대가 동시에 교전하는 그림이 나온다
- **구현이 반으로 준다.** 이동 해석기는 순수 위치 문제, 전투 해석기는 순수 사거리 문제.
  각각 따로 테스트할 수 있다(CLAUDE.md 규칙 2)

### 최초 규칙(원문)과의 대응

> 1. 모든 유닛이 클릭을 통해 이동할 방향을 정한다.
> 2. 정하든 정하지 않든 "진행" 버튼을 누르면 동시에 유닛들이 움직인다.
> 3. 이때 아군이 아닌 유닛끼리 부딪히면 자동으로 공격이 된다.
> 4. 유닛이 부딪히면 이동이 불가능하다.
> 5. 유닛이 부딪히지만 기병은 원래 가는 방향 -1만큼 이동이 가능하다.
> 6. 모든 유닛은 적 유닛을 누르면 해당 방향으로 이동하되 적을 공격하고 기병이더라도 통과하지 않는다.

| 원문 | 확정안 |
|---|---|
| 1·2 (동시 명령·동시 실행) | **그대로.** 핵심 의도 |
| 3 (부딪히면 자동 공격) | **전투 페이즈로.** 기준이 "부딪힘" → "사거리 안". 사거리 1인 병종은 결과가 사실상 같다 |
| 4 (부딪히면 이동 불가) | **유지.** 단 그 스텝만 실패하고 다음 스텝에 재시도 |
| 5 (기병은 -1만큼 통과) | **제거.** 특기(`Skill`) 후보로 미룸 — 아래 참조 |
| 6 (적을 누르면 공격 이동) | **그대로.** 목적지가 "그 적에 인접한 칸"이 된다 |

### 기병 관통을 뺀 이유

- 경계 사례를 가장 많이 만드는 규칙이었다(위 참조)
- 기병은 **이동력 5** 자체로 이미 기동력 우위가 확실하다. 최저 병종의 2.5배다
- 적진을 뚫고 지나가는 것은 강력한 능력이라, 기본 규칙보다 **특기**로 두는 편이 낫다.
  기본 규칙에 넣으면 나중에 밸런스가 무너져도 되돌리기 어렵다

기병의 강점은 이동력과, 이후 전투 공식의 돌격 보정으로 준다.

## 남은 미결

1. **전투 대상 선택** — 사거리 안에 적이 여럿이면 누구를 치는가.
   명령이 공격 이동이었다면 그 대상, 아니면 가장 가까운 적? 자동 선택 규칙이 필요하다
2. **반격** — 맞은 쪽도 같은 페이즈에 되받아치는가.
   사거리 3인 투석기를 사거리 1인 도검병이 때렸을 때 투석기가 반격할 수 있는가
3. **공격 모션의 실제 위치** — 공격 시 앞으로 나가는 모션은 이미 있다.
   실제 좌표는 그대로 두고 연출만 나가는 것으로 본다. 확인 필요
4. **피해 공식** — 밸런스 영역. 별도 문서 예정

## 구현 순서

1. **Core: 이동 해석기** — 명령 목록 → 스텝 시퀀스. 충돌은 재시도. 테스트 필수
2. **Core: 통행 판정 A\*** — 병종별 지형([design-unit.md](./design-unit.md) 통행 규칙 연결)
3. **Core: 전투 해석기** — 사거리 판정과 대상 선택. 피해 공식은 별도
4. **Game: 스텝 재생기** — 스텝 단위 트윈. 이동이 끝나면 전투 모션
5. **Game: 대기 모션(idle)** — 아래 참조
6. **Game: "진행" 버튼과 명령 미리보기 UI**

Core는 스텝 시퀀스만 만들고 Game은 **재생**만 한다. 이 분리가 되어야 화면 없이
Sandbox에서 같은 결과가 나온다(CLAUDE.md 규칙 4 결정론).

### 대기 모션에 대해

이동 페이즈에서 먼저 도착한 유닛이 **조각상처럼 굳어 있으면 버그처럼 보인다.** 정지 자체는
문제가 아니다 — 얼어붙는 것이 문제다. 숨쉬기·무기 고쳐잡기 정도의 미세 모션이면 충분하다.
편대원마다 위상을 흩는 것은 행군 모션에서 쓰던 방식 그대로 쓰면 된다.

걸음 주기가 이동 거리에 물려 있어(`UnitController3D.MarchRadiansPerUnit`) 멈추면 다리는
자연스럽게 선다. 그 위에 idle만 얹으면 된다.
