# 설계 노트 — 이동 체계 (2026-08-06)

> 동시 명령 → 동시 실행 방식의 턴 진행 설계.
> 병종별 이동력·사거리·통행 지형은 [design-unit.md](./design-unit.md) 참조.
>
> ⚠️ **2차 재설계안 — 확정 대기.** 1차 확정안(페이즈 분리 + 부대 모드)에서
> ZOC 도입·이동력 압축·이동 예약을 더한 것이다. 승인 전까지 구현하지 않는다.
> 채택하면 `data/troop-types.json`의 이동력 19개를 전부 다시 잡아야 한다.

## 1차 안에 남아 있던 문제

페이즈를 나누고 모드를 넣어 경계 사례는 정리됐지만, 셋이 남았다.

1. **전선이 없다.** 유닛들이 서로를 통과하듯 스쳐 지나간다. 적 부대 옆을 그냥 지나
   후방 도시로 들어갈 수 있다. 진형·측면·우회 같은 것이 성립하지 않는다.
2. **시간차가 여전하다.** 이동력 2~5는 2.5배 차이다. 가려놨을 뿐 사라지지 않았다.
3. **한 턴 5칸은 너무 크다.** 맵 20×14에서 5칸이면 맵의 1/4을 가로지른다.
   플레이어가 동시 이동의 결과를 5칸 앞까지 내다봐야 해서 예측이 불가능하다.

셋 다 원인이 같다. **이동이 다른 유닛의 존재를 무시한다.**

## 재설계안

### 1. ZOC(교전 지역)을 도입한다

**적 유닛에 인접한 칸에 들어가면 그 턴의 이동이 거기서 끝난다.**

- 최초 규칙 4("유닛이 부딪히면 이동이 불가능하다")의 의도를 제대로 구현한 것이다.
  "부딪힘"을 같은 칸 경합이 아니라 **적 앞에 닿는 것**으로 읽는다
- 전선이 생긴다. 뚫으려면 밀어내야 하고, 돌아가려면 대가를 치른다
- 이동력이 큰 유닛도 적 앞에서 멈추므로 **실제 스텝 수가 줄어 시간차가 저절로 준다**

### 2. 모드의 의미를 ZOC으로 다시 정의한다

이동력을 깎고 더하는 대신, **ZOC에 어떻게 반응하는가**로 모드를 가른다.

| | 행군모드 | 공격모드 |
|---|---|---|
| ZOC | **무시하고 계속 간다** | 걸리면 그 자리에서 멈춘다 |
| 이동력 | 병종 이동력 그대로 | 병종 이동력 그대로 |
| 전투 페이즈 | 공격하지 않는다 | 사거리 안의 적을 공격한다 |
| 반격 | 못 한다 | 한다 |
| 피해 | **크게 받는다** | 정상 |

행군 대열이 적 옆을 지나가면 얻어맞는다 — 대신 지나갈 수는 있다.
빠르게 통과할 것인가, 전선을 세울 것인가. 이동력 숫자를 건드리지 않고 선택이 생긴다.

> **최초 규칙 5(기병 관통)가 여기서 되살아난다.** 기병만의 특권이 아니라
> 모든 병종이 큰 피해를 감수하면 통과할 수 있는 일반 규칙이 됐다.
> 특기로 미뤄뒀던 것을 기본 규칙으로 되돌린다.

### 3. 이동력을 1~3으로 압축한다

2~5의 2.5배 폭이 시간차·예측 불가·밸런싱 난이도를 전부 만든다.
병종 차이는 이미 **사거리(1~3)** 와 **통행 지형**이라는 두 축으로 충분히 표현된다.

| 이동력 | 병종 | 기존 |
|---|---|---|
| 1 | `ThunderCart` `Catapult` `SiegeTower` | 2 |
| 2 | `Swordsman` `Archer` `Pikeman` `Scytheman` `Shieldbearer` `GreatBow` `Axeman` `WarElephant` `MediumShip` `LargeShip` `Panokseon` `Turtleship` | 2~3 |
| 3 | `Cavalry` `Lancer` `HorseArcher` `SmallBoat` | 4~5 |

- 스텝 차이가 최대 **2**로 준다(기존 3)
- `Axeman`의 산악 진입 제한 1은 그대로 — 이동력 2에서 1로 주는 것도 여전히 의미가 있다
- 기병은 보병의 1.5배. 여기에 ZOC 무시 행군까지 더하면 기동력 우위는 충분하다

### 4. 여러 턴에 걸친 이동 예약

이동력이 줄었으니 목적지가 멀면 여러 턴이 걸린다. 매 턴 다시 명령하게 하면 손이 아프다.

- 목적지를 찍으면 **도착할 때까지 턴마다 자동으로 진행**한다
- 언제든 새 명령으로 덮어쓸 수 있다
- 적을 만나 ZOC에 걸리면 예약은 취소되고 플레이어에게 판단을 넘긴다

## 유지하는 것 (1차 확정안에서)

### 턴 진행

| 단계 | 내용 |
|---|---|
| **1. 명령** | 유닛마다 모드(행군/공격)와 목적지를 지정한다. 적을 클릭하면 공격 이동이 되고 자동으로 공격모드가 된다 |
| **2. 이동** | 전원이 동시에, 스텝 단위로 움직인다. **이동 중에는 전투가 일어나지 않는다** |
| **3. 전투** | 이동이 끝난 뒤, 공격모드 유닛이 사거리 안의 적을 **동시에** 공격한다. 피해는 일괄 적용 |
| **4. 정리** | 전멸한 부대를 제거하고 다음 턴으로 |

### 이동 규칙

1. 스텝마다 전 유닛의 다음 칸을 **동시에** 확정한다.
2. **같은 칸을 둘 이상이 노리면 아무도 들어가지 못한다.** 막힌 유닛은 다음 스텝에 다시 노린다.
   남은 이동력을 버리지 않는다.
3. 경로는 명령 시점에 한 번만 계산한다.
4. **정면 교차(자리 맞바꾸기)는 충돌이 아니다.** 그대로 지나간다.
5. 명령이 없는 유닛은 제자리에 있는다.

### 전투 규칙

1. 이동이 전부 끝난 뒤에 판정한다.
2. **공격모드인 유닛만** 공격한다. 사거리는 대상에 따라 다르다
   (`range_unit` / `range_building` / `range_castle`).
3. 전 유닛이 동시에 공격하고 피해는 일괄 적용한다. 먼저 친 쪽이 이득을 보지 않는다.
4. 행군모드 유닛은 공격도 반격도 하지 않고, 맞을 때 피해를 더 받는다.

## 왜 이 구조인가 (기록)

### 1차 시도 — 스텝마다 충돌 판정

최초 규칙 3~6을 그대로 스텝 단위 충돌로 옮기려 했다. 규칙을 확정할 때마다 경계 사례가
**줄지 않고 늘었다**(기병 관통 누적 여부, 통과 중 공격 여부, 죽은 유닛이 비운 칸).
근본적으로는 이미 정의한 사거리 체계와 모순됐다 — 사거리 2인 궁병이 몸을 부딪혀야 쏘는 규칙.

원인은 **이동과 전투를 같은 페이즈에 섞은 것**이었다. 페이즈를 나누자 전부 사라졌다.

### 2차 시도 — 부대 모드

모드가 들어오면서 반격·대상 선택이 규칙에서 자동으로 풀렸고, 무엇보다
**플레이어가 의도를 표현할 수단**이 생겼다. 모드가 없으면 사거리에 든 유닛이 무조건 싸우므로
교전을 피하는 선택 자체가 불가능하다.

다만 이때의 모드는 이동력을 ±1 하는 것이어서, 병종 이동력과 뒤엉켜 밸런싱이 어려웠다.

### 3차 — ZOC

ZOC이 들어오자 세 가지가 동시에 정리됐다.

- 모드가 **이동력을 건드리지 않고** 갈린다(ZOC 반응으로)
- 최초 규칙 4·5의 의도가 자연스럽게 복원된다
- 이동력을 압축해도 기동력 차이가 죽지 않는다 — ZOC 무시 행군이 있으므로

### 최초 규칙(원문)과의 대응

> 1. 모든 유닛이 클릭을 통해 이동할 방향을 정한다.
> 2. 정하든 정하지 않든 "진행" 버튼을 누르면 동시에 유닛들이 움직인다.
> 3. 이때 아군이 아닌 유닛끼리 부딪히면 자동으로 공격이 된다.
> 4. 유닛이 부딪히면 이동이 불가능하다.
> 5. 유닛이 부딪히지만 기병은 원래 가는 방향 -1만큼 이동이 가능하다.
> 6. 모든 유닛은 적 유닛을 누르면 해당 방향으로 이동하되 적을 공격하고 기병이더라도 통과하지 않는다.

| 원문 | 재설계안 |
|---|---|
| 1·2 | **그대로.** 핵심 의도 |
| 3 (부딪히면 공격) | 전투 페이즈로. 기준이 "부딪힘" → "사거리 안" |
| 4 (부딪히면 이동 불가) | **ZOC으로 복원.** 적 인접 칸에 닿으면 이동 종료 |
| 5 (기병은 통과) | **행군모드로 복원.** 기병 전용이 아니라 전 병종 공통, 대가는 피해 |
| 6 (적을 누르면 공격 이동) | **그대로.** 자동으로 공격모드 |

## 남은 미결

1. **ZOC 세부** — 아군 ZOC도 있는가(없는 쪽을 권한다). ZOC에서 ZOC으로 바로 이동할 수 있는가
2. **행군모드 피해 배수** — 밸런스 영역
3. **대상이 여럿일 때의 동률** — 가장 가까운 적이 둘 이상이면.
   결정론을 위해 순서 규칙이 필요하다(유닛 ID 순 등)
4. **공격 모션의 실제 위치** — 연출만 앞으로 나가고 좌표는 그대로인 것으로 본다. 확인 필요
5. **피해 공식** — 밸런스 영역. 별도 문서 예정

## 구현 순서

1. **Core: 이동 해석기** — 명령 목록 → 스텝 시퀀스. ZOC 판정, 충돌 재시도. 테스트 필수
2. **Core: 통행 판정 A\*** — 병종별 지형([design-unit.md](./design-unit.md) 통행 규칙 연결)
3. **Core: 전투 해석기** — 사거리 판정과 대상 선택. 피해 공식은 별도
4. **Game: 스텝 재생기** — 스텝 단위 트윈. 이동이 끝나면 전투 모션
5. **Game: 대기 모션(idle)** — 아래 참조
6. **Game: 모드 전환·"진행" 버튼·명령 미리보기 UI**

Core는 스텝 시퀀스만 만들고 Game은 **재생**만 한다. 이 분리가 되어야 화면 없이
Sandbox에서 같은 결과가 나온다(CLAUDE.md 규칙 4 결정론).

### 대기 모션에 대해

이동 페이즈에서 먼저 도착한 유닛이 **조각상처럼 굳어 있으면 버그처럼 보인다.** 정지 자체는
문제가 아니다 — 얼어붙는 것이 문제다. 숨쉬기·무기 고쳐잡기 정도의 미세 모션이면 충분하다.
편대원마다 위상을 흩는 것은 행군 모션에서 쓰던 방식 그대로 쓰면 된다.

걸음 주기가 이동 거리에 물려 있어(`UnitController3D.MarchRadiansPerUnit`) 멈추면 다리는
자연스럽게 선다. 그 위에 idle만 얹으면 된다.
