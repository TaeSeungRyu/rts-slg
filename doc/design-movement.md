# 설계 노트 — 이동 체계 (2026-08-06)

> 동시 명령 → 동시 실행 방식의 턴 진행 설계.
> 병종별 이동력·사거리·통행 지형은 [design-unit.md](./design-unit.md) 참조.
> 파일명은 기존 문서 규약(`design-*.md`)에 맞췄다.

## 사용자 정의 규칙 (원문, 2026-08-06)

1. 모든 유닛이 클릭을 통해 이동할 방향을 정한다.
2. 정하든 정하지 않든 "진행" 버튼을 누르면 동시에 유닛들이 움직인다.
3. 이때 아군이 아닌 유닛끼리 부딪히면 자동으로 공격이 된다.
4. 유닛이 부딪히면 이동이 불가능하다.
5. 유닛이 부딪히지만 기병은 원래 가는 방향 -1만큼 이동이 가능하다.
6. 모든 유닛은 적 유닛을 누르면 해당 방향으로 이동하되 적을 공격하고 기병이더라도 통과하지 않는다.

핵심 의도는 **1·2번**이다. "동시에 명령하고 한 번에 움직인다." 3~6번은 그것을 위해 붙인 세부 규칙이다.

## 현재 이동력 분포

| 이동력 | 병종 |
|---|---|
| 2 | `ThunderCart` `Catapult` `SiegeTower` `Shieldbearer` `GreatBow` |
| 3 | `Swordsman` `Archer` `WarElephant` `MediumShip` `LargeShip` `Pikeman` `Scytheman` `Axeman` `Panokseon` `Turtleship` |
| 4 | `SmallBoat` `Lancer` |

## 1차 안이 왜 막혔나 (기록)

처음에는 3~6번을 그대로 스텝 단위 충돌 판정으로 옮기려 했다. 규칙을 하나 확정할 때마다
경계 사례가 **줄지 않고 늘었다**.

- 한 턴에 두 번 부딪힌 기병의 이동력은 5 → 3인가 4인가
- 통과하면서 공격도 하는가
- 이동 중 죽은 유닛이 비운 칸에 뒤 유닛이 들어갈 수 있는가
- 통과한 칸에 또 적이 있으면

그리고 더 근본적인 모순이 있었다. **사거리를 이미 정의해 뒀는데(궁병 2, 투석기 3, 대궁병 3)
"부딪히면 공격"은 그것과 어긋난다.** 궁병이 적과 몸을 부딪혀야 화살을 쏜다는 규칙이 된다.

원인은 규칙이 부족해서가 아니라 **이동과 전투를 같은 페이즈에 섞었기 때문**이다.

## 추천안 — 이동 페이즈와 전투 페이즈를 나눈다

### 턴 진행

| 단계 | 내용 |
|---|---|
| **1. 명령** | 유닛마다 목적지를 지정한다. 적을 클릭하면 "그 적을 치러 간다"는 뜻이 된다(규칙 6) |
| **2. 이동** | 전원이 동시에, 스텝 단위로 움직인다. **이동 중에는 전투가 일어나지 않는다** |
| **3. 전투** | 이동이 모두 끝난 뒤, 사거리 안에 적이 있는 유닛이 **동시에** 공격한다. 피해는 일괄 적용 |
| **4. 정리** | 전멸한 부대를 제거하고 다음 턴으로 |

### 왜 이게 낫나

- **경계 사례가 통째로 사라진다.** 이동 중 아무도 죽지 않으므로 "죽은 유닛이 비운 칸",
  "누가 먼저 공격했나" 같은 문제가 존재하지 않는다.
- **사거리 체계가 그대로 산다.** 궁병은 부딪힐 필요 없이 2칸 밖에서 쏘고, 투석기는 3칸 밖에서
  때린다. 이미 정의한 `range_unit` / `range_building` / `range_castle`이 그대로 쓰인다.
- **읽히는 게임이 된다.** 이동이 끝난 화면을 보고 "누가 누구 사거리 안에 있는지"를 눈으로 셀 수 있다.
  이동 중에 산발적으로 전투가 터지면 플레이어는 무슨 일이 일어났는지 따라갈 수 없다.
- **연출이 좋아진다.** 원래 걱정하신 "느린 유닛은 멈춰 있는데 기병만 움직이는" 시간차가
  오히려 **전투 직전의 뜸**이 된다. 다 모인 뒤 전 부대가 동시에 교전하는 그림이 나온다.
- **구현이 반으로 준다.** 이동 해석기는 순수 위치 문제, 전투 해석기는 순수 사거리 문제가 된다.
  각각 따로 테스트할 수 있다(CLAUDE.md 규칙 2).

### 원래 규칙과의 대응

| 원문 | 추천안에서 |
|---|---|
| 1. 클릭으로 이동 방향 지정 | **그대로** |
| 2. "진행" 누르면 동시에 움직임 | **그대로** — 핵심 의도 |
| 3. 부딪히면 자동 공격 | **전투 페이즈로 옮김.** 기준이 "부딪힘"에서 "사거리 안"으로 바뀐다. 사거리 1인 병종은 결과가 거의 같다(인접해야 친다) |
| 4. 부딪히면 이동 불가 | **유지.** 단 그 스텝만 실패하고 다음 스텝에 다시 시도한다(아래) |
| 5. 기병은 -1만큼 통과 | **빼는 것을 권한다** (아래) |
| 6. 적을 누르면 공격 이동 | **그대로.** 목적지가 "그 적에 인접한 칸"이 된다 |

### 이동 충돌 — 막히면 그 스텝만 실패

두 유닛이 같은 칸을 노리면 **둘 다 못 들어간다**(사용자 확정 유지). 다만 남은 이동력을 버리지 않는다.

- 막힌 유닛은 그 스텝을 제자리에서 보내고, **다음 스텝에 같은 칸을 다시 노린다**
- 상대가 비켰으면 들어간다. 계속 막히면 결국 못 간다
- 경로를 다시 계산하지는 않는다 — 매 스텝 A*를 다시 돌리면 결정론 검증이 어려워지고 느리다

남은 이동력을 즉시 버리면 명령이 너무 자주 실패해 답답해진다. 이 방식이면 "잠깐 길이 막혔다가
뚫린다"가 자연스럽게 표현된다.

### 정면 교차 — 그냥 지나간다

자리를 맞바꾸는 것 자체는 충돌이 아니다(사용자 확정 유지). 전투는 어차피 이동이 끝난 뒤
사거리로 판정하므로, 스쳐 지나간 두 적이 서로의 사거리 안에 있으면 전투 페이즈에서 교전한다.
**공격 이동인지 따로 볼 필요가 없어진다.**

### 기병 관통(규칙 5)은 빼는 것을 권한다

빼자는 이유:

- 경계 사례를 가장 많이 만드는 규칙이다(위 "1차 안이 왜 막혔나" 참조)
- 기병은 **이동력 5** 자체로 이미 기동력 우위가 확실하다. 최저 병종의 2.5배다
- 적진을 뚫고 지나가는 것은 강력한 능력이라, 기본 규칙보다 **특기(`Skill`)**로 두는 편이 낫다.
  기본 규칙에 넣으면 나중에 밸런스가 무너져도 되돌리기 어렵다

기병의 강점은 이동력과, 이후 전투 공식에서의 돌격 보정으로 주는 것을 권한다.

## 남은 미결

추천안을 채택하면 아래만 정하면 된다. 1차 안의 미결 9건 중 6건은 페이즈 분리로 사라졌다.

1. **명령 없는 유닛** — 규칙 2의 "정하든 정하지 않든"은 제자리라는 뜻으로 읽었다. 확인 필요
2. **전투 페이즈의 대상 선택** — 사거리 안에 적이 여럿이면 누구를 치는가.
   명령이 공격 이동이었다면 그 대상, 아니면 가장 가까운 적? 자동 선택 규칙이 필요하다
3. **반격** — 맞은 쪽도 같은 페이즈에 되받아치는가. 사거리 3인 투석기를 사거리 1인 도검병이
   때렸을 때 투석기가 반격할 수 있는가
4. **전투 페이즈의 이동** — 공격할 때 유닛이 앞으로 나가는 모션은 이미 있다.
   실제 위치는 그대로 두고 연출만 나가는 것으로 본다. 확인 필요

1. **Core: 이동 해석기** — 명령 목록 → 스텝 시퀀스. 충돌은 재시도. 테스트 필수
2. **Core: 통행 판정 A\*** — 병종별 지형([design-unit.md](./design-unit.md) 통행 규칙 연결)
3. **Core: 전투 해석기** — 사거리 판정과 대상 선택. 피해 공식은 별도 영역
4. **Game: 스텝 재생기** — 스텝 단위 트윈. 이동이 끝나면 전투 모션
5. **Game: 대기 모션(idle)** — 먼저 도착한 유닛이 얼어붙지 않게. 아래 참조
6. **Game: "진행" 버튼과 명령 미리보기 UI**

### 대기 모션에 대해

이동 페이즈에서 먼저 도착한 유닛이 **조각상처럼 굳어 있으면 버그처럼 보인다.** 정지 자체는
문제가 아니다 — 얼어붙는 것이 문제다. 숨쉬기·무기 고쳐잡기 정도의 미세 모션이면 충분하다.
편대원마다 위상을 흩는 것은 행군 모션에서 쓰던 방식 그대로 쓰면 된다.

걸음 주기가 이동 거리에 물려 있어(`UnitController3D.MarchRadiansPerUnit`) 멈추면 다리는
자연스럽게 선다. 그 위에 idle만 얹으면 된다.
