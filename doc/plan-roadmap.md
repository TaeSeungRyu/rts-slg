## 🎯 현재 최우선 작업 — v2 전투 중심 전환

현재 구현은 삼국지 11/13식 복합 SLG 방향으로 충분히 커졌다. 이후 작업은 기능 추가보다 “전투 중심으로 줄이고 재배치”하는 것을 우선한다.

1. **문서 기준 정리** — `plan-roadmap.md`, `design-administration.md`, `design-ui.md`에 v2 우선 기준 표시.
2. **도시 UI 전투 중심 축소** — 세율·시장·모병·징병·건설·시설 업그레이드·충성 표시를 플레이 흐름에서 제거.
3. **자동 담당자 내정 4슬롯** — 치안/내정/병력/훈련 담당자를 지정하면 월말에 자동 성장.
4. **도시별 자동 생산 병종** — 모병·징병을 제거하고 도시 특색 병종이 자동 생산.
5. **보급부대 편성 UI 분리** — 기존 보급 시스템을 전투 핵심 선택으로 노출.
6. **탐색 재정의** — 미등록 장수·금·군량·이벤트 유닛·아이템 발견 기능.
7. **장수 성장/액티브 성장/이벤트 유닛** — 전투 결과가 성장과 보상으로 이어지게 한다.
8. **집단군 시스템** — 보병+궁병+공성 병기를 최대 40,000명 규모의 1개 월드맵 부대로 운용.

제거 확정: 인구, 세율, 시장, 모병/징병 구분, 충성, 급여, 배신, 포로교환, 도시 계략 “이간”, 시설 건설·업그레이드.

유지 확정: 전투, 공성, 보급, 병종 연구, 도시 계략(이간 제외), 탐색, 동맹/동맹파기, 논·밭·마을 시작 배치, 생산 작전.

### 🆕 집단군 시스템 (2026-09-03 사용자 정의)

전투 중심 v2의 대규모 부대 운용 기능으로 **집단군**을 추가한다.

확정 규칙:

- 보병 + 궁병 + 공성 병기를 하나의 집단군으로 편성한다.
- 공성 병기는 투석기 또는 벽력거 중 선택한다.
- 집단군 최대 총병력은 **40,000명**이다.
- 각 성은 **자신을 편성 원점으로 하는 집단군을 동시에 최대 1개만** 보유할 수 있다.
- 출전 중인 집단군도 원 소속 성의 1개 제한에 포함한다. 즉, 성 안에 없더라도 원점 성 기준 집단군이 살아 있으면 같은 성에서 새 집단군을 편성할 수 없다.
- 월드맵에서는 구성 병종 수와 관계없이 **1개 부대 / 1개 타일 점유**로 운용한다.
- 이동속도는 **1칸/일 고정**, 유닛/건물/성 공격 사거리는 모두 **1**이다.
- 유닛 대상 공격 능력은 성(城) 기준, 건물/성 대상 공격 능력과 방어 DF는 공성탑 기준을 참조한다.
- 집단군 편성 중에는 액티브 스킬이 발동하지 않는다.

구현 단계:

1. Core 집단군 도메인 모델 및 최대 병력 40,000 규칙
2. Core 집단군 성 단위 1개 제한 규칙
3. 보병/궁병/공성 병기 혼성 편성 검증
4. Deploy 계층에 집단군 편성/출전 명령 추가
5. 이동속도 1 및 사거리 1 고정 규칙 연결
6. Combat 계층에 집단군 전용 능력치 참조 규칙 연결
7. 액티브 스킬 발동 차단
8. Game 집단군 편성 UI
9. 월드맵 집단군 표시 방식
10. AI 집단군 편성·운용
11. Sandbox 밸런스 시뮬레이션 및 Core 테스트 잠금

밸런스 검증:

- 일반 10,000 부대와 집단군 40,000의 전투력 차이
- 다대일 전투에서 집단군의 생존력
- 성 인접 공격 시 반격을 받는 공성 밸런스
- 액티브 미발동 페널티가 대규모 병력 이점을 충분히 상쇄하는지
- 패시브 스킬 적용 유지 여부
- 내부 병종별 병력 비율 및 피해 배분 규칙

> **현황**: 출전 부대 명령 = **정보 · 이동(행군/전진/공격 + 경유지) · 정지** ✅, **계략 = 스텁('준비 중')** ❌.

> **발동 경로는 이미 구현**되어 있다(`AdvanceOrchestrator.FireStratagems` · `UnitCombatState.ReserveStratagem`/
> `AdvanceField` tick · `StratagemResource`/`Reservation`/`Mastery`/`Strength`). **비어 있는 건 "명령 페이즈에서
> 예약을 거는 진입점(seam) + UI"뿐이다.** 규칙 원본: [design-stratagem.md](./design-stratagem.md).

**Phase 1 — Core 시전 seam (+테스트) ✅ (2026-08-29)**
- `FieldStratagemService`(도시 명령의 `CommandService`에 대응):
  - `Castable(state, casterId)` — 지금 시전 가능한 계략(모략력 ≥ 비용 · 숙달 `CanCast` · 선봉 존재).
  - `Targets(state, casterId, code)` — 사거리(`stratagems.json`의 `range`) 안의 적 부대 목록(예약 시점 UI 게이트).
  - `Reserve(state, casterId, code, targetId)` — 검증 후 시전자 `UnitCombatState`에 예약 설정, 새 `GameState` 반환.
    컨펌 정보 노출: **발동일(+2)** · **비용(모략력)** · **예상 강도**(시전 선봉 지력 − 대상 선봉 지력).
- 결정론 유지(난수 없음). 발동 경로는 재사용. 공격 계략은 적군, 정화 계략은 아군 대상으로 분기하고
  예약 시점 지형 조건도 검증한다.
- 테스트 완료: 시전 가능 필터 · 선봉/중복 예약 게이트 · 적/아군 대상 분기 · 사거리/지형 게이트 · 예약 설정 ·
  모략력/숙달 부족 거부 · 컨펌 정보 · **예약 → `AdvanceWeek` 발동** 통합.

**Phase 2 — Game UI 배선(맵 씬)**
- 부대 정보 카드에 **모략력(Current/Max) · 숙달 레벨 · 예약(대상·발동일)** 추가.
- '계략' 버튼 → **계략 선택 모달**(시전 가능한 것만 · 비용 · 필요 숙달 · 사거리 · 설명) → **대상 지정**
  (사거리 안 적 부대 하이라이트·클릭, 이동 목표 지정과 같은 UX) → **설치 컨펌**(무엇 · 2일 뒤 발동 · 비용 ·
  예상 강도 · 성공/실패 없음) → Core `Reserve` 호출.
- 예약 표시(선택 시 대상까지 점선), '발동일 공격 불가' 안내. 발동은 진행 재생 중 자동(이미 됨) · 보고 패널 표기(이미 됨).

**Phase 3 — 마무리**
- design-stratagem "구현 현황" · QA 항목 · 이 로드맵 갱신. Game 헤드리스 빌드 · `--balance` 회귀.

**설계 확정 필요(❓)**: 강도 배율 상수(K·하한·상한 — design-stratagem "강도 배율 초안"), 계략별 `range`·`cost`·
필요 숙달의 최종 수치(`data/stratagems.json` 확인). **AI의 계략 사용**은 별도 후속(정식 AI 단계 — 위 F).
