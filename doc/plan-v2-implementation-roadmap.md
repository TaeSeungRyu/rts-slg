## 2. 전환 원칙

1. Core 삭제보다 UI 숨김/대체를 먼저 한다.
2. 기존 세이브 호환을 당장 깨지 않는다.
3. 전투·보급·성장·탐색·생산을 먼저 플레이 가능하게 만든다.
4. 제거 대상은 한 커밋에서 전부 지우지 않고, 사용 경로 제거 → 테스트 수정 → 데이터 정리 순서로 간다.
5. Game UI는 “전투에 필요한 선택”만 보이게 줄인다.
6. 기존 문서와 충돌하는 항목은 v2 문서를 우선한다.

## Phase 2. 자동 담당자 내정 4슬롯

목표: 내정을 수동 명령이 아니라 담당자 배치형 자동 성장으로 바꾼다.

작업:

- 도시별 담당자 슬롯 추가:
  - 치안 담당
  - 내정 담당
  - 병력 담당
  - 훈련 담당
- 담당자 지정/해제 Command 또는 Service 추가
- 월말 자동 처리 추가:
  - 치안: 무력 영향
  - 금/식량: 정치 영향
  - 병력: 무력 영향
  - 훈련도: 무력 영향
- 담당자가 없으면:
  - 금/식량/병력/훈련도 현상 유지
  - 치안만 하락

추천 초기 수치:

| 항목 | 공식 |
|---|---|
| 치안 회복 | 무력 60 미만 +0, 60~79 +1, 80~99 +2, 100 이상 +3 |
| 담당자 없음 치안 | 매월 -2 |
| 병력 담당 치안 부담 | 매월 -3 |
| 금 생산 | 기본 100 + 정치 × 2 |
| 식량 생산 | 기본 300 + 정치 × 5 |
| 병력 생산 | 기본 200 + 무력 × 5 |
| 훈련도 증가 | 무력 60 미만 +1, 60~79 +2, 80~99 +3, 100 이상 +4 |

월말 처리 순서:

1. 병력 담당이 먼저 훈련도 50%의 병력을 도시 대기 병력에 합류시킨다.
2. 같은 도시·같은 병종이면 기존 병력과 신규 병력의 훈련도를 병력 수 기준 가중 평균 후 정수 반올림으로 산정한다.
3. 훈련 담당이 그 이후 전체 대기 병력에 월 훈련도 증가치를 적용한다.

완료 기준:

- 도시 담당자를 지정하면 진행만 눌러도 도시 상태가 자동으로 변한다.
- 기존 세율·시장·모병·징병 없이도 도시가 최소한 굴러간다.
- 성 명령 팔레트의 `담당자`에서 4개 담당 슬롯을 지정하고, 성 정보/상세에서 현재 담당자를 확인할 수 있다.

검증:

- Core 단위 테스트
- `dotnet build`
- `dotnet test`

권장 커밋:

- `feat: 도시 자동 담당자 내정을 추가`

## Phase 3. 인구·세율·시장·모병·징병 제거 경로 정리

목표: 제거 확정 기능을 실제 게임 흐름에서 분리한다.

작업:

- 인구 표시 제거
- 세율 UI 제거
- 시장 UI 제거
- 모병/징병 UI 제거
- 병력 생산은 자동 담당자 결과로만 증가
- 기존 데이터 필드는 세이브 호환 때문에 당장 삭제하지 않되, 신규 흐름에서는 사용하지 않게 한다.

완료 기준:

- 플레이어가 인구/세율/시장/모병/징병을 볼 일이 없다.

## Phase 4. 자동 생산 병종 선택과 금 소비

목표: 모병/징병 대신 병력 담당자가 지정한 병종이 도시 금을 소비해 자동으로 쌓이게 한다.

작업:

- 도시 스키마에 자동 생산 병종 추가
- 병력 담당자 지정 모달에서 자동 생산 병종 복수 선택
- 병력 담당자는 7일 단위로 소규모 병력 생산
- 무력 100 장수 기준 월 약 5,000명 생산
- 도시 금을 확인하고 비용을 차감한 뒤 해당 병종의 대기 병력 증가
- 금이 부족하면 해당 생산 틱은 생산 없음
- 선택 가능 병종은 싼 병종부터 비싼 병종 순서로 표시
- 해상(대하) 병종은 자동 생산 불가 — 차후 항구의 “배 만들기” 기능으로 분리
- 도시 정보 UI에 “생산 병종/월 비용” 표시
- 출전 UI에서 해당 도시가 보유한 병종만 명확히 표시

완료 기준:

- 담당자 지정 시 자동 생산 병종을 선택할 수 있다.
- 월말 자동 내정에서 도시 금이 충분할 때만 지정 병종이 생산된다.
- 금 소비 비중은 `상병 > 기병 > 투석기/공성탑 > 보병 = 궁병 = 충차` 순서를 따른다.

## Phase 5B. 통솔 병력 연구

목표: `전투 교리` 아래에 세력 단위 `통솔 병력` 연구를 추가하여 일반 전투부대의 최대 편성 병력 한계를 단계적으로 높인다.

설계:

- `연구` 명령 팔레트에서 `전투 교리` 아래에 `통솔 병력` 기능을 배치한다.
- `통솔 병력`은 병종별 공방 연구가 아니라 세력 공용 연구다.
- 최대 10레벨까지 연구 가능하며, 주력병종 선택 여부와 무관하게 항상 10레벨까지 허용한다.
- 기본 일반 부대 편성 상한은 10,000명으로 유지한다.
- 10레벨 완료 시 일반 부대 편성 상한은 최대 20,000명이 된다.
- 권장 증가량은 레벨당 +1,000명이다.
  - 계산식: `일반 부대 편성 상한 = 10,000 + 통솔 병력 Lv × 1,000`
- 비용은 1레벨 연구부터 1,000금으로 비싸게 시작한다.
  - 1차 권장안: `다음 레벨 × 1,000금`
  - 후반 부담이 약하면 6레벨 이후부터 1.5배 또는 2배 계수로 재조정한다.
- 소요일과 수행 장수 조건은 기존 연구 계열과 동일하게 사용한다.
- 연구 담당 장수는 다른 중복 불가 업무와 충돌하면 기존 업무 이탈 안내 컨펌을 따른다.
- 집단군 40,000명 상한과는 별도다. `통솔 병력` 연구는 일반 전투부대 편성 상한만 높인다.

UI:

- `전투 교리` 항목 아래에 `통솔 병력` 카드 또는 버튼을 둔다.
- 카드에는 현재 레벨, 현재 편성 상한, 다음 레벨 편성 상한, 비용, 소요일을 표시한다.
- 컨펌창에는 담당 장수 초상, 예상 성공/소요일 대사, 비용, 현재 상한 → 연구 후 상한을 함께 표시한다.
- 출전 모달의 수량 입력 상한은 향후 `CommandBalance.DeployMaxTroops` 고정값이 아니라 세력의 `통솔 병력` 연구 레벨을 반영한 값으로 계산한다.

구현 단계:

1. ✅ Core에 세력별 `통솔 병력` 연구 레벨과 상한 계산식을 추가한다.
2. ✅ 연구 서비스에 `통솔 병력` 연구 타입, 비용, 소요일, 완료 처리를 추가한다.
3. ✅ 출전 서비스와 UI의 일반 부대 최대 편성 병력 계산을 연구 레벨 기반으로 변경한다.
4. ✅ 연구 UI에 `통솔 병력` 카드와 컨펌창을 추가한다.
5. ✅ 세이브/로드 및 테스트를 보강하고, 기본값 0레벨·상한 10,000명을 보장한다.

구현 메모:

- 저장은 기존 `FactionResearch` 트랙을 재사용하고, 예약 코드 `__command_troops__`로 구분한다.
- 연구비는 일반 전투 교리와 동일하게 연구 시작 전 보유 도시별 비율 분담 UI를 통해 납부할 수 있다.
- 일반 부대 출전 상한은 `10,000 + 통솔 병력 Lv × 1,000`으로 계산한다.
- 보급부대와 집단군 상한에는 영향을 주지 않는다.

검증:

- 연구 0레벨에서 일반 부대 최대 편성 10,000명
- 연구 1레벨에서 일반 부대 최대 편성 11,000명
- 연구 10레벨에서 일반 부대 최대 편성 20,000명
- 집단군 편성 상한 40,000명에는 영향 없음
- 금 부족, 담당 장수 업무 충돌, 연구 완료 로그 정상 표시

## Phase 9. 세력·도시형 위인 잠금 해제

목표: 삼국지식 “랜덤 인재 탐색/등용/배신” 대신, 문명류 위인처럼 세력·도시 조건 달성으로 고유 장수가 해금되는 장수 수급 축을 만든다.

유지 규칙:

- 성 함락 시 장수 30% 획득 규칙은 유지한다.
- 세력 멸망 시 남은 장수 70% 획득, 미획득 장수 70% 타 세력 편입 규칙은 유지한다.
- 배신·충성·포로교환은 다시 넣지 않는다.

핵심 방향:

- 위인은 크게 “세력형 위인”과 “도시형/지역형 위인”으로 나눈다.
- 각 세력은 미리 정의된 “세력형 위인/고유 장수 풀”을 가진다.
- 각 도시 또는 지역은 점령·유지·이벤트 조건으로 열리는 “도시형/지역형 위인 풀”을 가진다.
- 플레이어와 AI 모두 같은 조건을 달성하면 해당 장수를 영입 후보로 해금한다.
- 해금은 즉시 자동 합류가 아니라, 조건 확인 후 금/도시/세력 상태 등을 만족하면 영입 가능하게 한다.
- 위인 해금은 “어떤 플레이를 했는가”를 보상한다.
- 시나리오 시작 시 선택하는 도시별 영웅 4명은 초기 배치 장수이며, 위인 해금은 게임 중 추가 영입 축으로 구분한다.

위인 분류:

| 분류 | 기준 | 역할 |
|---|---|---|
| 세력형 위인 | 세력 정체성 | 유비-제갈량, 조조-순욱, 손권-주유처럼 세력 판타지를 강화 |
| 도시형/지역형 위인 | 도시·지역 장악 | 형주 책사, 서량 기병 장수, 강동 수군 장수처럼 정복 보상을 강화 |
| 유랑 위인 | 원 세력 멸망 | 잠긴 세력형 위인이 삭제되지 않고 더 어려운 조건으로 세계에 재등장 |

세력 멸망 시 잠긴 위인 처리:

| 대상 | 처리 |
|---|---|
| 이미 소속된 장수 | 기존 세력 멸망 규칙 유지: 70% 점거 세력 합류, 실패 시 70% 타 세력 편입 |
| 잠긴 세력형 위인 | 원 세력이 멸망하면 “유랑 위인” 상태로 전환 |
| 유랑 위인 | 지역·명성·능력·금 조건을 만족한 다른 세력이 영입 가능 |

### 보조 인재 수급: 문과시험·무과시험

목표: 위인 해금은 세력의 정체성 보상으로 유지하되, 장수가 너무 적은 세력도 장기전에 버틸 수 있도록 범용 장수를 생성하는 보조 루트를 둔다.

기본 규칙:

- `인재` 명령에 `문과시험`, `무과시험`을 추가한다.
- 도시별로 시행하며, 도시마다 1년에 1회 실행 가능하다.
- 게임 시작 직후에는 활성화되어 있고, 실행 완료 날짜 기준으로 1년 재사용 제한을 계산한다.
- 주최 장수와 소비금을 선택한다.
- 소비금은 100~1,000금 사이에서 선택한다.
- 시험은 7일간 진행되며, 완료 시 신규 장수 1명을 생성한다.
- 문과시험은 지력/정치/내정형 병종 적성에 조금 더 유리하다.
- 무과시험은 무력/전투형 병종 적성에 조금 더 유리하다.
- AI도 장수 수가 부족하면 같은 규칙으로 실행할 수 있다.

생성 상한:

- 신규 장수의 능력치 상한은 주최 장수 능력치의 90%다.
- 예: 주최 장수 무력 90, 지력 90, 정치 90이면 생성 장수의 각 능력 최대치는 81/81/81이다.
- 병종 적성은 주최 장수의 해당 병종 적성보다 한 단계 낮은 등급을 최대치로 한다.
- 예: 주최 장수가 도검병 A면 생성 장수는 도검병 B까지 가능하다.

확률 조정안:

소비금은 상한에 가까운 능력치가 나올 확률을 올린다. 단, 1,000금을 써도 상한값 자체는 희귀하게 유지한다.

| 소비금 | 품질 보정 | 상한값 도달 확률 | 추천 평균 위치 |
|---:|---:|---:|---|
| 100 | +0 | 0.1% | 상한의 45~55% |
| 300 | +1 | 0.25% | 상한의 50~60% |
| 500 | +2 | 0.45% | 상한의 55~65% |
| 700 | +3 | 0.70% | 상한의 60~70% |
| 1,000 | +4 | 1.00% | 상한의 65~75% |

능력치 판정은 “상한에서 몇 점 낮은가”를 뽑는 방식으로 처리한다.

| 상한 대비 결과 | 1,000금 기준 예시 확률 | 설명 |
|---|---:|---|
| 상한값 | 1% | 81 상한이면 81 |
| 상한 -1 | 2% | 80 |
| 상한 -2 | 3% | 79 |
| 상한 -3~-5 | 9% | 우수 |
| 상한 -6~-10 | 20% | 준수 |
| 상한 -11~-20 | 35% | 보통 |
| 상한 -21 이하 | 30% | 낮음 |

소비금이 낮을수록 위 표를 아래쪽으로 밀어낸다. 즉, 100금은 “보통 이하”가 대부분이고, 1,000금은 “준수~우수” 비중이 높다. 상한값 1%는 유지한다.

적성 판정:

- 병종 적성도 능력치와 같은 “상한 대비 하락폭” 패턴으로 판정한다.
- 먼저 주최 장수의 병종별 적성을 한 단계 낮춰 생성 상한으로 삼는다.
  - 예: 주최 장수 도검병 A → 생성 장수 도검병 최대 B
  - 예: 주최 장수 기병 S → 생성 장수 기병 최대 A+
- 이후 상한에서 몇 단계 낮은지를 뽑는다.

| 상한 대비 결과 | 1,000금 기준 예시 확률 | 설명 |
|---|---:|---|
| 상한 등급 | 1% | B 상한이면 B |
| 상한 -1단계 | 4% | B 상한이면 C |
| 상한 -2단계 | 10% | B 상한이면 D |
| 상한 -3단계 | 20% | B 상한이면 F |
| 최저 등급 | 65% | 하한 F에 머무름 |

- 소비금이 낮을수록 능력치와 마찬가지로 아래쪽 구간 가중치가 커진다.
- 문과시험은 궁병, 공성, 보급/내정형 태그에 품질 보정 +1을 준다.
- 무과시험은 보병, 기병, 궁병 등 전투 병종에 품질 보정 +1을 준다.
- 어떤 경우에도 생성 상한을 넘지 않는다.

UI:

- `인재` 팔레트 하위에 `문과시험`, `무과시험`을 표시한다.
- 모달 구성:
  - 주최 장수 선택
  - 소비금 슬라이더 또는 100/300/500/700/1000 빠른 선택
  - 예상 품질 설명
  - 1년 재사용 제한 표시
- 완료 시 신규 장수 이름, 능력치, 병종 적성, 출신 도시를 결과 모달로 보여준다.

완료 기준:

- 장수 수급이 랜덤 탐색이 아니라 세력·도시 목표 달성 보상으로 작동한다.
- 다른 세력이 도시를 점령해도 도시형/지역형 위인과 이벤트 보상을 통해 정복 가치가 생긴다.
- 세력이 멸망해도 잠긴 세력형 위인은 삭제되지 않고 유랑 위인으로 재분배된다.
- 플레이어와 AI가 같은 규칙으로 위인을 해금하고 영입할 수 있다.
- 장수가 부족한 세력은 문과시험·무과시험으로 범용 장수를 제한적으로 보충할 수 있다.

## Phase 9A. 개발용 장수 에디터

추가일: 2026-09-09. 개발자가 로컬 원본 장수 데이터를 편집하는 도구다. 게임 내 플레이 기능이 아니며 이번 작업에서는 계획만 추가한다. 별도 루트 실행 파일 **`run-general-editor.bat`**으로 에디터 전용 씬을 실행한다. Game의 기존 Godot/.NET 및 데이터 로더를 재사용하고 전투 캠페인을 실행하지 않는다.

추천 착수 순서: Phase 14A의 장수별 액티브 재배정과 Phase 17의 원형 얼굴 UI보다 먼저 에디터의 데이터 검증·저장 기반을 만든다. Phase 9의 해금/영입 로직을 변경하는 작업은 아니다.

### 편집 범위

| 대상 | 편집 및 검증 규칙 |
|---|---|
| 장수 선택 | ID·이름 검색, 세력/지역 필터, 목록에서 현재 편집 대상 표시. ID는 읽기 전용이며 재번호화 금지 |
| 능력치 | 무력·지력·정치 1~100 정수. 유효 범위를 벗어나면 저장 전 오류 표시 |
| 병종 적성 | 보병·궁병·기병·상병·공성·해상·보급 각각 F/D/C/B/A/A+/S/SS/SSS 선택 |
| 전투 액티브 | `active-skills.json`에서 최대 1개 선택 또는 해제. 전환 예정과 실제 등록된 스킬을 구분하고 미등록 코드는 저장 불가 |
| 전투 패시브 | `passive-skills.json`에서 선택·해제·티어 1~3 수정. 전투 스킬 합계 0~4개, 같은 코드 중복 금지 |
| 내정 패시브 | `admin-skills.json`에서 0~4개 선택·해제·티어 1~3 수정. 내정 액티브 항목 없음. 현재 효과 미연결 여부도 확인 가능 |
| 초상 | ID에 연결된 원본 일러스트 확인. 원본 이미지 경로 및 얼굴 구도 관리. 일반 상세 일러스트와 원형 얼굴 미리보기를 함께 표시 |

선택한 스킬의 설명을 함께 표시한다. 장수의 이름·출생년·해금 가능 년도·설명·기타 기존 필드는 편집 범위 밖이어도 저장 시 보존한다. 게임 실행 중 상태나 세이브의 성장 수치를 직접 수정하지 않는다. 원본 수정은 새로 데이터를 로드할 때 반영한다.

### 원형 얼굴 데이터

출전 부대를 선택했을 때 원 안에 장수 얼굴이 나오는 향후 UI를 위해, 원본 일러스트를 훼손하지 않는 **구도 메타데이터**를 저장한다.

제안 파일: `data/general-portraits.json`. 다음 필드는 신규 계획이며 현재 로더에 이미 존재하는 필드가 아니다.

| 필드 | 형식·기본값 | 의미 |
|---|---|---|
| `general_id` | 기존 장수 ID, 고유 키 | `generals.json`과 연결. 미등록 ID 저장 불가 |
| `portrait_path` | 저장소 내 상대 경로, 기본 `SanguoSLG.Game/assets/portraits/{id}.png` | 전체 일러스트 경로. 절대 경로 저장 금지, 게임에서는 리소스 경로로 변환 |
| `face_center_x` | 0~1, 기본 0.5 | 얼굴 영역 중심 X를 원본 너비로 정규화 |
| `face_center_y` | 0~1, 기본 0.35 | 얼굴 영역 중심 Y를 원본 높이로 정규화 |
| `face_zoom` | 1~4 실수, 기본 1 | 기준 정사각형에서 확대. 범위는 에디터의 초기 제안값 |

얼굴 정사각형 한 변은 `min(원본 너비, 원본 높이) / face_zoom`이다. 중심 위치를 픽셀로 변환한 뒤 영역이 이미지 밖으로 나가지 않도록 보정하고 원형 마스크로 표시한다. 원형 안을 빈 여백 없이 채우되 이미지 비율은 유지한다. 미리보기와 게임은 같은 좌표 변환을 재사용한다. 기본 구도는 얼굴을 정확히 보장하지 않으므로 개별 조정이 가능해야 한다.

이미지·메타데이터가 없으면 기존 공용 장수 이미지와 기본 구도로 대체한다. 전체 일러스트는 자르지 않는다. 파일 확장자·이미지 존재·크기를 검증하고 잘못된 경로는 저장 전에 안내한다. 원본 장수 ID나 초상 PNG 파일명을 편집 때문에 바꾸지 않는다.

### 저장과 실행

- `run-general-editor.bat`는 자신의 위치를 기준으로 프로젝트·데이터 경로를 찾는다. 공백 경로를 지원하고 .NET Godot 실행 파일이 없으면 원인을 안내한다.
- 저장 버튼은 변경 전후 능력치·적성·스킬·얼굴 구도를 보여준다. 변경 없이 닫기와 초기값 복원도 제공한다.
- 장수 원본과 얼굴 메타데이터를 모두 검증한 뒤 저장한다. 저장 중 오류가 나면 두 파일의 변경이 일부만 남지 않도록 복원한다.
- 편집 중 외부에서 원본이 바뀌었으면 덮어쓰지 않고 다시 불러오기 또는 비교를 제공한다. 읽지 못한 필드나 다른 장수의 값도 보존한다.
- 백업은 D드라이브 프로젝트 아래 `tools/general-editor/backups/`에 날짜별로 저장한다. 임시 파일·백업은 Git에서 제외하고 실제 데이터 변경만 검토·커밋한다. C드라이브에 별도 기억 저장소를 만들지 않는다.
- 에디터가 자동으로 Git 커밋·푸시하지 않는다. 개발 작업 단위로 변경을 검증한 뒤 커밋·푸시한다.

## Phase 10B. 저치안 페널티와 도적 습격

상태: ✅ 구현 완료(2026-09-09)

목표: 병력 자동 생산의 반대급부로 치안 관리 압박을 만든다. 병력 담당으로 도시를 빠르게 키우면 치안이 떨어지고, 치안 담당·방어 병력을 함께 운용해야 한다.

규칙:

- 치안 70 이하:
  - 내정 담당 금/군량 산출 감소
  - 병력 담당 자동 생산량 감소
  - 훈련 담당 훈련도 증가량 감소
- 치안 60 이하:
  - `진행` 종료 시 도적 출현 판정
  - 도적은 해당 성 주변 빈 타일에 생성되고 가장 가까운 성을 공격 목표로 삼는다.
  - 이미 해당 성을 공격 중인 도적이 있으면 추가 출현 확률을 낮추거나 출현하지 않는다.

추천 초기 수치:

| 조건 | 효과 |
|---|---|
| 치안 61~70 | 내정/병력/훈련 효과 80% |
| 치안 41~60 | 내정/병력/훈련 효과 60%, 도적 출현 20% |
| 치안 21~40 | 내정/병력/훈련 효과 40%, 도적 출현 35% |
| 치안 0~20 | 내정/병력/훈련 효과 20%, 도적 출현 50% |

도적 전투 규칙:

- 도적은 임시 적대 세력 또는 중립 적대 부대로 처리한다.

- 도적은 성벽을 공격할 수 있으나 1차 구현에서는 성 점령까지는 하지 않는다.
- 도적을 격퇴하면 소량의 금/군량 또는 장수 경험치를 지급할 수 있다.

완료 기준:

## Phase 10D. 출전 부대 명령 팔레트

목표: 성에서 출전한 부대를 다시 선택했을 때 전장 상황에 맞는 명령을 내릴 수 있게 한다. 현재 구 로드맵에는 출전 부대 명령 계획이 있고 일부 이동·정지 계열은 구현되어 있으나, v2 로드맵에는 독립 단계로 없었다. 정찰/전장의 안개 이후, 보급부대 UI와 집단군으로 확장하기 전에 일반 전투부대 조작을 먼저 완성한다.

우선 범위:

1. **부대 선택 정보 팔레트 정리**
   - 출전 부대를 클릭하면 장수 초상, 병종, 병력, 훈련도, 군량/보급 상태, 현재 목표, 현재 업무를 표시한다.
   - 아군 부대는 명령 버튼을 표시하고, 적군 부대는 시야/정찰 규칙에 따라 정보만 표시한다.
   - 담당자·연구·외교·탐색 등 다른 업무와 같은 `현재 담당업무` 표현을 사용한다.

2. **이동·공격·정지·복귀 명령**
   - 이동: 행군/전진/공격 모드를 유지하고, 목적지 선택과 경로 프리뷰를 제공한다.
   - 공격: 적 부대 또는 적 성을 대상으로 지정하면 공격 모드로 목표를 갱신한다.
   - 정지: 현재 목표와 경로를 지우고 다음 진행부터 대기한다.
   - 복귀: 원 소속 성 또는 가장 가까운 아군 성을 선택해 복귀 목표를 설정한다. 성 도착 시 주둔 병력으로 편입한다.

3. **전투 액티브 스킬 명령**
   - Phase 14A 이후 독립 계략 대신 장수 액티브 스킬을 사용한다.
   - Phase 10D 1차에서는 이미 등록된 액티브 스킬의 사용 가능 여부, 충전 상태, 대상 조건만 UI에 보여준다.
   - 실제 신규 효과 수치와 계략 전환 액티브 구현은 Phase 14A/15에서 진행한다.

4. **보급부대와 생산부대 처리**
   - 보급부대는 공격 명령을 받지 못하고 이동/정지/복귀 중심으로 조작한다.
   - 생산 중인 500명 채집 부대는 시설 내부 상태이므로 일반 명령 팔레트를 띄우지 않는다.
   - 생산 이동/복귀 중인 부대는 일반 부대처럼 선택 가능하되, 취소 불가 규칙 때문에 목적지 변경을 제한한다.

5. **명령 검증과 보고**
   - 진행 중 재생 상태에서는 새 명령을 받을 수 없고 실패 사유를 작은 모달/토스트로 표시한다.
   - 명령 변경 성공, 목표 상실, 복귀 완료, 전멸은 좌측 하단 `보고`에 남긴다.
   - 전장의 안개 밖 대상이나 60일 정찰 만료 후 정보가 없는 적 성은 대상 지정에서 제외한다.

완료 기준:

- 아군 출전 부대를 클릭하면 정보와 명령 팔레트가 안정적으로 표시된다.

## Phase 11B. 보급부대 적성·스킬·모션 개선

목표: 보급부대가 단순 짐꾼처럼 보이지 않게 하되, 전투부대와 역할이 겹치지 않도록 “약하지만 중요한 병참 전투 단위”로 정리한다. 집단군보다 먼저 보급부대의 조작감과 성장 축을 고정한다.

기준 자료:

- `tools/blender/make_troop_archer.py`: 궁병 병사의 활·화살·화살통 구성과 손 화살 발사 구조를 참고한다.
- `SanguoSLG.Game/assets/models/troop-supply.glb`: 기존 대기/이동/공격 상태 모델을 유지하되, 병사 사격 모션을 보강한다.

확정 규칙:

- 보급부대 병종 적성을 신설한다.
- 보급 적성 등급은 다른 병종과 동일하게 `F, D, C, B, A, A+, S, SS, SSS`를 사용한다.
- 모든 장수의 병종 특성에 `보급` 항목을 추가한다.
- 기존에는 발휘되지 않던 보급부대 선봉의 액티브·패시브 스킬을 유효하게 전환한다.
- 단, 보급부대의 기본 공격력과 방어력은 계속 전체 게임 최저 수치를 사용한다.
- 보급 적성과 스킬은 직접 공방 수치를 크게 올리는 축이 아니라 보급 효율, 생존 보조, 사기·군량·보충 효율 등으로 우선 적용한다.
- 전투 액티브/패시브 중 명백히 전투 피해량을 크게 키우는 효과는 보급부대 적용 시 별도 보정 계수를 둔다.
- 보급부대 공격 연출은 화살 투사체를 유지하되, 보급부대 모델 안의 병사들에게 궁병형 활 당김·발사 모션을 넣어 밋밋함을 줄인다.

## Phase 11C. 수성 적성·태수 방어전 개선

목표: 공성전에서 성이 단순 고정 포탑처럼 동작하지 않게 하고, 태수 임명과 수성 특화 장수의 의미를 만든다. 공격 측 집단군이 들어오기 전에 방어 측 규칙을 먼저 정리한다.

확정 규칙:

- 성에 `태수`로 임명된 장수의 액티브·패시브 스킬만 공성전 방어에 영향을 준다.
- 같은 성에 있는 나머지 장수의 액티브·패시브 스킬은 공성전 방어에 발휘되지 않는다.
- 태수가 출전·탐색·외교·생산 등으로 자리를 비운 경우, 해당 성에 주둔 중인 장수 중 `수성` 적성이 가장 높은 장수가 임시로 태수 역할을 맡는다.
- 원래 태수가 복귀해도 진행 중에는 즉시 교체하지 않고, 해당 `진행`이 끝난 뒤 방어 지휘권을 다시 넘겨받는다.
- 성 액티브 스킬 발동은 기존 전투 액티브와 같은 5일 충전 규칙을 따른다.
- 하루가 지났는데 해당 성을 향한 적 공격이 없으면 성 액티브 충전은 즉시 0으로 초기화한다.
- 수성 병종 적성을 신설한다.
- 수성 적성 등급은 다른 병종과 동일하게 `F, D, C, B, A, A+, S, SS, SSS`를 사용한다.
- 모든 장수의 병종 특성에 `수성` 항목을 추가한다.
- 수성 중인 성의 부상병은 회복되지 않는다. 적 공격이 이어지는 동안은 치료보다 성벽·대열 유지가 우선이다.

권장 작업 분할:

1. **데이터 스키마 확장**
   - 장수 적성 스키마에 `수성` 추가.
   - 모든 장수 데이터에 수성 적성 기본값을 채운다.
   - 기존 데이터 로더와 개발용 장수 에디터가 수성 적성을 읽고 저장하도록 확장한다.
2. **수성 지휘관 선정 규칙**
   - 성의 태수가 성에 있으면 태수를 방어 지휘관으로 사용한다.
   - 태수가 없으면 같은 성 주둔 장수 중 수성 적성, 무력, 지력, ID 순으로 대리 지휘관을 고른다.
   - 진행 중 지휘관은 고정하고, 복귀·임명 변경은 다음 진행부터 반영한다.
3. **공성 방어 스킬 연결**
   - 방어 지휘관의 액티브·패시브만 공성 교환에 적용한다.
   - 태수 외 장수 스킬이 섞이지 않도록 테스트로 막는다.
   - 공격 측 액티브/패시브 적용 범위와 충돌하지 않게 공성 컨텍스트를 분리한다.
4. **성 액티브 충전/초기화**
   - 적 공격을 받은 날만 성 액티브 충전을 누적한다.
   - 공격이 없는 날이 지나면 충전을 0으로 초기화한다.
   - 5일 충전 완료 시 방어 지휘관 액티브가 공성 방어에 발동한다.
5. **부상병 회복 차단**
   - 수성 중인 성은 부상병 회복을 중단한다.
   - 공격이 끊긴 뒤 다음 진행부터 회복을 재개한다.
6. **UI와 보고**
   - 성 상세 모달에 현재 수성 지휘관, 수성 적성, 적용 스킬, 성 액티브 충전일을 표시한다.
   - 태수 부재로 대리 지휘관이 선정되면 보고 팔레트에 명확히 알린다.
   - 수성 중 부상병 회복 정지 상태를 성 상세에 표시한다.

완료 기준:

- 공성 방어에는 태수 또는 대리 수성 지휘관 1명의 스킬만 적용된다.
- 모든 장수가 `수성` 적성을 가진다.
- 성 액티브는 적 공격이 이어진 날만 충전되고, 공격이 없으면 0으로 초기화된다.
- 수성 중 부상병은 회복되지 않는다.
- UI에서 현재 방어 지휘 체계와 스킬 적용 여부를 확인할 수 있다.

검증:

- 수성 적성 데이터 로딩/저장/무결성 테스트
- 태수 우선 선정 테스트
- 태수 부재 시 대리 수성 지휘관 선정 테스트
- 원태수 복귀 후 다음 진행부터 지휘권 복귀 테스트
- 태수 스킬만 적용되고 다른 장수 스킬은 제외되는 공성 테스트
- 성 액티브 5일 충전/무공격 초기화 테스트
- 수성 중 부상병 회복 차단 테스트
- Game 빌드와 Godot headless 로딩
- 수동 테스트: `run-maptest.bat`에서 성 상세 수성 지휘관·충전·부상병 회복 정지 표시 확인

## Phase 11A. 집단군 편성·출전

목표: 보병·궁병·공성 병기를 하나의 대규모 혼성 부대로 묶어, 공성전과 대규모 야전의 선택지를 만든다.

### 보고 팔레트 확장 구성

성이 많아지면 좌측 하단 보고 팔레트에 모든 도시의 자동내정·전투·명령 결과가 한꺼번에 쌓여 전황 판단을 방해한다. 보고 팔레트는 다음 구조로 확장한다.

| 층위 | 표시 방식 | 목적 |
|---|---|---|
| 기본 보기 | 중요 보고만 노출: 전투, 함락, 명령 실패, 큰 손실, 선택 도시 자동내정 | 진행 직후 즉시 판단 |
| 요약 보기 | `자동내정 요약: 금 +n / 군량 +n / 병력 +n / 훈련도 +n / 치안 ±n`처럼 세력 합계 1줄 | 성이 많을 때 숫자 흐름 압축 |
| 필터 | 전체, 전투, 내정, 도시, 경고 버튼 | 플레이어가 보고 싶은 사건만 선택 |
| 도시 필터 | 현재 선택 도시 우선, 전체 모달에서 도시별 접기/펼치기 | 다도시 운영 시 탐색 비용 감소 |
| 중요도 | 경고/손실은 항상 상단 고정, 일반 내정은 접힌 상태 허용 | 놓치면 안 되는 사건 보호 |

구현 순서:

1. 보고 타입 enum 또는 문자열 태그를 추가한다.
2. 자동내정 보고는 도시별 상세와 세력 합계 요약을 동시에 만든다.
3. 좌측 하단 기본 팔레트는 요약과 중요 보고만 보여준다.
4. `전체` 보고 모달에서 타입/도시 필터와 접기/펼치기를 제공한다.

이 순서가 좋은 이유:

- 먼저 보이는 복잡도를 줄인다.

- 출전한 일반 부대를 직접 조작하는 흐름을 먼저 완성한다.
