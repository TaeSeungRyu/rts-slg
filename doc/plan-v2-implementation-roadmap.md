## 2. 전환 원칙

1. Core 삭제보다 UI 숨김/대체를 먼저 한다.
2. 기존 세이브 호환을 당장 깨지 않는다.
3. 전투·보급·성장·탐색·생산을 먼저 플레이 가능하게 만든다.
4. 제거 대상은 한 커밋에서 전부 지우지 않고, 사용 경로 제거 → 테스트 수정 → 데이터 정리 순서로 간다.
5. Game UI는 “전투에 필요한 선택”만 보이게 줄인다.
6. 기존 문서와 충돌하는 항목은 v2 문서를 우선한다.

## Phase 2. 자동 담당자 내정 4슬롯

목표: 내정을 수동 명령이 아니라 담당자 배치형 자동 성장으로 바꾼다.

작업:

- 도시별 담당자 슬롯 추가:
  - 치안 담당
  - 내정 담당
  - 병력 담당
  - 훈련 담당
- 담당자 지정/해제 Command 또는 Service 추가
- 월말 자동 처리 추가:
  - 치안: 무력 영향
  - 금/식량: 정치 영향
  - 병력: 무력 영향
  - 훈련도: 무력 영향
- 담당자가 없으면:
  - 금/식량/병력/훈련도 현상 유지
  - 치안만 하락

추천 초기 수치:

| 항목 | 공식 |
|---|---|
| 치안 회복 | 무력 60 미만 +0, 60~79 +1, 80~99 +2, 100 이상 +3 |
| 담당자 없음 치안 | 매월 -2 |
| 병력 담당 치안 부담 | 매월 -3 |
| 금 생산 | 기본 100 + 정치 × 2 |
| 식량 생산 | 기본 300 + 정치 × 5 |
| 병력 생산 | 기본 200 + 무력 × 5 |
| 훈련도 증가 | 무력 60 미만 +1, 60~79 +2, 80~99 +3, 100 이상 +4 |

월말 처리 순서:

1. 병력 담당이 먼저 훈련도 50%의 병력을 도시 대기 병력에 합류시킨다.
2. 같은 도시·같은 병종이면 기존 병력과 신규 병력의 훈련도를 병력 수 기준 가중 평균 후 정수 반올림으로 산정한다.
3. 훈련 담당이 그 이후 전체 대기 병력에 월 훈련도 증가치를 적용한다.

완료 기준:

- 도시 담당자를 지정하면 진행만 눌러도 도시 상태가 자동으로 변한다.
- 기존 세율·시장·모병·징병 없이도 도시가 최소한 굴러간다.
- 성 명령 팔레트의 `담당자`에서 4개 담당 슬롯을 지정하고, 성 정보/상세에서 현재 담당자를 확인할 수 있다.

검증:

## Phase 5B. 통솔 병력 연구

목표: `전투 교리` 아래에 세력 단위 `통솔 병력` 연구를 추가하여 일반 전투부대의 최대 편성 병력 한계를 단계적으로 높인다.

설계:

- `연구` 명령 팔레트에서 `전투 교리` 아래에 `통솔 병력` 기능을 배치한다.
- `통솔 병력`은 병종별 공방 연구가 아니라 세력 공용 연구다.
- 최대 10레벨까지 연구 가능하며, 주력병종 선택 여부와 무관하게 항상 10레벨까지 허용한다.
- 기본 일반 부대 편성 상한은 10,000명으로 유지한다.
- 10레벨 완료 시 일반 부대 편성 상한은 최대 20,000명이 된다.
- 권장 증가량은 레벨당 +1,000명이다.
  - 계산식: `일반 부대 편성 상한 = 10,000 + 통솔 병력 Lv × 1,000`
- 비용은 1레벨 연구부터 1,000금으로 비싸게 시작한다.
  - 1차 권장안: `다음 레벨 × 1,000금`
  - 후반 부담이 약하면 6레벨 이후부터 1.5배 또는 2배 계수로 재조정한다.
- 소요일과 수행 장수 조건은 기존 연구 계열과 동일하게 사용한다.
- 연구 담당 장수는 다른 중복 불가 업무와 충돌하면 기존 업무 이탈 안내 컨펌을 따른다.
- 집단군 40,000명 상한과는 별도다. `통솔 병력` 연구는 일반 전투부대 편성 상한만 높인다.

UI:

- `전투 교리` 항목 아래에 `통솔 병력` 카드 또는 버튼을 둔다.
- 카드에는 현재 레벨, 현재 편성 상한, 다음 레벨 편성 상한, 비용, 소요일을 표시한다.
- 컨펌창에는 담당 장수 초상, 예상 성공/소요일 대사, 비용, 현재 상한 → 연구 후 상한을 함께 표시한다.
- 출전 모달의 수량 입력 상한은 향후 `CommandBalance.DeployMaxTroops` 고정값이 아니라 세력의 `통솔 병력` 연구 레벨을 반영한 값으로 계산한다.

구현 단계:

1. ✅ Core에 세력별 `통솔 병력` 연구 레벨과 상한 계산식을 추가한다.
2. ✅ 연구 서비스에 `통솔 병력` 연구 타입, 비용, 소요일, 완료 처리를 추가한다.
3. ✅ 출전 서비스와 UI의 일반 부대 최대 편성 병력 계산을 연구 레벨 기반으로 변경한다.
4. ✅ 연구 UI에 `통솔 병력` 카드와 컨펌창을 추가한다.
5. ✅ 세이브/로드 및 테스트를 보강하고, 기본값 0레벨·상한 10,000명을 보장한다.

구현 메모:

- 저장은 기존 `FactionResearch` 트랙을 재사용하고, 예약 코드 `__command_troops__`로 구분한다.
- 연구비는 일반 전투 교리와 동일하게 연구 시작 전 보유 도시별 비율 분담 UI를 통해 납부할 수 있다.
- 일반 부대 출전 상한은 `10,000 + 통솔 병력 Lv × 1,000`으로 계산한다.
- 보급부대와 집단군 상한에는 영향을 주지 않는다.

검증:

- 연구 0레벨에서 일반 부대 최대 편성 10,000명
- 연구 1레벨에서 일반 부대 최대 편성 11,000명
- 연구 10레벨에서 일반 부대 최대 편성 20,000명
- 집단군 편성 상한 40,000명에는 영향 없음
- 금 부족, 담당 장수 업무 충돌, 연구 완료 로그 정상 표시

## Phase 5C. 일반연구 6종

목표: 세력의 장기 내정 기반을 성장시키는 `일반연구`를 `전투교리`와 별도 연구선으로 추가한다.

명령/UI:

- 연구 명령 팔레트 순서는 `주력병종 → 전투교리 → 일반연구 → 통솔 병력 → 성벽 강화`를 기준으로 한다.
- `일반연구` 모달은 6개 연구를 카드 또는 표로 보여주며 현재 레벨, 다음 효과, 비용, 예상 기간을 표시한다.
- 모든 일반연구는 Lv.0~10의 독립 트랙이다.
- 연구 시작 전 기존 도시별 연구비 분담 표를 그대로 사용하며, 도시가 1개여도 표를 노출한다.
- 전투교리 연구선과 일반연구 연구선을 분리한다. 두 연구는 동시에 진행할 수 있지만, 같은 연구선 안에서는 한 번에 하나만 진행한다.
- 두 연구가 병행될 때는 각각 수행 장수가 필요하며 한 장수를 두 연구에 중복 배치할 수 없다.

추천 명칭과 효과:

| 번호 | 추천 연구명 | 레벨 효과 | Lv.10 누적 |
|---:|---|---|---|
| 1 | 민심 안정 | 짝수 레벨마다 치안 주간 정산 +1 | +5 |
| 2 | 농정 개량 | 레벨마다 식량 생산 +2% | +20% |
| 3 | 상업 진흥 | 레벨마다 금 생산 +2% | +20% |
| 4 | 군역 정비 | 레벨마다 병력 생산 +2% | +20% |
| 5 | 훈련 교범 | 짝수 레벨마다 훈련도 주간 증가 +1 | +5 |
| 6 | 의술 연구 | 레벨마다 부상병 회복 속도 +10% | +100% |

처리 원칙:

- 백분율 연구는 해당 세력의 모든 도시 주간 산출량에 곱연산 보정으로 적용한다.
- `민심 안정`은 담당자 효과와 병력 생산 페널티를 모두 합산한 뒤 주간 치안 변화량에 더한다.
- `훈련 교범`은 훈련 담당자의 주간 훈련도 증가량에 더하며, 담당자가 없을 때 독립적으로 훈련을 생성하지 않는다.
- `의술 연구`는 실제 회복 가능한 주간 부상병 수에 적용하며 수성 중 회복 금지 규칙보다 우선하지 않는다.
- 효과 계산과 UI 예상치는 같은 Core 계산기를 사용한다.

검증:

- 전투교리와 일반연구 동시 진행 테스트
- 같은 연구선 중복 시작 및 같은 장수 중복 수행 거부 테스트
- 6종 레벨별/누적 효과 테스트

## Phase 9. 세력·도시형 위인 잠금 해제

목표: 삼국지식 “랜덤 인재 탐색/등용/배신” 대신, 문명류 위인처럼 세력·도시 조건 달성으로 고유 장수가 해금되는 장수 수급 축을 만든다.

유지 규칙:

- 성 함락 시 장수 30% 획득 규칙은 유지한다.
- 세력 멸망 시 남은 장수 70% 획득, 미획득 장수 70% 타 세력 편입 규칙은 유지한다.
- 배신·충성·포로교환은 다시 넣지 않는다.

핵심 방향:

- 위인은 크게 “세력형 위인”과 “도시형/지역형 위인”으로 나눈다.
- 각 세력은 미리 정의된 “세력형 위인/고유 장수 풀”을 가진다.
- 각 도시 또는 지역은 점령·유지·이벤트 조건으로 열리는 “도시형/지역형 위인 풀”을 가진다.
- 플레이어와 AI 모두 같은 조건을 달성하면 해당 장수를 영입 후보로 해금한다.
- 해금은 즉시 자동 합류가 아니라, 조건 확인 후 금/도시/세력 상태 등을 만족하면 영입 가능하게 한다.
- 위인 해금은 “어떤 플레이를 했는가”를 보상한다.
- 시나리오 시작 시 선택하는 도시별 영웅 4명은 초기 배치 장수이며, 위인 해금은 게임 중 추가 영입 축으로 구분한다.

위인 분류:

| 분류 | 기준 | 역할 |
|---|---|---|
| 세력형 위인 | 세력 정체성 | 유비-제갈량, 조조-순욱, 손권-주유처럼 세력 판타지를 강화 |
| 도시형/지역형 위인 | 도시·지역 장악 | 형주 책사, 서량 기병 장수, 강동 수군 장수처럼 정복 보상을 강화 |
| 유랑 위인 | 원 세력 멸망 | 잠긴 세력형 위인이 삭제되지 않고 더 어려운 조건으로 세계에 재등장 |

세력 멸망 시 잠긴 위인 처리:

| 대상 | 처리 |
|---|---|
| 이미 소속된 장수 | 기존 세력 멸망 규칙 유지: 70% 점거 세력 합류, 실패 시 70% 타 세력 편입 |
| 잠긴 세력형 위인 | 원 세력이 멸망하면 “유랑 위인” 상태로 전환 |
| 유랑 위인 | 지역·명성·능력·금 조건을 만족한 다른 세력이 영입 가능 |
| 도시형/지역형 위인 | 해당 도시/지역 조건을 보유한 세력이 계속 해금 가능 |

유랑 위인 조건은 원 세력 조건보다 어렵게 잡는다. 원 세력은 정체성 보상으로 쉽게 접근하고, 타 세력은 정복·운영·명성 투자를 통해 어렵게 획득한다.

작업:

  - 도시 운영: 치안, 금/군량 생산, 담당자 누적 운영

### 보조 인재 수급: 문과시험·무과시험

목표: 위인 해금은 세력의 정체성 보상으로 유지하되, 장수가 너무 적은 세력도 장기전에 버틸 수 있도록 범용 장수를 생성하는 보조 루트를 둔다.

기본 규칙:

- `인재` 명령에 `문과시험`, `무과시험`을 추가한다.
- 도시별로 시행하며, 도시마다 1년에 1회 실행 가능하다.
- 게임 시작 직후에는 활성화되어 있고, 실행 완료 날짜 기준으로 1년 재사용 제한을 계산한다.
- 주최 장수와 소비금을 선택한다.
- 소비금은 100~1,000금 사이에서 선택한다.
- 시험은 7일간 진행되며, 완료 시 신규 장수 1명을 생성한다.
- 문과시험은 지력/정치/내정형 병종 적성에 조금 더 유리하다.
- 무과시험은 무력/전투형 병종 적성에 조금 더 유리하다.
- AI도 장수 수가 부족하면 같은 규칙으로 실행할 수 있다.

생성 상한:

- 신규 장수의 능력치 상한은 주최 장수 능력치의 90%다.
- 예: 주최 장수 무력 90, 지력 90, 정치 90이면 생성 장수의 각 능력 최대치는 81/81/81이다.
- 병종 적성은 주최 장수의 해당 병종 적성보다 한 단계 낮은 등급을 최대치로 한다.
- 예: 주최 장수가 도검병 A면 생성 장수는 도검병 B까지 가능하다.

확률 조정안:

소비금은 상한에 가까운 능력치가 나올 확률을 올린다. 단, 1,000금을 써도 상한값 자체는 희귀하게 유지한다.

| 소비금 | 품질 보정 | 상한값 도달 확률 | 추천 평균 위치 |
|---:|---:|---:|---|
| 100 | +0 | 0.1% | 상한의 45~55% |
| 300 | +1 | 0.25% | 상한의 50~60% |
| 500 | +2 | 0.45% | 상한의 55~65% |
| 700 | +3 | 0.70% | 상한의 60~70% |
| 1,000 | +4 | 1.00% | 상한의 65~75% |

능력치 판정은 “상한에서 몇 점 낮은가”를 뽑는 방식으로 처리한다.

| 상한 대비 결과 | 1,000금 기준 예시 확률 | 설명 |
|---|---:|---|
| 상한값 | 1% | 81 상한이면 81 |
| 상한 -1 | 2% | 80 |
| 상한 -2 | 3% | 79 |
| 상한 -3~-5 | 9% | 우수 |
| 상한 -6~-10 | 20% | 준수 |
| 상한 -11~-20 | 35% | 보통 |
| 상한 -21 이하 | 30% | 낮음 |

소비금이 낮을수록 위 표를 아래쪽으로 밀어낸다. 즉, 100금은 “보통 이하”가 대부분이고, 1,000금은 “준수~우수” 비중이 높다. 상한값 1%는 유지한다.

적성 판정:

- 병종 적성도 능력치와 같은 “상한 대비 하락폭” 패턴으로 판정한다.
- 먼저 주최 장수의 병종별 적성을 한 단계 낮춰 생성 상한으로 삼는다.
  - 예: 주최 장수 도검병 A → 생성 장수 도검병 최대 B
  - 예: 주최 장수 기병 S → 생성 장수 기병 최대 A+
- 이후 상한에서 몇 단계 낮은지를 뽑는다.

| 상한 대비 결과 | 1,000금 기준 예시 확률 | 설명 |
|---|---:|---|
| 상한 등급 | 1% | B 상한이면 B |
| 상한 -1단계 | 4% | B 상한이면 C |
| 상한 -2단계 | 10% | B 상한이면 D |
| 상한 -3단계 | 20% | B 상한이면 F |
| 최저 등급 | 65% | 하한 F에 머무름 |

- 소비금이 낮을수록 능력치와 마찬가지로 아래쪽 구간 가중치가 커진다.
- 문과시험은 궁병, 공성, 보급/내정형 태그에 품질 보정 +1을 준다.
- 무과시험은 보병, 기병, 궁병 등 전투 병종에 품질 보정 +1을 준다.
- 어떤 경우에도 생성 상한을 넘지 않는다.

UI:

- `인재` 팔레트 하위에 `문과시험`, `무과시험`을 표시한다.
- 모달 구성:
  - 주최 장수 선택
  - 소비금 슬라이더 또는 100/300/500/700/1000 빠른 선택
  - 예상 품질 설명
  - 1년 재사용 제한 표시
- 완료 시 신규 장수 이름, 능력치, 병종 적성, 출신 도시를 결과 모달로 보여준다.

완료 기준:

- 장수 수급이 랜덤 탐색이 아니라 세력·도시 목표 달성 보상으로 작동한다.
- 다른 세력이 도시를 점령해도 도시형/지역형 위인과 이벤트 보상을 통해 정복 가치가 생긴다.
- 세력이 멸망해도 잠긴 세력형 위인은 삭제되지 않고 유랑 위인으로 재분배된다.
- 플레이어와 AI가 같은 규칙으로 위인을 해금하고 영입할 수 있다.
- 장수가 부족한 세력은 문과시험·무과시험으로 범용 장수를 제한적으로 보충할 수 있다.

검증:

- 위인 해금 조건 판정 테스트
- 세력 멸망 시 잠긴 위인 유랑화 테스트
- 도시 점령/상실에 따른 도시형 위인 해금 가능성 테스트
- 해금 상태 저장/로드 테스트
- AI 영입 가능 조건 테스트
- Game 빌드

- `feat: 세력별 위인 해금 시스템을 추가`

### 편집 범위

| 대상 | 편집 및 검증 규칙 |
|---|---|
| 장수 선택 | ID·이름 검색, 세력/지역 필터, 목록에서 현재 편집 대상 표시. ID는 읽기 전용이며 재번호화 금지 |
| 능력치 | 무력·지력·정치 1~100 정수. 유효 범위를 벗어나면 저장 전 오류 표시 |
| 병종 적성 | 보병·궁병·기병·상병·공성·해상·보급·수성 각각 F/D/C/B/A/A+/S/SS/SSS 선택 |
| 전투 액티브 | `active-skills.json`에서 최대 1개 선택 또는 해제. 전환 예정과 실제 등록된 스킬을 구분하고 미등록 코드는 저장 불가 |
| 전투 패시브 | `passive-skills.json`에서 선택·해제·티어 1~3 수정. 전투 스킬 합계 0~4개, 같은 코드 중복 금지 |

선택한 스킬의 설명을 함께 표시한다. 장수의 이름·출생년·해금 가능 년도·설명·기타 기존 필드는 편집 범위 밖이어도 저장 시 보존한다. 게임 실행 중 상태나 세이브의 성장 수치를 직접 수정하지 않는다. 원본 수정은 새로 데이터를 로드할 때 반영한다.

### 원형 얼굴 데이터

출전 부대를 선택했을 때 원 안에 장수 얼굴이 나오는 향후 UI를 위해, 원본 일러스트를 훼손하지 않는 **구도 메타데이터**를 저장한다.

제안 파일: `data/general-portraits.json`. 다음 필드는 신규 계획이며 현재 로더에 이미 존재하는 필드가 아니다.

| 필드 | 형식·기본값 | 의미 |
|---|---|---|
| `general_id` | 기존 장수 ID, 고유 키 | `generals.json`과 연결. 미등록 ID 저장 불가 |
| `portrait_path` | 저장소 내 상대 경로, 기본 `SanguoSLG.Game/assets/portraits/{id}.png` | 전체 일러스트 경로. 절대 경로 저장 금지, 게임에서는 리소스 경로로 변환 |
| `face_center_x` | 0~1, 기본 0.5 | 얼굴 영역 중심 X를 원본 너비로 정규화 |
| `face_center_y` | 0~1, 기본 0.35 | 얼굴 영역 중심 Y를 원본 높이로 정규화 |
| `face_zoom` | 1~4 실수, 기본 1 | 기준 정사각형에서 확대. 범위는 에디터의 초기 제안값 |

얼굴 정사각형 한 변은 `min(원본 너비, 원본 높이) / face_zoom`이다. 중심 위치를 픽셀로 변환한 뒤 영역이 이미지 밖으로 나가지 않도록 보정하고 원형 마스크로 표시한다. 원형 안을 빈 여백 없이 채우되 이미지 비율은 유지한다. 미리보기와 게임은 같은 좌표 변환을 재사용한다. 기본 구도는 얼굴을 정확히 보장하지 않으므로 개별 조정이 가능해야 한다.

이미지·메타데이터가 없으면 기존 공용 장수 이미지와 기본 구도로 대체한다. 전체 일러스트는 자르지 않는다. 파일 확장자·이미지 존재·크기를 검증하고 잘못된 경로는 저장 전에 안내한다. 원본 장수 ID나 초상 PNG 파일명을 편집 때문에 바꾸지 않는다.

### 저장과 실행

- `run-general-editor.bat`는 자신의 위치를 기준으로 프로젝트·데이터 경로를 찾는다. 공백 경로를 지원하고 .NET Godot 실행 파일이 없으면 원인을 안내한다.
- 저장 버튼은 변경 전후 능력치·적성·스킬·얼굴 구도를 보여준다. 변경 없이 닫기와 초기값 복원도 제공한다.
- 장수 원본과 얼굴 메타데이터를 모두 검증한 뒤 저장한다. 저장 중 오류가 나면 두 파일의 변경이 일부만 남지 않도록 복원한다.
- 편집 중 외부에서 원본이 바뀌었으면 덮어쓰지 않고 다시 불러오기 또는 비교를 제공한다. 읽지 못한 필드나 다른 장수의 값도 보존한다.
- 백업은 D드라이브 프로젝트 아래 `tools/general-editor/backups/`에 날짜별로 저장한다. 임시 파일·백업은 Git에서 제외하고 실제 데이터 변경만 검토·커밋한다. C드라이브에 별도 기억 저장소를 만들지 않는다.
- 에디터가 자동으로 Git 커밋·푸시하지 않는다. 개발 작업 단위로 변경을 검증한 뒤 커밋·푸시한다.

- 적 부대/생산 이동 모델, 시설 생산 라벨, 성벽·주둔 수치, 클릭 상세, 피해/해골 효과를 현재 시야에 맞춰 제한한다. 도시 이름·소속과 정적 지도 외형은 계속 남긴다.

- 검증: Core·Game 빌드, 신규 17개 포함 총 665개 테스트 통과(장수 데이터는 커밋본 기준). 로컬 미커밋 제갈량 스킬과 기존 테스트 기대값 불일치 1건은 별도다.

목표: 도시 계략 `정찰`을 단순 정보 해금이 아니라 전장 판단을 바꾸는 정보전 시스템으로 확장한다. 먼저 정찰 완료 상태를 맵에서 눈에 띄게 보여주고, 이어서 성·부대 시야를 기준으로 전장의 안개를 적용한다.

권장 순서:

1. **정찰 완료 월드 표시**

## Phase 10D. 출전 부대 명령 팔레트

목표: 성에서 출전한 부대를 다시 선택했을 때 전장 상황에 맞는 명령을 내릴 수 있게 한다. 현재 구 로드맵에는 출전 부대 명령 계획이 있고 일부 이동·정지 계열은 구현되어 있으나, v2 로드맵에는 독립 단계로 없었다. 정찰/전장의 안개 이후, 보급부대 UI와 집단군으로 확장하기 전에 일반 전투부대 조작을 먼저 완성한다.

우선 범위:

1. **부대 선택 정보 팔레트 정리**
   - 출전 부대를 클릭하면 장수 초상, 병종, 병력, 훈련도, 군량/보급 상태, 현재 목표, 현재 업무를 표시한다.
   - 아군 부대는 명령 버튼을 표시하고, 적군 부대는 시야/정찰 규칙에 따라 정보만 표시한다.
   - 담당자·연구·외교·탐색 등 다른 업무와 같은 `현재 담당업무` 표현을 사용한다.

2. **이동·공격·정지·복귀 명령**
   - 이동: 행군/전진/공격 모드를 유지하고, 목적지 선택과 경로 프리뷰를 제공한다.
   - 공격: 적 부대 또는 적 성을 대상으로 지정하면 공격 모드로 목표를 갱신한다.
   - 정지: 현재 목표와 경로를 지우고 다음 진행부터 대기한다.
   - 복귀: 원 소속 성 또는 가장 가까운 아군 성을 선택해 복귀 목표를 설정한다. 성 도착 시 주둔 병력으로 편입한다.

3. **전투 액티브 스킬 명령**
   - Phase 14A 이후 부대 계략 대신 장수 액티브 스킬을 사용한다. 도시 계략은 성 명령에 유지한다.
   - Phase 10D 1차에서는 이미 등록된 액티브 스킬의 사용 가능 여부, 충전 상태, 대상 조건만 UI에 보여준다.
   - 실제 신규 효과 수치와 계략 전환 액티브 구현은 Phase 14A/15에서 진행한다.

4. **보급부대와 생산부대 처리**
   - 보급부대는 공격 명령을 받지 못하고 이동/정지/복귀 중심으로 조작한다.
   - 생산 중인 500명 채집 부대는 시설 내부 상태이므로 일반 명령 팔레트를 띄우지 않는다.
   - 생산 이동/복귀 중인 부대는 일반 부대처럼 선택 가능하되, 취소 불가 규칙 때문에 목적지 변경을 제한한다.

5. **명령 검증과 보고**
   - 진행 중 재생 상태에서는 새 명령을 받을 수 없고 실패 사유를 작은 모달/토스트로 표시한다.
   - 명령 변경 성공, 목표 상실, 복귀 완료, 전멸은 좌측 하단 `보고`에 남긴다.
   - 전장의 안개 밖 대상이나 60일 정찰 만료 후 정보가 없는 적 성은 대상 지정에서 제외한다.

완료 기준:

- 아군 출전 부대를 클릭하면 정보와 명령 팔레트가 안정적으로 표시된다.
- 이동·공격·정지·복귀 명령이 Core 상태를 바꾸고 다음 `진행`에서 반영된다.
- 보급부대/생산부대/일반 전투부대의 명령 가능 범위가 서로 구분된다.
- 명령 실패 사유와 명령 결과가 UI와 보고 로그에 표시된다.
- Phase 14A 전까지는 부대 계략 UI를 새로 확장하지 않고, 액티브 스킬 슬롯 표시까지만 연결한다. 도시 계략 UI는 유지한다.

검증:

- Game 빌드: 부대 선택 팔레트, 목적지 지정, 경로 프리뷰, 보고 로그

## Phase 11B. 보급부대 적성·스킬·모션 개선

목표: 보급부대가 단순 짐꾼처럼 보이지 않게 하되, 전투부대와 역할이 겹치지 않도록 “약하지만 중요한 병참 전투 단위”로 정리한다. 집단군보다 먼저 보급부대의 조작감과 성장 축을 고정한다.

기준 자료:

- `tools/blender/make_troop_archer.py`: 궁병 병사의 활·화살·화살통 구성과 손 화살 발사 구조를 참고한다.
- `SanguoSLG.Game/assets/models/troop-supply.glb`: 기존 대기/이동/공격 상태 모델을 유지하되, 병사 사격 모션을 보강한다.

확정 규칙:

- 보급부대 병종 적성을 신설한다.
- 보급 적성 등급은 다른 병종과 동일하게 `F, D, C, B, A, A+, S, SS, SSS`를 사용한다.
- 모든 장수의 병종 특성에 `보급` 항목을 추가한다.
- 기존에는 발휘되지 않던 보급부대 선봉의 액티브·패시브 스킬을 유효하게 전환한다.
- 단, 보급부대의 기본 공격력과 방어력은 계속 전체 게임 최저 수치를 사용한다.

## Phase 11C. 수성 적성·태수 방어전 개선

목표: 공성전에서 성이 단순 고정 포탑처럼 동작하지 않게 하고, 태수 임명과 수성 특화 장수의 의미를 만든다. 공격 측 집단군이 들어오기 전에 방어 측 규칙을 먼저 정리한다.

확정 규칙:

- 성에 `태수`로 임명된 장수의 액티브·패시브 스킬만 공성전 방어에 영향을 준다.
- 같은 성에 있는 나머지 장수의 액티브·패시브 스킬은 공성전 방어에 발휘되지 않는다.

- 원래 태수가 복귀해도 진행 중에는 즉시 교체하지 않고, 해당 `진행`이 끝난 뒤 방어 지휘권을 다시 넘겨받는다.

- 수성 적성 등급은 다른 병종과 동일하게 `F, D, C, B, A, A+, S, SS, SSS`를 사용한다.

## Phase 11D. 수송과 괴멸 전리품

목표: 전투부대·보급부대와 별개로, 주둔지의 병력·금·군량을 다른 성으로 옮기는 비전투 물류 명령을 만든다. 동시에 야전에서 부대가 괴멸될 때 들고 있던 금과 군량이 전장에 사라지지 않고 승리 측 전리품으로 이어지게 한다.

상태(2026-09-14):

- Core 수송 도메인, 편성, 이동, 입성 정산, 괴멸 전리품 이전 구현 완료.
- Game 수송편성 UI와 목표 지정 흐름 구현 완료.
- 자동 QA는 통과했으며, 최종 화면/손맛은 `run-maptest.bat` 실기기 확인 대기.

확정 규칙:

- **수송**은 주둔지에 있는 병력과 물자를 다른 아군 성으로 이동하는 기능이다.
- 수송 부대는 장수 1명을 편성하고, 출발 즉시 야전 부대로 생성되며 **행군모드**로 전환된다.
- 수송 부대는 보급부대와 달리 **공격과 방어가 불가능**하다.
- 수송 부대의 이동속도는 **2**다.
- 수송 가능한 병력은 한 번에 최대 **50,000명**이다.
- 수송 가능한 금과 군량은 사용자가 원하는 만큼 지정할 수 있다. 단, 출발 성 보유량을 초과할 수 없다.
- 수송 중 군량 소비는 일반 부대보다 **50% 감소**한다.
- 수송 부대가 목적 성에 도착하면 병력은 해당 성의 대기 병력으로, 금과 군량은 해당 성 비축으로 합산된다.
- 수송 부대가 괴멸되면 들고 있던 금과 군량은 공격한 상대 부대가 가져간다.
- 괴멸 전리품의 금은 무제한으로 휴대한다.
- 괴멸 전리품의 군량은 **휴대 한도를 초과해도 보유 가능**하다. 이 규칙은 시설 약탈 군량의 휴대 한도 규칙보다 우선한다.

구현 확인:

- `CombatUnit.IsTransport`, `CargoGold`, 병종별 `SupplyCargo`를 통해 수송 부대의 병력·금·군량을 표현한다.
- `DeployService.DeployTransport`는 같은 세력의 다른 성만 목적지로 허용하고, 장수 1명·병종 N개·금·군량을 예약한다.
- 수송 부대는 행군모드·속도 2·전투 불가로 움직이며, 목표 성에 인접하면 공격턴 전에 즉시 입성한다.
- 입성 시 병종별 대기 병력, 금, 군량이 목적 성에 예치된다.
- `CampaignEngine`은 괴멸한 야전 부대의 금과 군량을 최근접 상대 생존 부대에 이전한다.

## Phase 11A. 집단군 편성·출전

목표: 보병·궁병·공성 병기를 하나의 대규모 혼성 부대로 묶어, 공성전과 대규모 야전의 선택지를 만든다.

상태(2026-09-14): **1차 구현 완료, 시각 손맛은 후속 보강**

이 단계는 현재 Core 규칙, Game 편성 UI, 출전 예약, 목표 지정, 월드맵 표시, 전투 연결, AI 1차 운용까지 들어가 있다.
문서상 "작업 예정"으로 남아 있던 항목을 실제 구현 기준으로 정리한다.

기준 문서:

- [plan-roadmap.md](./plan-roadmap.md)의 **집단군 시스템**
- [spec-unit.md](./spec-unit.md)의 **집단군**
- [design-combat.md](./design-combat.md)의 **집단군 전투 규칙**

확정 규칙:

- 집단군은 보병 + 궁병 + 공성 병기로 편성한다.
- 공성 병기는 투석기 또는 벽력거 중 하나를 선택한다.
- 기본 최대 총병력은 **30,000명**이고, 집단군 연구로 최대 **40,000명**까지 확장한다.
- 집단군은 최소 편성 규칙을 만족해야 한다. 보병·궁병·공성 병기 각 병과가 최소 병력을 포함해야 한다.
- 각 성은 **자신을 편성 원점으로 하는 집단군을 동시에 최대 1개만** 보유한다.
- 출전 중인 집단군도 원 소속 성의 1개 제한에 포함한다.
- 월드맵에서는 구성 병종 수와 관계없이 **1개 부대 / 1개 타일 점유**로 표시한다.
- 1차 모델 에셋은 `SanguoSLG.Game/assets/models/troop-army-group.glb`를 사용한다.
- 이동속도는 **1칸/일 고정**이다.
- 유닛/건물/성 공격 사거리는 모두 **1**이다.
- 유닛 대상 공격 능력은 성의 유닛 공격 능력을 참조한다.
- 건물/성 대상 공격 능력과 방어 DF는 공성탑 기준을 참조한다.
- 집단군은 액티브 스킬을 발동하지 않는다.
- 집단군 병종 특성은 선봉 장수의 보병·궁병·공성 적성을 평균낸 뒤 반내림한다.
  - 예: S/A/S = A+
  - 예: S/A/A = A
- 집단군은 선봉과 부관을 선택할 수 있다.
- AI 집단군 운용 1차 규칙:
  - 적 성의 주둔 병력이 내 주력 병종 주둔 병력보다 많을 때 고려한다.
  - 현재 성의 보병·궁병·공성 편성 가능 병력이 40,000명 이상일 때 고려한다.
  - 현재 성의 자유 장수가 4명 이상일 때 고려한다.
  - 각 보병·궁병·공성 병력은 기본적으로 절반씩 편성한다.
  - 선봉은 집단군 적성이 높은 장수를 우선한다.
  - 부관은 가능한 경우 함께 편성하고, 부족하면 선봉만 편성할 수 있다.
  - 선봉 후보가 기병·상병·해상 등 다른 병종에서 S급 이상이면 집단군 선봉에서 제외하고 해당 특화 병종 운용 여지를 남긴다.

## Phase 11E. 항구·선박 생산·해상 전환

목표: 항구를 약한 성벽을 가진 해상 거점으로 정리하고, 항구에서 선박을 생산·저장·출전시키는 해상 전투 축을 연다.

핵심 규칙:

- 항구는 기존 계획처럼 일반 성과 같은 거점이다.
  - 소형 항구와 중형 항구만 존재한다.
  - 성벽이 있지만 일반 성보다 매우 약하다.
  - 공격받아 함락/탈취될 수 있다.
- 항구 주둔 병력은 금과 군량을 소비하지 않는다.
- 항구는 7일 단위로 금과 군량을 소량 생산한다.
  - 소형 항구: 기준 수입.
  - 중형 항구: 소형 항구의 2배 수입.
- 항구는 선박을 생산하고 저장한다.
  - 소형 선박: 생산 기간 2주.
  - 중형 선박: 생산 기간 1개월.
  - 대형 선박: 생산 기간 2개월.
  - 거북선은 이벤트성 유닛으로 분리하고, 이 단계의 일반 선박 생산 대상에서 제외한다.
- 선박 1척당 탑승 가능 병력은 10,000명이다.
  - 20,000명 출전에는 선박 2척이 필요하다.
  - 실제 병종이 보병·궁병·기병·상병·공성이어도 승선 출전 시 해상 선박 유닛으로 자동 전환한다.
  - 승선 전 병종 정보는 “하선/후속 상륙전” 확장을 위해 원본 병종으로 보존한다.
- 항구가 적에게 탈취되면 항구에 저장 중인 선박은 전부 새 점령 세력에게 넘어간다.

## Phase 11F. 일괄전투편성

목표: 사용자가 전투부대를 하나씩 추가하는 반복을 줄이기 위해, 도시 주둔 병력과 가용 장수를 분석해 최대 5개 전투부대 초안을 한 번에 만든다.

진입/흐름:

- 성의 `출전` 하위 메뉴에 `전투편성 → 일괄전투편성 → 보급편성 → 수송편성 → 집단군편성` 순으로 배치한다.
- `일괄전투편성`은 즉시 출전시키지 않는다. 자동 추천된 편성 초안을 사용자가 검토·수정하고 확인한 뒤 기존 `전투편성` 목록 화면으로 돌아간다.
- 이후 목표, 이동 경로, 공격 방법 등은 기존 전투편성 흐름에서 부대별로 선택한다.
- 취소하면 병력·장수 상태는 전혀 변경하지 않는다. 최종 출전 확정 시 기존 `DeployService` 검증과 차감을 그대로 사용한다.

편성 표 UI:

| 부대 넘버링 | 장수 1 | 장수 2 | 병종 | 병력수 |
|---|---|---|---|---|
| 1~5 | 선봉 드롭다운 | 부관 드롭다운 | 병종 드롭다운 | 숫자 텍스트필드 |

- 장수 드롭다운 항목은 이름, 현재 업무, 선택 병종 적성, 무력을 함께 표시한다.
- 병종 드롭다운은 해당 도시에 실제 주둔한 병종만 보여준다.
- 병력수는 숫자 직접 입력을 기본으로 하며 해당 병종 잔여량과 세력 통솔 병력 연구 상한을 넘을 수 없다.
- 자동 추천 뒤에도 각 행을 삭제하거나 장수·병종·병력수를 수정할 수 있다.
- 중복 장수, 중복 차감, 출전 불가 업무는 행 단위 오류로 표시하고 확인 버튼을 비활성화한다.

자동 추천 규칙:

1. 주둔 병력이 10,000명 이상인 병종을 우선 후보로 삼아 병종별 10,000명 편성을 먼저 만든다.
2. 최대 5개 부대까지만 만들며, 같은 병종의 잔여 병력이 충분하면 추가 부대 후보가 될 수 있다.
3. 모든 부대의 선봉을 먼저 배치한다.
   - 선택 병종 적성 S 이상 장수를 최우선으로 한다.
   - 같은 적성 등급이면 무력이 높은 장수를 우선한다.
   - 그다음 적성 등급 내림차순, 무력 내림차순, 장수 ID 오름차순으로 결정론을 보장한다.
4. 선봉 배치가 끝난 뒤 남은 가용 장수로 모든 부대의 부관을 배치한다.
   - 부관도 해당 병종 적성 내림차순, 무력 내림차순, 장수 ID 오름차순으로 정한다.
   - 가용 장수가 부족하면 부관은 비워둘 수 있다.
5. 담당자·연구·성벽·계략/계략형 액티브·외교·탐색·생산·출전·보급·수송 중인 장수는 기존 업무 교체 컨펌 없이는 자동 추천 대상에서 제외한다.
6. 태수와 군사는 겸임 가능이라는 기존 규칙을 유지한다.

구현 분할:

1. Core 자동 추천기와 결정론적 우선순위 테스트
2. 최대 5개 편성 초안·가용 병력/장수 예약 검증
3. 일괄편성 표 UI와 행 수정·삭제·오류 표시
4. 기존 전투편성 목록으로 초안 인계 및 최종 출전 연결
5. 저장 상태 비변경·취소·부족 자원·업무 충돌 적대적 QA

완료 기준:

- 한 번의 추천으로 최대 5개 유효한 전투편성 카드가 기존 전투편성 목록에 생성된다.
- 자동 추천 결과를 사용자가 수정할 수 있고, 목표 선택 전에는 부대가 출전하거나 자원이 차감되지 않는다.
- 동일 입력은 항상 동일한 추천 결과를 만든다.

## Phase 14. 패시브 스킬 레벨 1~3

목표: 전투·내정 패시브를 장기간 운용한 장수만 상위 레벨에 도달하도록 성장 속도를 무겁게 재설계한다.

상태: **구현 완료 (2026-09-18)**. 기존 패시브 경험치 획득·효과·상세 UI 흐름을 유지하면서 확정 성장 곡선과 최대 레벨 처리를 적용했다. 액티브 효과와 이펙트는 사용자 후속 지시 전까지 변경하지 않는다.

확정 원칙:

- 패시브 스킬 레벨은 `Lv.1~3`만 존재한다.
- 전투 패시브와 내정 패시브 모두 같은 필요 경험치 곡선을 사용한다.
- 액티브 스킬에는 레벨과 경험치가 없다. 최초에 정의된 고정 효과를 항상 그대로 사용한다.
- 패시브는 상시 능력 보정이므로 별도의 전투 이펙트를 재생하지 않는다.
- 액티브는 실제 발동 사건이므로 Phase 15에서 스킬별 이펙트·배너·피해/회복 표현을 반드시 연결한다.

필요 경험치:

| 스킬 레벨 | 다음 레벨 필요 경험치 | 현재 지급량 기준 체감 |
|---:|---:|---|
| Lv.1 → Lv.2 | **500** | 전투 50회 또는 훈련 약 34회 수준 |
| Lv.2 → Lv.3 | **2,000** | 전투 200회 또는 훈련 약 134회 수준 |
| Lv.3 | MAX | 더 이상 경험치를 저장하지 않음 |

- 위 횟수는 한 종류의 활동만 반복했을 때의 비교값이며 실제 플레이에서는 전투·훈련·내정 활동이 섞인다.
- Lv.2는 숙련 장수, Lv.3는 캠페인 후반의 핵심 장수를 나타내야 한다. 짧은 반복 작업으로 Lv.3에 도달하지 않게 한다.
- 밸런스 QA에서 평균 시나리오 종료 시 Lv.3 장수가 지나치게 많으면 필요 경험치를 다시 상향한다.

경험치 획득:

- 전투 패시브: 실제 교전 참가 +10, 장수 훈련 +15.
- 내정 패시브: 관련 담당 업무 주간 정산 +10, 생산 작전 완료 +30, 장수 훈련 +15.
- 실제 효과가 발생하지 않은 취소 명령이나 미완료 작업에는 지급하지 않는다.
- 한 사건에서 같은 패시브에 경험치를 중복 지급하지 않는다.

작업:

1. 기존 임시 필요 경험치 `100 / 200`을 `500 / 2,000`으로 교체한다.
2. 전투·훈련·담당·생산 획득처의 중복 및 완료 조건을 전수 검사한다.
3. 패시브 정의의 Lv.1~3 수치가 실제 계산과 설명 UI에서 일치하도록 검증한다.
4. 장수 상세에 패시브 Lv, 현재 경험치, 다음 레벨 필요 경험치 또는 `MAX`를 표시한다.
5. 레벨 상승은 보고와 결과 UI로 알리되 별도 3D/전투 이펙트는 사용하지 않는다.
6. 장기 시뮬레이션으로 Lv.2·Lv.3 도달 속도를 검증한다.

완료 기준:

- 패시브만 Lv.1~3으로 성장하고 액티브에는 레벨·경험치가 생성되지 않는다.
- Lv.1→2와 Lv.2→3 모두 상당한 누적 활동을 요구한다.
- 패시브 레벨별 효과, 상세 설명, 실제 전투·내정 계산이 일치한다.
- 패시브 성장 알림은 제공되지만 액티브 전용 시각 이펙트를 재사용하지 않는다.

검증:

- 패시브 `499 + 1`, `1,999 + 1` 경계 승급 테스트
- Lv.3 경험치 0 및 추가 경험치 무시 테스트
- 활동 취소·미완료·중복 지급 방지 테스트
- 액티브 데이터에 레벨·경험치가 없음을 검증하는 데이터 테스트
- 패시브 Lv.1~3 실제 효과 및 UI 설명 일치 테스트
- 1,000턴 Sandbox 성장 분포 검증

권장 분할:

1. 필요 경험치 곡선·세이브 호환
2. 전투 패시브 획득처 검증
3. 내정 패시브 획득처 검증
4. 레벨별 효과·설명 일치 검증
5. 성장 UI·보고 및 장기 밸런스 QA

구현 기록 (2026-09-18):

- `GeneralGrowth`의 임시 `100 / 200` 곡선을 `500 / 2,000`으로 교체했다.
- Lv.3은 경험치를 저장하지 않으며, 대량 경험치가 한 번에 들어와도 Lv.3을 넘지 않는다.
- 전투·훈련·내정 담당·생산에서 사용하는 공용 성장 함수가 동일한 곡선을 따르는지 회귀 테스트했다.
- 패시브 Lv.1~3 효과 계산과 기존 상세 UI의 `현재/필요 경험치` 및 `MAX` 표시는 공용 필요 경험치 함수를 그대로 사용한다.
- 액티브 스킬의 고정 효과·발동·이펙트 코드는 이번 단계에서 수정하지 않았다.

## Phase 14A. 도시 계략 유지·부대 액티브 통합

설계 원본: [design-stratagem.md](./design-stratagem.md), [design-skill-actives.md](./design-skill-actives.md). 신규 효과는 아직 구현하지 않았다. 액티브는 레벨 없는 고정 효과이므로 Phase 14와 독립적으로 기존 5일 충전 체계에 전환한다.

> **2026-09-18 확정 경계:** 도시에서 수행하는 `정찰`, `방화`, `성벽파괴`, `선동`, `절취`는 기존 도시 계략으로 유지한다. `낙뢰`, `화계`, `혼란`, `교란`, `이간`, `소화`, `진정`만 앞으로 부대 계략이 아닌 **전투 액티브 스킬**이라 부르며, 기존 액티브 공용 정책인 **5일 충전**을 유지한다. 사용자가 액티브별 최종 효과를 별도로 전달하기 전까지 효과 수치·대상·광역·상태·이펙트는 임의 구현하지 않는다.

| 상태 | 단계 | 작업 | 완료 기준 |
|---|---:|---|---|
| ✅ | 0 | 도시/부대 기능 경계·미정의 발동 차단 | 도시 계략 팔레트 유지, Tactic 배정·5일 게이지 보존, 허위 발동 없음 |
| ⬜ | 1 | 공용 액티브 데이터·발동 조건 확장 | 사용자 확정안으로 지력 조건·대상·광역·상태 지속을 표현 |
| ⬜ | 2 | 화계·낙뢰 | 2% × 2진행, 중심 10%/주변 5%, 동맹 제외·생산 부대 포함 테스트 |
| ⬜ | 3 | 혼란·교란·이간·정화 | 혼란 1진행, 교란 이동 전 4→3→2→1칸 후퇴, 소화·진정 자신 중심 2칸 범위, 중첩·정화 검증 |
| ⬜ | 4 | 도시 계략 회귀 검증 | 정찰·방화·성벽파괴·선동·절취의 기존 파견·성공 판정·정찰 60일 유지 |
| ⬜ | 5 | UI·AI·이전 데이터 정리 | 도시 계략 팔레트 유지, 부대 모략력·숙달·예약만 제거, 삭제 4종 미노출, 기존 액티브 보존 |

각 단계 후 커밋·푸시한다. 기존 저장 상태의 계략 예약·상태·숙달은 버전별로 변환하거나 폐기 안내하며, 로딩 실패와 이중 발동을 방지한다. Game의 신규 설명은 실제 적용된 효과만 표시하고 구현 전 수치를 동작 중인 것처럼 안내하지 않는다.

선행 구현 기록 (2026-09-18):

- 도시 계략과 부대 액티브의 경계를 확정하고, 직전 선행 작업에서 숨겼던 도시 `계략` 그룹을 복구했다.
- `Tactic` 액티브는 최종 효과가 확정될 때까지 자동 발동하지 않으며, 5일 게이지도 소비하지 않는다.
- 선봉의 `Tactic`이 대기 중이어도 준비된 부관의 기존 타격·방어·회복 액티브는 정상 발동한다.
- 장수 배정 코드와 기존 레거시 계략 상태는 삭제하지 않아 데이터 손실을 피했다.
- 화계·낙뢰·혼란·교란·이간·소화·진정의 실제 효과는 사용자 확정안 수신 후 구현한다. 도시 계략 5종은 기존 동작을 유지한다.

효과 확정 추가 (2026-09-18):

- 소화·진정은 시전자 자신을 포함한 헥사 거리 2 이내 모든 방향의 아군을 대상으로 한다.
- 혼란은 대상의 행동을 1진행 동안 막고 자동 회복한다.
- 교란은 일반 이동 전에 처리하며 4칸 도착 가능 지점을 우선 찾는다. 불가능하면 3칸, 2칸, 1칸 순으로 축소하고 모든 후보가 막혔으면 위치를 유지한다.

### 보고 팔레트 확장 구성

성이 많아지면 좌측 하단 보고 팔레트에 모든 도시의 자동내정·전투·명령 결과가 한꺼번에 쌓여 전황 판단을 방해한다. 보고 팔레트는 다음 구조로 확장한다.

| 층위 | 표시 방식 | 목적 |
|---|---|---|
| 기본 보기 | 중요 보고만 노출: 전투, 함락, 명령 실패, 큰 손실, 선택 도시 자동내정 | 진행 직후 즉시 판단 |
| 요약 보기 | `자동내정 요약: 금 +n / 군량 +n / 병력 +n / 훈련도 +n / 치안 ±n`처럼 세력 합계 1줄 | 성이 많을 때 숫자 흐름 압축 |
| 필터 | 전체, 전투, 내정, 도시, 경고 버튼 | 플레이어가 보고 싶은 사건만 선택 |
| 도시 필터 | 현재 선택 도시 우선, 전체 모달에서 도시별 접기/펼치기 | 다도시 운영 시 탐색 비용 감소 |
| 중요도 | 경고/손실은 항상 상단 고정, 일반 내정은 접힌 상태 허용 | 놓치면 안 되는 사건 보호 |

구현 순서:

1. 보고 타입 enum 또는 문자열 태그를 추가한다.
2. 자동내정 보고는 도시별 상세와 세력 합계 요약을 동시에 만든다.
3. 좌측 하단 기본 팔레트는 요약과 중요 보고만 보여준다.
4. `전체` 보고 모달에서 타입/도시 필터와 접기/펼치기를 제공한다.
