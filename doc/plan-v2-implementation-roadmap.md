## 2. 전환 원칙

1. Core 삭제보다 UI 숨김/대체를 먼저 한다.
2. 기존 세이브 호환을 당장 깨지 않는다.
3. 전투·보급·성장·탐색·생산을 먼저 플레이 가능하게 만든다.
4. 제거 대상은 한 커밋에서 전부 지우지 않고, 사용 경로 제거 → 테스트 수정 → 데이터 정리 순서로 간다.
5. Game UI는 “전투에 필요한 선택”만 보이게 줄인다.
6. 기존 문서와 충돌하는 항목은 v2 문서를 우선한다.

## Phase 2. 자동 담당자 내정 4슬롯

목표: 내정을 수동 명령이 아니라 담당자 배치형 자동 성장으로 바꾼다.

작업:

- 도시별 담당자 슬롯 추가:
  - 치안 담당
  - 내정 담당
  - 병력 담당
  - 훈련 담당
- 담당자 지정/해제 Command 또는 Service 추가
- 월말 자동 처리 추가:
  - 치안: 무력 영향
  - 금/식량: 정치 영향
  - 병력: 무력 영향
  - 훈련도: 무력 영향
- 담당자가 없으면:
  - 금/식량/병력/훈련도 현상 유지
  - 치안만 하락

추천 초기 수치:

| 항목 | 공식 |
|---|---|
| 치안 회복 | 무력 60 미만 +0, 60~79 +1, 80~99 +2, 100 이상 +3 |
| 담당자 없음 치안 | 매월 -2 |
| 금 생산 | 기본 100 + 정치 × 2 |
| 식량 생산 | 기본 300 + 정치 × 5 |
| 병력 생산 | 기본 200 + 무력 × 5 |
| 훈련도 증가 | 무력 60 미만 +1, 60~79 +2, 80~99 +3, 100 이상 +4 |

월말 처리 순서:

1. 병력 담당이 먼저 훈련도 50%의 병력을 도시 대기 병력에 합류시킨다.
2. 같은 도시·같은 병종이면 기존 병력과 신규 병력의 훈련도를 병력 수 기준 가중 평균 후 정수 반올림으로 산정한다.
3. 훈련 담당이 그 이후 전체 대기 병력에 월 훈련도 증가치를 적용한다.

완료 기준:

- 도시 담당자를 지정하면 진행만 눌러도 도시 상태가 자동으로 변한다.
- 기존 세율·시장·모병·징병 없이도 도시가 최소한 굴러간다.
- 성 명령 팔레트의 `담당자`에서 4개 담당 슬롯을 지정하고, 성 정보/상세에서 현재 담당자를 확인할 수 있다.

검증:

- Core 단위 테스트
- `dotnet build`
- `dotnet test`

권장 커밋:

- `feat: 도시 자동 담당자 내정을 추가`

## Phase 3. 인구·세율·시장·모병·징병 제거 경로 정리

목표: 제거 확정 기능을 실제 게임 흐름에서 분리한다.

작업:

- 인구 표시 제거
- 세율 UI 제거
- 시장 UI 제거
- 모병/징병 UI 제거
- 병력 생산은 자동 담당자 결과로만 증가
- 기존 데이터 필드는 세이브 호환 때문에 당장 삭제하지 않되, 신규 흐름에서는 사용하지 않게 한다.

완료 기준:

- 플레이어가 인구/세율/시장/모병/징병을 볼 일이 없다.
- 전투 준비에 필요한 병력은 도시 특색 병종 자동 생산으로 공급된다.
- AI도 기존 수동 모병 명령을 발행하지 않는다. 병력 공급은 자동 담당자/도시 특색 병종 단계로 이관한다.

검증:

- Core 테스트 조정
- Game 빌드
- Godot headless build

권장 커밋:

- `refactor: 수동 병력 생산과 시장 UI를 제거`

## Phase 4. 자동 생산 병종 선택과 금 소비

목표: 모병/징병 대신 병력 담당자가 지정한 병종이 도시 금을 소비해 자동으로 쌓이게 한다.

작업:

- 도시 스키마에 자동 생산 병종 추가
- 병력 담당자 지정 모달에서 자동 생산 병종 복수 선택
- 병력 담당자는 7일 단위로 소규모 병력 생산
- 무력 100 장수 기준 월 약 5,000명 생산
- 도시 금을 확인하고 비용을 차감한 뒤 해당 병종의 대기 병력 증가
- 금이 부족하면 해당 생산 틱은 생산 없음
- 선택 가능 병종은 싼 병종부터 비싼 병종 순서로 표시
- 해상(대하) 병종은 자동 생산 불가 — 차후 항구의 “배 만들기” 기능으로 분리
- 도시 정보 UI에 “생산 병종/월 비용” 표시
- 출전 UI에서 해당 도시가 보유한 병종만 명확히 표시

완료 기준:

- 담당자 지정 시 자동 생산 병종을 선택할 수 있다.
- 월말 자동 내정에서 도시 금이 충분할 때만 지정 병종이 생산된다.
- 금 소비 비중은 `상병 > 기병 > 투석기/공성탑 > 보병 = 궁병 = 충차` 순서를 따른다.

검증:

- 병력 자동 생산 테스트
- Game 빌드

완료 커밋:

- `f79d1b8` 자동 병력 생산 병종 지정 저장
- `e9ad7ba` 자동 병력 생산 도시 금 비용 적용

## Phase 5. 병종 연구 유지 정리

목표: 기존 병종 연구를 v2에 맞게 유지하되, UI를 간결하게 한다.

작업:

- 병종 연구 Core 로직은 유지
- 연구 UI에서 공방 필요, 비용, 소요일을 간결하게 유지
- 병종 연구는 “세력 전투 교리”로 설명 변경

## Phase 11A. 집단군 편성·출전

목표: 보병·궁병·공성 병기를 하나의 대규모 혼성 부대로 묶어, 공성전과 대규모 야전의 선택지를 만든다.

기준 문서:

- [plan-roadmap.md](./plan-roadmap.md)의 **집단군 시스템**
- [spec-unit.md](./spec-unit.md)의 **집단군**
- [design-combat.md](./design-combat.md)의 **집단군 전투 규칙**

확정 규칙:

- 집단군은 보병 + 궁병 + 공성 병기로 편성한다.
- 공성 병기는 투석기 또는 벽력거 중 하나를 선택한다.
- 최대 총병력은 **40,000명**이다.
- 각 성은 **자신을 편성 원점으로 하는 집단군을 동시에 최대 1개만** 보유한다.
- 출전 중인 집단군도 원 소속 성의 1개 제한에 포함한다.
- 월드맵에서는 구성 병종 수와 관계없이 **1개 부대 / 1개 타일 점유**로 표시한다.
- 이동속도는 **1칸/일 고정**이다.
- 유닛/건물/성 공격 사거리는 모두 **1**이다.
- 유닛 대상 공격 능력은 성의 유닛 공격 능력을 참조한다.
- 건물/성 대상 공격 능력과 방어 DF는 공성탑 기준을 참조한다.
- 집단군은 액티브 스킬을 발동하지 않는다.

작업:

- Core 집단군 도메인 모델 추가
- 집단군 최대 병력 40,000 검증
- 성별 편성 원점 기준 1개 제한 검증
- 출전 중인 집단군도 원 소속 성 제한에 포함
- 보병/궁병/공성 병기 혼성 편성 검증
- 집단군 출전 명령 추가
- 이동속도 1, 사거리 1 고정 규칙 연결
- 집단군 전투 능력치 참조 규칙 연결
- 액티브 스킬 발동 차단
- 월드맵 집단군 표시 방식 추가
- 집단군 편성 UI 추가
- AI 집단군 편성·운용 기준 추가

권장 작업 분할:

1. Core 모델과 성별 1개 제한
2. 편성 검증과 출전 명령
3. 전투 능력치·사거리·액티브 차단
4. Game 편성 UI와 월드맵 표시
5. AI와 Sandbox 밸런스 검증

완료 기준:

- 한 성은 자신을 원점으로 하는 집단군을 동시에 1개만 보유한다.
- 집단군이 출전 중이어도 원 소속 성에서 새 집단군을 편성할 수 없다.
- 집단군은 최대 40,000명까지만 편성된다.
- 집단군은 1개 월드맵 부대로 이동하고 전투한다.
- 집단군 전투에서 액티브 스킬이 발동하지 않는다.

검증:

- 집단군 편성 성공 테스트
- 40,000 초과 편성 실패 테스트
- 성별 2개 편성 실패 테스트
- 출전 중 집단군이 있을 때 같은 원점 성 추가 편성 실패 테스트
- 혼성 편성 조건 실패 테스트
- 집단군 전투 능력치 참조 테스트
- 액티브 미발동 테스트
- Game 빌드
- Godot headless build

권장 커밋:

- `feat: 집단군 편성과 출전을 추가`

### 보고 팔레트 확장 구성

성이 많아지면 좌측 하단 보고 팔레트에 모든 도시의 자동내정·전투·명령 결과가 한꺼번에 쌓여 전황 판단을 방해한다. 보고 팔레트는 다음 구조로 확장한다.

| 층위 | 표시 방식 | 목적 |
|---|---|---|
| 기본 보기 | 중요 보고만 노출: 전투, 함락, 명령 실패, 큰 손실, 선택 도시 자동내정 | 진행 직후 즉시 판단 |
| 요약 보기 | `자동내정 요약: 금 +n / 군량 +n / 병력 +n / 훈련도 +n / 치안 ±n`처럼 세력 합계 1줄 | 성이 많을 때 숫자 흐름 압축 |
| 필터 | 전체, 전투, 내정, 도시, 경고 버튼 | 플레이어가 보고 싶은 사건만 선택 |
| 도시 필터 | 현재 선택 도시 우선, 전체 모달에서 도시별 접기/펼치기 | 다도시 운영 시 탐색 비용 감소 |
| 중요도 | 경고/손실은 항상 상단 고정, 일반 내정은 접힌 상태 허용 | 놓치면 안 되는 사건 보호 |

구현 순서:

1. 보고 타입 enum 또는 문자열 태그를 추가한다.
2. 자동내정 보고는 도시별 상세와 세력 합계 요약을 동시에 만든다.
3. 좌측 하단 기본 팔레트는 요약과 중요 보고만 보여준다.
4. `전체` 보고 모달에서 타입/도시 필터와 접기/펼치기를 제공한다.

바로 코드 작업을 시작한다면 아래 순서를 추천한다.

1. Phase 0 문서 기준 정리

이 순서가 좋은 이유:

- 먼저 보이는 복잡도를 줄인다.
- 그 다음 내정을 자동화한다.
- 병력 공급을 새 구조로 바꾼다.
- 보급부대를 UI에서 선명하게 만든 뒤, 대규모 공성 선택지인 집단군을 붙인다.

장수 성장과 이벤트 유닛은 매력적이지만, 먼저 도시/출전 흐름을 단순화해야 그 보상이 들어갈 자리가 생긴다.
