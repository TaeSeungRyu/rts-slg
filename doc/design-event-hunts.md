# 이벤트 사냥 — Phase 19 대호

상태: 2026-10-13 1차 구현·자동 QA 완료. 실제 대호 이동/공격 모습과 화면 구성은 사용자 플레이 검수 항목이다.

2026-10-13 1차 구현 기준. 탐색의 기존 신수 흔적 발견 확률은 유지한다. 고대유물 단서의 해석·장착 효과와 용·봉황 보상은 후속 작업이다.

## 출현과 행동

- `divine_beast_trace` 발견 이력 하나당 대호 출현 예약 하나를 저장한다. 발견 7일 후부터 출현하며 지도 전체에 활동 중인 대호는 최대 1마리다. 후속 예약은 대기한다.
- 발견한 도시 주변 2~6칸의 숲·산지 중 도시·시설·유적·건축물·부대와 겹치지 않는 타일을 거리, q, r 순으로 고른다. 장소가 없으면 예약을 유지한다. 모든 선택은 결정론적이다.
- 중립 적대 세력으로 플레이어와 AI 모두 공격할 수 있다. 이동 3칸/일, 탐지 2칸, 사거리 1칸. 전투 체력은 병력 환산 20,000, 공격 18·방어 12·적성 A다. 단일 대호 모델로 표시한다.
- 매일 이동 전에 탐지 범위의 육상 부대 중 현재 병력이 가장 적은 부대를 추격한다. 건물 주둔·출전 대기·해상 부대는 제외한다. 부대가 없으면 대기하며 성·시설·유적을 스스로 공격하지 않는다.
- 기존 이동턴→공격턴, 피해·부상·반격·괴멸 표현을 재사용한다. 대호는 장수·액티브·패시브·군량 소모가 없다.
- 수치는 `data/event-units.json`에 둔다. 이벤트 전용 목록으로 일반 생산·연구·출전 병종 목록에 섞지 않는다.

## 처치 보상

- 처치 공격턴의 실제 대호 교전 부대 중 피해를 가한 부대를 대상으로, 명령 순번→부대 ID 순으로 처치 기여 세력을 결정한다. 근처에 있다는 이유만으로 보상을 지급하지 않는다.
- 일반 교전 성장에 더해 처치 부대의 선봉·부관 각각 전투 경험치 250, 사용 병종 숙련 10을 지급한다. 집단군은 보병·궁병·공성에 적용한다. 기존 숙련 상한은 유지한다.
- 해당 세력 창고에 `호부` 1개를 등록한다. 호부는 사냥 증표이며 이번 단계에서 장착·능력치 보정은 부여하지 않는다.
- 동시 괴멸·재진행·저장 재개에도 처치 기록과 보물 지급은 한 번만 발생한다. 전투 기여가 확인되지 않은 소멸은 보상을 지급하지 않는다.
- 낙뢰·화계의 실제 대상/인접 범위에 포함된 대호는 시전 기여를 기록한다. 지속피해 처치는 저장된 최근 교전 기여자를 사용한다.
- 탐색 단서, 출현 예약, 활동 부대 ID, 처치일·보상 세력, 실제 보물 목록을 캠페인 저장에 보존한다. 기존 세이브에서 누락된 목록은 빈 목록이다.

## 화면과 QA

- 신수 흔적 결과에서 대호 사냥으로 이어지는 설명을 표시한다. 출현·처치는 보고에 표시하고 처치 후 보상 모달에서 사진·장수 경험치·숙련·호부를 안내한다.
- 대호 정보에서 위협도·공방·행동·보상을 확인한다. 기존 `troop-great-tiger.glb`와 `great_tiger.png`를 사용한다.
- 시스템의 단서·보물 보관함은 실제 호부 목록을 표시한다. 단서와 획득 보물은 별개다.
- `run-maptest.bat --event-hunt-sample`은 확정 출현 예약 샘플을 추가한다. 일반 실행의 탐색 확률을 변경하지 않는다.
- Core: 데이터 검증, 구 저장 호환, 출현 중복·부적합 장소, 활동 상한, 약한 부대 추격·건물 무시, 실제 처치·동시 괴멸·무기여 보상 금지, 저장 재개를 검사한다.
- Game: 빌드·Godot 헤드리스 로딩 및 대호 모델·카드·보고·보상 모달·보관함 연결 자동 QA. 실제 모션·화면 품질은 사용자 `run-maptest.bat` 검수로 구분한다.

실기기 확인: `run-maptest.bat --event-hunt-sample` → 진행 → 장안 주변 대호 출현 → 출전 부대로 공격 → 처치 보상 모달 → 시스템의 단서·보물 보관함에서 호부 확인. 샘플 인자는 최초 1회 출현 예약만 추가하고 탐색 확률은 변경하지 않는다.
