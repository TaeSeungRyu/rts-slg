# 설계 노트 — 외교와 군주 관계도

> 현재 외교는 동맹/동맹파기와 도시 대상 선전 포고를 지원한다. 동맹 성공률은 수행 장수 정치로 판정한다. 이후 군주별 관계도 데이터를 추가하면 이 문서를 기준으로 성공률 보정에 연결한다.

선전 포고는 적 도시 하나를 지정해 사절을 보낸다. 도시 계략과 같은 거리 비례 소요일이 지난 도착일에 발효되며, 발효일을 포함해 100일간 유효하다. 이동 중에는 점령 치안 보호 효과가 없다. 동맹 중인 세력에는 먼저 동맹을 파기해야 한다. 해당 도시를 유효 기간 안에 점령하면 포고 기록을 소진하고 기존 치안을 유지한다. 포고하지 않거나 만료 후 점령하면 기존 치안의 50~70%를 잃는다. 도시에 대한 모든 포고 기록은 소유권이 변경될 때 제거한다. 선전 포고한 적 도시는 시야 밖에서도 도시 타일이 흐리게 보이며 이름 위에 포고 기호와 남은 일수가 표시되지만, 정찰하지 않았다면 병력·성벽 등 상세 정보는 여전히 숨긴다.

발행할 때 대상 성의 모든 발자국 칸을 기준으로 반경 4칸 이내에 선포 세력의 출전 부대가 있으면 발행할 수 없다. 대기 출격 중이거나 병력이 0인 부대는 제외한다. UI는 실패 이유를 알림으로 보여준다.

## 1. 외교 범위

v2 외교는 전투 구도에 직접 영향을 주는 기능만 남긴다.

| 기능 | 유지 여부 | 설명 |
|---|---:|---|
| 동맹 | 유지 | 일정 비용을 내고 대상 세력과 공격 불가 관계를 만든다 |
| 동맹파기 | 유지 | 대상 세력 도시에 사절이 도착하면 동맹을 해제한다 |
| 포로교환 | 제거 | 장수 관리를 복잡하게 만들기 때문에 v2에서 제외 |
| 조공/협박/화친/공물 | 보류 | 전투 중심 리듬을 해치지 않는지 검증 후 후속 판단 |

## 2. 현재 구현 규칙

| 항목 | 규칙 |
|---|---|
| 동맹 비용 | 수행 도시 금고에서 `alliance_gold_cost` 소비 |
| 수행 기간 | 도시 계략과 같은 거리 비례 공식 사용 |
| 대상 위치 | 대상 세력의 가장 가까운 도시 |
| 성공 판정 시점 | 사절이 대상 세력에 도착하는 완료일 |
| 성공 확률 | 수행 장수 정치 `%` |
| 성공 결과 | 두 세력 사이에 동맹 상태 추가 |
| 실패 결과 | 동맹 없음, 비용은 환불하지 않음 |
| 동맹 중 제한 | 동맹 세력의 부대·생산시설·야전 건축물·성·항구 공격 불가. 자동 추격·AI 표적·도시/야전 공격 계략도 제외 |
| 동맹파기 | 동맹처럼 도시 간 거리에 따른 소요일을 적용하며, 도착 전까지 동맹을 유지한다. 대상 도시가 그 세력 소유가 아니거나 동맹이 이미 끝났다면 효과 없이 종료한다. |

동맹 체결 시 이미 지정된 동맹 대상 공격 명령은 대기로 전환하고 목표·경유지를 지운다. 동맹 파기 후에도 기존 공격 명령은 자동 복원하지 않으며 사용자가 새로 지정한다. 이동 중 동맹 체결이 이루어진 경우 공격턴 진입 전에 적대 판정을 다시 적용한다.

## 3. 군사 예측

동맹 실행 전 컨펌창에서 군사는 성공/실패 예상을 말한다.

| 값 | 의미 |
|---|---|
| 동맹 성공 확률 | 현재는 수행 장수 정치로 계산 |
| 군사 지력 | 예측이 실제 기대 결과와 일치할 확률 |

예시:

- 동맹 성공 확률 95%, 군사 지력 70 → 70% 확률로 “성공할 듯합니다”를 말한다.
- 동맹 성공 확률 95%, 군사 지력 100 → 항상 “성공할 듯합니다”를 말한다.
- 예측 실패 시 반대로 조언한다.

## 4. 군주 관계도 데이터 계획

향후 `ruler_relations.json` 또는 시나리오 파일에 군주별 관계도를 추가한다.

권장 스키마:

```json
[
  {
    "ruler_a": 1,
    "ruler_b": 2,
    "relation": 20
  }
]
```

| 필드 | 설명 |
|---|---|
| `ruler_a` | 첫 번째 군주 장수 id |
| `ruler_b` | 두 번째 군주 장수 id |
| `relation` | -100~100 관계도. 높을수록 동맹 성공 보정 상승 |

관계도는 세력 id가 아니라 **군주 장수 id** 기준으로 둔다. 같은 세력이라도 군주가 바뀌면 외교 성향이 달라질 수 있게 하기 위함이다.

## 5. 성공률 보정 계획

초안 공식:

```text
기본 성공률 = 수행 장수 정치
관계 보정 = relation / 4
최종 성공률 = clamp(기본 성공률 + 관계 보정, 5, 95)
```

예시:

| 수행 정치 | 관계도 | 최종 |
|---:|---:|---:|
| 80 | 60 | 95 |
| 80 | 0 | 80 |
| 80 | -80 | 60 |
| 30 | -100 | 5 |

상한을 95로 두는 이유는 외교가 완전히 확정적인 계산이 되지 않게 하기 위함이다. 단, 군사 지력 100은 “예측”을 100% 맞출 뿐, 동맹 성공 자체를 확정하지 않는다.

## 6. 후속 작업 목록

| 순서 | 작업 | 산출물 |
|---:|---|---|
| 1 | 군주 관계도 데이터 스키마 추가 | `RulerRelation`, loader, 테스트 |
| 2 | 시나리오 데이터에 군주 관계도 입력 | `data/ruler-relations.json` 또는 scenario 통합 |
| 3 | `DiplomacyRules.AllianceSuccessPercent`에 관계 보정 연결 | Core 테스트 |
| 4 | 동맹 컨펌 UI에 관계도 영향 표시 | “군주 관계 +15%” 같은 설명 |
| 5 | AI 외교 판단 | 적대/동맹 후보 선정 로직 |

## 7. 보류 판단

동맹 기간은 현재 데이터 구조에 `EndDay`가 있으므로 나중에 바로 붙일 수 있다. 다만 현재는 사용자가 명시적으로 “동맹/동맹파기”를 직접 통제하는 흐름이 더 읽기 쉬우므로, 자동 만료는 후속 밸런스 판단 뒤 적용한다.
