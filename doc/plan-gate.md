# Phase 21D. 관문 계획

상태: **21D-1~4 구현 및 Core 검증 완료, 21D-5 시나리오 에디터 연동 대기** (2026-10-28). [v2 로드맵 Phase 21D](plan-v2-implementation-roadmap.md#phase-21d-관문)의 상세 기준이다. 지도/시나리오 파일의 연결은 [Phase 21C](plan-scenario-editor.md)를 따른다.

## 역할과 기본 수치

관문은 성·항구와 별개의 **육상 거점 건물**이다. 소형 관문 내구도는 **2,000**, 중형은 **3,000**이다. 관문 하나에 주둔한 병력의 합계는 **100,000명 이하**다. 97,000명 주둔 중 4,000명 부대의 입장을 시도하면 일부만 받아들이지 않고 **부대 전체의 입장을 거부**한다. 부상병이 관문 안에 남는 표현을 허용할 경우 활동병+부상병을 모두 합쳐 상한을 계산한다. 관문은 육상 부대만 입장하며, 적 부대와 선박은 통과·입장할 수 없다.

관문에 들어간 부대는 성 수비와 같은 건물 방어/공성 판정을 받는다. 내구도가 남아 있으면 주둔 부대보다 건물이 먼저 피해를 받으며, 0이 되면 같은 공격턴의 후속 피해부터 노출된다. 내구도 0과 점령은 진행 7일 종료를 기다리지 않고 해당 공격턴에 반영한다. 관문은 성과 같이 세력 소유가 있고, 점령 시 기존 소유 세력의 주둔 부대·관문장 처리와 새 소유권 반영을 같은 전투 결과로 확정한다. 출입·복귀·패배 장수/부상병 귀환은 기존 거점 라이프사이클과 충돌하지 않도록 별도 테스트한다.

관문 주둔 병력의 군량 소비는 **기본 소비량의 50%**다. 타 보급/스킬 감면이 함께 있으면 21D-1에서 합성 순서를 기존 공식에 맞춰 확정하고, 중복 적용으로 소비량이 음수가 되지 않도록 한다. 관문은 부상병을 회복하지 않는다. 생산·연구·탐색·치안·내정·훈련·선박생산·별도 보급 생성도 하지 않는다. 관문은 금과 군량을 보관하며, 보유 금으로 7일 단위 내구도 수리를 할 수 있다. 주둔 중인 부상병은 회복되지 않으며 출전·정상 거점 복귀 후 기존 회복 규칙을 따른다.

## 관문장

같은 세력의 관문 주둔 장수 1명을 **관문장**으로 임명·해임한다. 관문장은 성 태수와 동일한 **수성 지휘관의 방어·반격 보정**을 적용한다. 태수의 세금/생산 보정은 관문에 그 기능이 없으므로 발생하지 않는다. 장수가 관문 밖으로 이동하거나 포로/이탈/소속 변경/관문 함락이 발생하면 임명을 자동 해제한다. 한 장수가 동시에 두 거점의 지휘관을 맡는 중복 임명은 금지한다. 관문장 없는 관문은 기존 무지휘관 수비 기본값을 쓴다.

## 편집·화면

- `run-editmap.bat`의 빈 육상 타일 팔레트에 **관문 추가**를 넣는다. 소형은 1타일, 중형은 방향에 따라 인접 2타일을 차지한다. 방향은 기존 성·항구처럼 6방향이다. 설치 예정 타일/출입 방향/인접 지형을 미리 보여주고 성·항구·유적·시설·다른 관문의 발자국과 겹치지 않게 한다. 추가 후 **관문 편집**에서 이름·소형/중형·방향 변경·제거를 지원한다. 방향은 외형과 출입구에 반영한다. 아군·동맹 육상 부대는 관문을 통과할 수 있다. 자기 관문을 목적지로 지정한 부대만 입장하며 적군과 선박은 통과할 수 없다.
- 게임에서 관문을 클릭하면 기존 **건축물 정보 모달**의 카드·내구도 표시를 재사용한다. 관문 이름/크기/소유 세력/내구도/보유 금·군량/군량 50% 절감/주둔 합계 `현재/100,000`을 표시한다. 하단에는 **출전·관문수리·관문장 임명·해임**과 **주둔병력현황**을 둔다. 주둔 목록은 병종별 수량·부상병·장수·입장 가능 잔여 병력을 보여준다. 적 관문은 보이는 정보만 표시하고 임명 버튼을 숨긴다.
- 관문장은 성 태수 선택 UI의 장수 사진·테이블/선택·확인 구성을 재사용한다. 100,000 초과 입장 시 현재/추가/상한 수치를 함께 보여준다. 내구도 0/주둔 제거/점령은 정보 모달과 맵 에셋에 즉시 반영한다.

## 데이터·AI·저장 계약

지도 프리셋에 관문 배치물의 고유 ID, 이름, 크기, 방향을 저장한다. 시나리오는 해당 지도 버전의 관문 ID를 참조해 시작 소유 세력, 내구도, 주둔 병력, 관문장을 정한다. 기존 지도에는 관문이 없어도 유효하다. 기존 세이브에는 관문 자료가 없어도 이전 상태로 열린다. 새 게임이 시작되면 지도/시나리오의 관문 배치를 스냅샷으로 복사해, 이후 맵 에디터 수정이 진행 중 게임을 바꾸지 않게 한다. 지도 교체로 관문이 사라지면 다른 거점으로 자동 이동시키지 않고 시나리오 에디터의 미배치 오류로 보여준다.

AI는 적 관문을 성과 같은 거점 목표로 인식하되 항구/성 공격 판단과 혼동하지 않도록 목표 유형을 구분한다. 아군 관문 입장과 100,000 상한, 적 관문 통행 금지, 공성 공격·방어·즉시 함락은 플레이어와 같은 규칙을 쓴다. 관문장이 없는 기본 시나리오에서도 AI가 정지하거나 병력이 사라지지 않게 검증한다.

| --- | --- | --- |
| 21D-1 | 관문 도메인·소/중 내구도·소유/주둔/관문장·용량/군량·저장 계약 | 97,000+4,000 거절, 정확히 100,000 허용, 부상병 포함, 50% 소비, 구 세이브 호환 xUnit |

| 21D-3 | `run-editmap.bat` 관문 추가/크기/방향/제거와 프리셋 검증 | 소형 1타일·중형 2타일 중복·경계·해안/험지 거부, 저장/재열기/새 게임 일치, 기존 지도 유지 |
| 21D-4 | 관문 정보 모달·관문장 임명·주둔병력현황·맵 에셋 | 정보/임명/주둔·상한 오류 UI headless QA와 실제 화면 검수 |
| 21D-5 | 시나리오 에디터 관문 초기 배치·AI 목표·통합 회귀 | 지도 교체로 관문 삭제 시 미배치 차단, AI 공격/수비, 기존 저장/신작 분리, 장기 진행 |

각 단계는 관련 QA 후 별도 커밋·푸시한다. 관문 에셋 제작 방식과 소형/중형 외형은 실제 화면 검수 전에 확정한다. 관문장 보정의 구체 수치는 현행 태수 수성 공식을 재사용하며 중복 보너스를 만들지 않는다.

## 구현 기록

- 원본 에셋 gate.glb(소형), gate-2tile.glb(중형)을 맵 에디터와 게임 양쪽에서 사용한다.
- 관문은 City.Gate로 구분하는 거점이며 기존 성의 입성·공성·점령 경로를 재사용한다. 일반 도시 생산·연구·수리 명령은 금지하고 관문장은 태수 임명의 수성 보정을 재사용한다.
- 현재 지도 프리셋의 관문 ID·이름·크기·방향과 게임 시작 스냅샷은 구현했다. 시작 소유권·병력·관문장 지정 UI는 Phase 21C 시나리오 에디터와 함께 연결해야 한다. 실제 화면의 모델 크기와 클릭 영역 검수는 남았다.

추가 개선(2026-10-28): 아군·동맹 통과, 기존 전투편성 UI를 통한 출전, 관문 자체 금·군량 보관 및 소형/중형 내구도 기준 수리 구현. 관문 전용 xUnit과 Game 빌드로 검증한다.
